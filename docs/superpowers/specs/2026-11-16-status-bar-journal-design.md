# 三页顶部的任务条 + 「记账」页改版（2026-11-16）

分支：`feat/bar-journal`（从 main ab07be7 拉出，工作区在 `.claude/worktrees/bar-journal`）。
这是一份**事后补的设计记录**，流程比上一轮（控制台改版）更省一步：用户说「接着优化」，
这次没有先出原型等确认，直接在隔离的工作区里做成成品、真机验收、过两轮独立审查，再交给用户决定合不合并。

## 0. 起因

用户（2026-11-16）两条要求：

1. 「接着优化其他页面顶部的控制条」——上一轮收尾时列在"这轮没做的"里的那一项；
2. 「优化『记账』这个页面的布局和 UI 设计」。

## 1. 三页顶部的任务条

「信号」「回测报告」「个股K线」三页顶上那条，代码里一直叫 `ui.control_bar`。文档里从这次起叫**任务条**
（「状态条」这个名字首页已经在用——那是行情时段的状态）。

### 改之前的毛病（真机，1440×900，真实数据）

| | 改之前 | 改之后 |
|---|--:|--:|
| 「信号」页：页头到第一块数据 | 334 px | 192 px |
| 「回测报告」：页头到第一块内容（「个股K线」是同一条，没单独量） | 243 px | 118 px |

- **只说上一次运行「成功」，不说结果是哪天的**：实测「信号」页写着成功，最新信号却停在 2026-09-11（两个月前）；
- 两个任务的按钮都叫「开始」——第二个一点就是半小时到两小时的全市场扫描，与十几秒的信号跟踪并排、长得一样；
- 「停止」常驻却九成九的时候点不了；两行灰字提示与去控制台的链接，没有任务在跑时也天天亮着；下面还有一道分隔线；
- 点了「开始」之后这一页不会自己动：状态不变、表不换，得去控制台才知道跑完没有。

### 现在的样子

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 信号跟踪 [成功]  最新一份是 2026-09-11——不是今天的                 [▶ 开始跟踪] │
│ 全市场扫描 [成功]  最近一次 2026-11-13，全量 3017 只，报出 64 条信号   [▶ 开始扫描] │
│ ── 以下几行只在适用时出现 ──                                                   │
│ [■ 停止]  扫描中，1700/3010（56%） ━━━━━━━━━━━━━━━━━━━━━                       │   ← 这一条自己的任务在跑
│ 已用 11秒，预计剩余 ~8分钟……任务在后台运行，关掉浏览器也不会中断。              │
│ 「回测」正在运行，同时只能跑一个任务                                           │   ← 别的页起的任务占着互斥
│ ▶ 去「任务控制台」看实时日志                                                   │   ← 有任务在跑 / 上次没跑成
└──────────────────────────────────────────────────────────────────────────────┘
```

- 一个原生带边框的容器（与控制台的任务卡片一家），一个任务一行：任务名、上一次运行的状态、一句**最新结果**
  ——与控制台卡片上那句是同一句话，同一个函数（`ui.step_status`，从 `pages_console` 搬到共享件）。
- 右端一个与控制台**同名**的按钮（开始跟踪 / 开始扫描 / 开始回测）。普通按钮，不是琥珀色的主按钮：
  这三页是来看结果的。「按默认参数运行、想改去控制台」从常驻的灰字挪到按钮的悬停提示（`guide.BAR_START_HELP`），
  扫描那条把「全量」与时长说在最前面。空态那句话里引的按钮名跟着改（`EMPTY_STATES` 逐字取自 `CONSOLE_START`）。
- **运行中才多出一行**进度与「停止」（`ui.running_row`，与控制台卡片共用）。任务条包在 fragment 里：有任务在跑时
  每 2 秒只重画这一条，跑完请求整页重跑一次——下面的表直接换成新结果。全空闲时不定时。
- 去控制台的链接、互斥提示都是"适用时才出现"（`view.bar_follow_up`）：有任务在跑才指路；这一条自己的任务在跑时
  进度就在条上，链接只说"看实时日志"；别的页起的任务才需要点名是谁在跑。

### 几个位置与措辞上的决定

- **「信号」页的两行都留在页顶**，没有把扫描那一行挪到页尾的扫描区块旁。挪过去控件离它的结果更近，但扫描结果在
  第二屏，放在页顶才能不滚动就知道那份结果是哪天的；区块小标题上的日期、条数、范围徽标一个字没动（那些有一组测试钉着）。
- **进度那一行排在所有任务行之后，「停止」在它的最左边。** 初稿把进度行放在它自己那个任务行的正下方、「停止」在右边
  （照抄控制台卡片）。真机上一看不对：信号跟踪十几秒就跑完，进度行一消失，它下面那一行的「开始扫描」正好滑到
  「停止」原来的位置——光标底下的按钮从"停止"变成"两小时的扫描"。现在进度行来了又走，哪个「开始」都不挪位置，
  上下也对不齐（有测试钉着列位置与先后顺序）。控制台卡片上「停止」仍在进度条右边，另有测试钉着，共用画法不许把它带过去。
- **没有结果时说「还没有结果——……要跑完一次才有」，不说「还没跑过」「还没人盯」**（`steps.UNKNOWN` 与三句话的后半句，
  控制台卡片上那句跟着一起改）。这句话现在紧挨着任务的运行状态：第一次扫描正在跑、或者第一次就失败了的时候，
  「运行中　还没跑过」「失败　还没人盯」当面打架。这几个函数看的本来就是磁盘上的结果，不是"面板起没起过它"。
- 面板上已经没有哪个按钮只写着「开始」两个字：空态文案、「边界与安全」一节与 README 里带引号的「开始」都换掉了
  （泛指时说"开始按钮"），有测试钉着。

## 2. 「记账」页

### 改之前的毛病（真机，同一份 7 笔记录）

| | 改之前 | 改之后 |
|---|--:|--:|
| 页面高度 | 1703 px | 1414 px |
| 常驻文字 | 1110 字 | 673 字 |

（两处的"改之后"都是审查修完之后、对着最终代码重新量的。）

- 录入区十二个输入框同等权重，分不出哪几样每一笔都要填；记之前看不到股数 × 成交价是多少钱、费用合计多少；
- 历史表照搬文件的列序：第一列是机器编号，类型与来源显示 `buy` / `sell` / `discretionary`（用户点名过的
  「中文里不夹英文值」），「删除」勾选框在最右边的屏幕外，没填的格子显示灰字 `None`；
- 表格上方常驻六个筛选框（一共才七笔记录）；表格下面三段灰字加五个控件堆在一起，保存、撤销、导出分不出层次；
- 按钮文字里还拼着 `✔` `↓`，CSV 那个按钮的字长到折成两行。

### 现在的样子

```
┌ 记一笔 ────────────────────────────────────────────────────────────┐
│ 方向   成交日期   代码   股数   成交价                    ← 每一笔都要填的五样 │
│ 600519 · 贵州茅台 · 本地还没有 2026-11-16 的行情数据，无法核对价格区间        │
│ 核对  买入 100 股 × 1,500.00 = 150,000.00 元；佣金 37.50、印花税 0.00，共付出 150,037.50 元 │
│ 理由（为什么做这一笔）         来源        计划止损价                          │
│ ▸ 更多：佣金与印花税、成交时刻、备注                                          │
│ [＋ 记这一笔]                                                               │
└────────────────────────────────────────────────────────────────────┘
▸ 其他记录：送股/转增/拆股、现金分红

历史记录（共 7 条）
▸ 筛选
筛出 1 / 7 条：类型 卖出。导出也只含这些。                         [清除筛选]   ← 只在筛选生效时
直接在表里改，按「保存修改」才写入……
[删除 | 日期 | 代码 | 名称 | 类型 | 股数 | 成交价 | 金额 | 来源 | 理由 | … | 记录号]
[保存修改]  勾了 1 行要删除，还没保存——点「保存修改」才写入。             ← 只在有改动时
每次保存前会自动留一份上一版……
[恢复上一版] ☐ 确认用上一版覆盖当前记录                    [导出 CSV] [导出 Excel]
```

- **核对那一行**是这次最要紧的一样：会写进文件的数，明面上写一行。费用输入框收进了「更多」（自动算好的，
  九成的时候不用碰），所以必须有它——控制台改版时定下的规矩：看不见的值不许悄悄生效。数字取自
  `schema.apply_defaults`，与落盘走同一个函数、同一组入参；在「更多」里改了佣金，这一行跟着变。
  股数与成交价照输入的原样写、不舍入（150.5 股不写成 150 股），等号两边才对得上。
- 「其他记录」挪到卡片**下面**：卡片里只有一张表单、一个主按钮。
- 历史表的列序只管显示（`journal_ui.EDITOR_ORDER` + `st.data_editor(column_order=)`），文件与导出的列序不变；
  类型与来源用 `SelectboxColumn(format_func=)` 显示中文、存的仍是键。记录号没有隐藏，排在最后——保存失败的提示、
  「持仓与盈亏」页的平仓明细都还指回它。
- **数字、名称、代码、日期这些列不钉死宽度**。初稿为了让理由一列不用拖就看得见，把数字列与名称设成了窄档；审查后用大数
  一试：数字右对齐，放不下时截掉的是**左边**——1,234,500 股显示成 234500.00，一千五百万的金额少了最高位。
  一个被截掉最高位的数看着完全正常。宽度交给表格按内容定（有测试钉着这些列没有固定宽度）。钉了宽度的只有勾选框
  与理由两列：理由是长文字，被截的是右边、看得出没显示完。
- 四个折叠区（说明 / 更多 / 其他记录 / 筛选）都带 `key`。不带的话，页面顶上一冒出报错那一条，下面的元素整体往后
  挪一位，折叠区会被浏览器当成新的、自己合上——正开着「筛选」点一下「记这一笔」被拒，面板就在眼前关掉了
  （真机上看到，用一个小页面对照过：带 key 的留着、不带的合上）。
- 筛选收进折叠区；筛了什么写在表格上方并说明"导出也只含这些"，旁边一个「清除筛选」。一笔都没记过时，
  筛选、表格、导出整个不出，只留那句指路的话和「恢复上一版」（后者照留，是 v0.3.2 的既有决定）。
- 表格下面：一行保存（有没保存的改动时按钮变主按钮，旁边写明改了几行、勾了几行要删），一句撤销手段在哪，
  一行撤销与导出。原先那三段解释挂到了各自按钮的悬停提示上。

### 顺手修掉的真问题（多数是旧的，做验收与两轮审查时抓到的）

1. **记完一笔，表单其实没清。** v0.5.0 的清法是把控件的值从 `session_state` 里删掉：后台空了，浏览器手里那份
   旧值还在，而每次操作浏览器都会把全部控件的值送回来——记完之后只要再点一下「卖出」，上一笔的代码、股数、
   成交价就原样回来，再点「记这一笔」就是一条重复记录。AppTest 没有浏览器，这件事一直没被测到。
   现在落盘时只登记"该清了"，下一轮渲染、控件创建之前**明确写回空值**（`clear_entry_form` → `apply_pending_clear`，
   与预填同一个做法）；测试看协议里的 `set_value`。
2. **「其他记录」那张表单记完根本不清**（要清的键里只有买卖那张的），到账金额还在框里，再点一次就是第二笔
   一模一样的分红；反过来，记一笔分红还会把上面填到一半的买卖表单清掉。现在两张表单各清各的。
3. **一次什么都没改的「保存修改」会吃掉唯一的备份。** 备份只留一版，每次写盘都把它换成"写之前的样子"：
   删错一行并保存之后再点一下保存，备份就成了删错之后的那一版。现在没有改动就不写盘，并如实说"没有需要保存的改动"。
   顺带把保存提示里的数改成**真正变了**的行数——原先写的是"表里有几行"，七行的表只删一行，它会说
   「改动 6 行、删除 1 行」。
4. **历史表里没保存的改动，会跟着"第几行"落到另一笔交易头上**（独立审查抓到，真实浏览器里复现过）。
   `st.data_editor` 记的是"第几行的哪一格改成了什么"；带 key 的固定行数编辑器，身份只看表的结构（列、行数、索引），
   不看里面的值——streamlit 1.61 的文档原话是 *edits are matched by row position*。于是两个**行数相同**的筛选结果是
   同一个控件：筛出一笔「黄金」、勾上删除、不保存，把关键词改成「验收」（也是一笔），那个勾就在另一笔交易上，
   点保存删掉的是它（落盘按 trade_id 写，所以写得"很准"）。修法是**这个编辑器不给 key**：身份取自表的内容，
   表里换了一批记录、或者保存 / 恢复之后内容变了，它就是一个新控件，旧改动自然作废；还是那几行时，没保存的改动照常留着。
   代价是换一批记录时表格会重新挂载（实测约 0.4 秒的空白）。
5. **点「记这一笔」之后，筛选条件丢一轮**（旧的，复审抓到）。提交完是当场 `st.rerun()`，那时它下面的筛选框、历史表
   还没画——Streamlit 把一次中途重跑当成"这一轮跑完了"，没画出来的控件就被后台当成不在了、状态丢掉：筛着「卖出」
   点一下「记这一笔」，表格变回全部记录一轮，筛选框里却还写着卖出；表里没保存的改动也跟着少报一轮。
   现在三处（记一笔 / 记其他 / 保存修改）都改成**等整页画完再重跑**。
6. **在「删除」那一格上按 Delete 键，表格崩一轮**（旧的，复审抓到）。表格送回来的是"这一格清空"，往硬邦邦的 bool 列里
   塞空值是 TypeError，表格连同下面的保存、恢复、导出一起消失一轮。勾选列改成可空的布尔类型，清空 = 没勾。
   这一列这次挪到了最前面，比以前好碰得多，所以必须修。
7. **表里把日期清空再保存，是一屏 traceback**（旧的，复审抓到）。清空的日期是 `pd.NaT`，而它是 datetime 的一个实例，
   被当成真日期一路走到比较才炸。`schema.is_blank` 认了它之后，走的是设计好的那句「缺少成交日期」、文件不动。
8. **校验信息里夹着内部键**（旧的，真机上看到）。空着表单点「记这一笔」——第一次来的人最可能做的第一件事——
   页面上第一句话是「buy 必须填写 shares；buy 必须填写 price」。现在说的是页面上的字：「买入必须填写股数」。
   记录类型的中文名收成一份（`schema.KIND_NAMES`，页面上的标签也取自它）。

## 3. 独立审查（2026-11-16，两轮）

成品做完后交给一个没有上下文的审查者，只给它代码差异与"这次应该做成什么"。**第一轮**的结论是「先别合」，三条要紧的：

| 审查意见 | 核实 | 处理 |
|---|---|---|
| 历史表的改动按行号走，行数相同的筛选结果之间会串（上面第 4 条） | 真实浏览器里复现：勾在 A 表第 0 行，切到 B 表后 B 的第 0 行是勾着的。根子是旧的（原先就带 key），但这次新加的「还没保存」提醒会把人往坑里引 | 编辑器不给 key；真机复验：换一批记录后勾与提醒都消失，同一批记录时照常保留 |
| 「还没保存」按"哪些格子被碰过"算，把原值敲回去也报、保存完还亮着 | 前一半成立。"保存完还亮着"是审查者用测试替身推出来的；我在真实浏览器里用一个小页面试，保存之后前端自己把那条改动清掉了，没有复现 | 改成两张表**按值**逐格比（`journal_ui.pending_changes`），与类型无关——不依赖前端清不清 |
| 一个任务在跑、另一个任务的状态文件又恰好损坏时，「信号」页原地打转 | 成立，是这次把任务条包进 fragment 引入的；控制台卡片上同样的写法早就有同一个毛病 | `ui.busy_changed`：读不出"谁在跑"就是不知道，不算"变了"，不请求整页重跑。两处一起修，真机复验页面稳住、报错留在页面上 |

其余小项也都处理了：没有结果时的措辞、带引号的「开始」、空日志态那句"用导出"、核对行的舍入、
到账金额提示里那句指向不明的"记进佣金那一栏"、几处旧名字的注释。

审查还点了九个"测试变红不了"的地方（任务条读不出状态那条分支没有测试覆盖、"没在跑的任务没有停止"其实只测了
"没跑过的任务"、任务条的扫描按钮带没带参数没验、帮助圆点那条测试对任务条是空跑、清除筛选只验了六个条件里的两个……），
逐个补了测试。**审查自己没法验证的**（它没有浏览器）：上面第 1、2 条的真机表现，这两条是我在真实浏览器里补验的。

**第二轮**只看第一轮之后改的那几处，结论是三处主要修复站得住（没能让改动落到别的交易上、没能造出打转、
状态不明时拿不到可点的开始按钮），没有严重问题。它另外点出来的，都处理了：

| 复审意见 | 处理 |
|---|---|
| 「还没保存」与真正保存用的不是同一把尺：只敲了空格的格子，提醒说没改，保存却写了盘、换了备份 | `_same_cell` 的文字比较改成与落盘一致（原样、不去空白）；空着的数字与 0 也分开 |
| 记一笔之后当场重跑，筛选与没保存的改动丢一轮（上面第 5 条） | 等整页画完再重跑 |

验收里**没法照人那样做**的两件：
