# 表格右上角的工具条盖住上方靠右的控件：给它垫出落脚的地方（2026-11-18 ～ 11-19）

分支：`claude/exciting-curie-39aec9`（工作区在 `.claude/worktrees/exciting-curie-39aec9`）。第一轮的四个提交接在
删除改版那条分支（`feat/journal-delete`）后面——它改的是同一批文件；第二轮的三个提交接在三件后续任务都排到
那条分支上之后的顶端。写这份记录时这条线还没有合进 main。
事后补的设计记录，分两轮：第一轮（11-18）是「记账」页的「清除筛选」，§0–§6；第二轮（11-19）是用户说
「一并改」之后把别的页都查了一遍，§7。本文与测试里的例子一律用虚构的票和数（仓库是公开的，
用户的交易记录不进仓库）。

## 0. 起因

做「历史记录的删除」那一轮时顺带看到的旧问题（那份设计记录的 §7 最后几条之一），主分支上本来就有，
当时没有动，单独拿出来做。

「记账」页的历史记录是一张可编辑的表格（`st.data_editor`）。它右上角有一条表格自带的浮动工具条：
四个小图标——显示 / 隐藏列、下载、搜索、全屏。平时看不见；**鼠标停在表上，或者表里选中着一格**
（点过任何一格之后就是这样，鼠标移开也不变），它就显出来并往上抬，压在表格上方那一行靠右的控件上：

- 有筛选生效时，压住「清除筛选」按钮下面约三分之二。改完一格想清掉筛选，点在按钮下半截没有任何反应，
  再偏一点就点开了表格的搜索框；
- 筛选折叠区展开、没有筛选生效时，压住最右边「理由关键词」输入框的右下角。

## 1. 原因（量出来的）

在 `/tmp` 的副本里量的（虚构账本十条，streamlit 1.61.1，1440×900）。工具条是
`[data-testid="stElementToolbar"]`，绝对定位在表格（`stDataFrame`）里、贴着右缘：

| | 位置（`top`） | 看得见吗 |
|---|---|---|
| 平时 | `-1rem`（−16 像素） | 不透明度 0 |
| 显出来 | `-2.65rem`（−42.4 像素） | 不透明度 1 |

- 它整块宽 105.6、高 46.4 像素（四个图标各 22.4 宽；看得见的那块深色底比整块小一圈，上下左各让 8 像素）。
- 平时它正好缩在表格与上一行之间那 1rem 的空隙里，所以不碍事；显出来时顶边比表格顶边高出 42.4 像素，
  比空隙多出 26.4 像素——这 26.4 像素、贴着右缘 105.6 像素宽的一块，就是它压到上一行的地方。
- 什么时候显出来，装着的前端里写得很清楚（`static/js/` 里那段样式）：鼠标停在表上；鼠标停在工具条自己身上
  （所以从表格往上移、经过它的时候，它一直抬着）；表里选中着一格时干脆**锁在**抬起的位置，鼠标在哪儿都一样
  （前端里"锁住"的条件一共四个，我只验证了「选中一格」这一个）。点一下表格外面别的控件，选中的格子才放开。
- 改之前逐点量到的：选中一格、鼠标移开后，「清除筛选」（80×40 像素）的 3200 个点里有 2160 个落在工具条上
  ——按钮顶边往下 13.6 像素起、整个宽度。真鼠标点按钮下半截：筛选还在，表格的搜索框开了。
  「理由关键词」输入框（175.2×35.6 像素）被压住右边 104.6 像素、下面 24.2 像素；1024 宽下这个输入框只有
  96.3 像素宽，整个宽度都在工具条底下。

**绕不开的两条**：`st.data_editor` / `st.dataframe` 没有关掉这条工具条的参数（看过 1.61.1 的函数签名）；
`app/theme.py` 的样式只许选我们自己的 `.qd-*`，不能靠选中 streamlit 的元素去藏它、挪它。
所以做法只剩一个方向：**表格正上方靠右那一块，不放可点的东西**。

## 2. 摆给用户看的三种做法

没有写方案文档。在 `/tmp` 的副本里把三种都做成能点的，历史记录上方放一条只在预览里有的切换
（连同「现在的样子」，方便对照着复现）。三种在 1440 与 1024 两种宽度下都先量过，确认不再被盖。
下表里的像素是摆给他看的那一版的（空当 12 像素）；第二轮把空当加到了 16 像素，见 §7。

| 做法 | 怎么让 | 代价 |
|---|---|---|
| **用到时才留空**（我建议的，用户选的） | 「清除筛选」那一行与表格之间垫一条空当；「筛选」折叠区的最下面也垫一条（只有展开才看得见）。平时——折叠区收着、没有筛选——页面一个像素都不变 | 筛选生效时、筛选框展开时，表格上方的间距从 16 变成 44 像素；平时工具条抬起来仍压在收着的「筛选」那一行的右端 |
| 一直留空 | 表格上方永远垫这条空当 | 绝大多数时候（没在筛选）表格上方也多 28 像素空白 |
| 按钮上移 | 「清除筛选」挪到「历史记录（共 N 条）」那一行的右端；「筛出 N / M 条」那行字留在表格正上方、右端空着 | 按钮离"筛了什么"那行字远了，中间隔着筛选框；折叠区最下面同样要垫 |

**用户的选择**：第一种。实现与验收是在他回话之前、照我建议的这一种先做完的（他要是选了别的，改的只是
`_log_section` 里那几行与对应的测试）；随后他在发起这件事的那个会话的选项框里点了「方案一 用到时才留空（推荐）」，
没有附加别的话——是从三句文字说明里选的，有没有点开预览逐个比较，不知道。他点的就是已经做好的这一种。

没有摆出来的几种，和不摆的理由：

- **把「筛出 N / M 条 + 清除筛选」那一行挪到折叠区上面**（让收着的折叠区那一行隔在按钮与表格之间，
  一条空当都不用垫）：筛选条件一生效，这一行冒出来，会把正在操作的六个筛选框整体往下顶一行。
- **把空当留到连图标的名称提示也压不到**（见 §6 最后一段）：要约 80 像素，表格上方空出一大截。
- **按钮放左边**：操作按钮一律靠右是用户定的全站规矩。

空当是 `app/ui.py::toolbar_room()`，里面只有一句 `st.space(TOOLBAR_ROOM)`，`TOOLBAR_ROOM = 16`（像素）。
算术：上下各一道元素间的空隙（各 16 像素）加上它，是 **48 像素，高过工具条上移的 42.4 像素**。
按钮占多大地方就能点多大地方，余 5.6 像素；`st.page_link` 的链接可点的范围比它占的位置上下各多出 4 像素，
余 2.6 像素。第一轮垫的是 12 像素（`st.space("small")`），为什么改见 §7。

## 4. 几个决定

- **垫在折叠区里面，不垫在它后面。** 折叠区收着的时候里面的东西不占地方，于是平时的页面与改之前
  逐像素相同；垫在后面就成了"一直留空"。
- **平时不垫，认了那一处压。** 折叠区收着、没有筛选时，工具条抬起来压的是「筛选」那一行的右端
  （那一行整行都能点开折叠区，量到的是右端 105.6 × 26.4 像素那一块）。人点的是左边「筛选」两个字，
  为这一块天天空着一截不值——这是"一直留空"那一种做法唯一多出来的好处，摆给用户看了。
- **筛到一条不剩不垫**：没有表格。
- **不看折叠区是开是合**：1.61 的 `st.expander` 可以把开合报给后台（`on_change="rerun"`），那样能做到
  "展开才垫"；但垫在里面已经是这个效果，不必为它多一次整页重跑。
- **只在表格正上方靠右真有可点的东西时才垫**，没有做成"每张表都垫"：上面是小标题、一行字，或者
  右端空着时，工具条压不到任何东西。
- **空当是一个有名字的函数，不是散在各页的 `st.space(...)`**：为什么垫、垫多高、什么时候不该垫，
  写在一处，各页用的是同一个高度。走顶层 `st.space`（不是 容器.space），测试靠替换它看垫了多高。
- **高度按像素给，不用 `st.space` 的档位名**：档位里 0.75rem（12 像素）之上就是 2.5rem（40 像素），
  中间没有合用的一档。

## 6. 验证

### 量法

`/tmp` 的隔离副本（工作区里已跟踪的文件 + 一套**全是虚构的**数据：账本十条——美的集团 / 贵州茅台 /
招商银行；第二轮另加了信号池覆盖、扫描 / 信号 / 回测的结果与"今天跑完"的状态，让八个功能页都有内容），
在应用自带的浏览器里开，视口设成 1440×900 与 1024×768 各做一遍。主目录的 `journal/` 自始至终没动
（校验和与修改时间前后一致）。

- 位置：`getBoundingClientRect()` 取工具条、表格、上方那个控件的矩形。
- 盖没盖住：对控件矩形里的点逐个（1 像素一格；「清除筛选」80×40 共 3200 个点，「去信号池」96×28 共
  2688 个点）调 `document.elementFromPoint`，落在控件自己身上算点得中，落在工具条身上算被盖住；
  六个筛选控件同样处理。
- 工具条的两种状态都是用真的指针事件造出来的：把鼠标移到表里某一格上（`:hover` 成立，工具条的
  `top` 变成 −42.4 像素）；点一下那一格、再把鼠标移到侧边栏上（工具条仍在 −42.4 像素、不透明度 1）。
- **折叠区要用真鼠标点开再量**（第二轮的教训，见 §7）：用脚本去点折叠区的标题，它标记成了展开，
  里面的东西却没有排出来，量到的是一堆互相重叠的位置。

### 结果（空当 16 像素，11-19 重量）

每一格是"控件底边到抬起的工具条顶边的距离 / 落在工具条上的点数"。两种宽度、两种触发方式
（鼠标停在表上；选中一格后鼠标移开）量到的数完全一样，所以合成一张表：

| 页面与状态 | 表格上方靠右的控件 | 六个筛选控件 |
|---|---|---|
| 记账：折叠区收起、有筛选生效 | 「清除筛选」5.6 像素 / 0 个点 | （收着，不在页面上） |
| 记账：折叠区展开、有筛选生效 | 「清除筛选」5.6 像素 / 0 个点 | 93.6 像素 / 0 个点 |
| 记账：折叠区展开、没有筛选 | （没有这个按钮） | 5.6 像素 / 0 个点 |
| 记账：筛到一条不剩 | 没有表格、没有工具条（第一轮量的，这一条分支第二轮没有动：按钮 3200 个点里 3191 个点得中，其余 9 个落在按钮外面那层容器上——圆角处，别的状态下也是这 9 个） | 0 个点 |
| 记账：平时（折叠区收起、没有筛选） | （没有这个按钮）；「筛选」那一行右端被压住——见 §4 | （收着） |
| 持仓与盈亏：有那条提醒 | 「去信号池」2.6 像素 / 0 个点（链接外面那一圈 0.6 像素 / 0 个点） | —— |
| 持仓与盈亏：没有那条提醒 | 表格上面是那一排标签页，最右一个标签的右缘离工具条的范围还有两百多像素 | —— |

改之前同样的量法：「清除筛选」3200 个点里 2160 个落在工具条上；「去信号池」2688 个点**全部**落在工具条上。
第一轮（空当 12 像素）量到的「清除筛选」与筛选控件是 1.6 像素 / 0 个点。

### 真鼠标点过的

都是先选中表里一格、把鼠标移开，再去点；1440 与 1024 各一遍：

- 「清除筛选」的右下角（底边往上 3 像素、宽度的四分之三处，改之前正在工具条底下）：筛选清掉——
  第一轮在折叠区收起、展开、筛到零条三种状态各点了一次，第二轮（空当改成 16 像素之后）在折叠区收起时重点了；
- 「理由关键词」输入框的右下角：点进去了，打的字落在框里，回车后筛选生效（两轮都点了）；
- 「去信号池」的最下沿（底边往上 2 像素）：跳到了「信号池」页；
- 第一轮在 1440 下另走了一遍"鼠标从表格往上移、经过工具条、再到按钮最下沿"：点中的是按钮。

### 工具条自己的四个功能

没有动过它，照旧能用（第一轮验的，1024 宽）。选中一格、工具条抬着的时候：点「显示 / 隐藏列」，
列的清单弹出来；点「搜索」，搜索框出来，打一个代码，表里标出四处；点「全屏」，表格铺满，Esc 回来。
**「下载」没有点**（点了会真的往下载目录里存一个文件），只确认了它的图标正中间点得中。
四个图标的名称与列清单里的 "Select all" 是英文，streamlit 自带的，没有动。

### 没法照人那样做、或者没做的

- 自动化工具的"移动鼠标"是从一点直接跳到另一点，不是连续划过去。上面"经过工具条"那一条是分三步跳的。
- **图标的名称提示会暂时压住上方的控件**（第一轮量出来的，改之前也一样）。鼠标在工具条某个图标上停满一秒，
  会冒出它的名称（"Search"、"Download as CSV"……），出在图标上方——工具条抬着的时候，那正是
  「清除筛选」的位置：空当 12 像素时量到的是按钮 3200 个点里 2135 个落在提示框上（提示框顶边比表格顶边
  高 74.7 像素；空当加到 16 像素之后没有重量，按几何关系仍压住按钮的大半）。
  鼠标一离开图标它当场消失（挪到图标与提示框之间的空隙里，立刻就没有了，之后按钮整个点得中）；
  但鼠标若是一下子跳进提示框所在的那一块，它不消失，那一下点中的是提示框——自动化的"跳"正好造出了
  这种情况，真人要划得很快才会碰上，挪一下鼠标它就没了。要连它也让开，空当得留到约 80 像素，
  没有这么做；用户知道这件事。
- 只在应用自带的浏览器（Chromium 内核）、深色主题、100% 缩放、根字号 16 像素下量过；没有换别的浏览器，
  也没有试触屏。
- 没有请独立审查。上面的验收与变异自查是我自己做的。
- 给用户看的那份副本（里面是他账本的拷贝）只用来摆三种做法，验收没有在它上面做；他选定之后已经删掉，
  留给他看定稿的那份预览里是虚构的数据。

## 7. 第二轮：把别的页都查一遍（2026-11-19）

第一轮交回时我报了三处"别的页也有同一个毛病"，用户回的是「一并改」。动手前把八个功能页里的每一张表、
每一种状态用虚构数据重新量了一遍，结论与当初报的不一样：

| 页面 | 第一轮报的 | 重新量的结果 |
|---|---|---|
| 持仓与盈亏 | 「当前持仓」表上方那条提醒右端的「去信号池」整个被盖住 | **属实**，改了（见下）。另两个标签页的表格上方只有左边一个「读表说明」，不用改 |
| 任务控制台 | 「本次结果」展开时，上方「去增删信号池」链接下半截在范围里 | **误报**。那个链接在两张任务卡片之间，离哪张表都远 |
| 回测报告 | 「选择回测」下拉框底边 4 像素在范围里 | **误报**。下拉框在「全部 N 次回测一览」那张表的**下面** |
| 信号、信号池 | 没有 | 没有：表格上方都是小标题。「信号」页的「按策略筛」在扫描表上方 90 像素处 |
| 市场概览、个股K线 | 没有表格 | 没有表格 |

**两条误报是怎么来的**：第一轮扫别的页时，表格收在折叠区里，我用脚本去"点开"折叠区的标题再量。
折叠区的标记确实变成了展开，里面的表格也量得到一个矩形，但内容并没有真的排出来——那个矩形与折叠区
下面的东西叠在一起，下面的控件于是"落进了"表格上方的范围。这次改成：只量看得见的表（不在收着的折叠区、
没选中的标签页里，也没有被上层裁掉），折叠区一律用真鼠标点开，并且核对量到的位置彼此不重叠。
第一轮那两条我当时就注明了"只按矩形算的，没有用真鼠标验证"——没验证的就不该当成结论报。

**还有一处压着、没有垫**：控制台「信号跟踪」卡片的结果表是「本次结果」折叠区里的第一样东西，
工具条抬起来压在「本次结果」那一行的右端。与「记账」页平时压在「筛选」那一行右端是同一种情况
（那里没有控件，只是整行可点），照用户选的那一种做法的口径，不垫。

### 「持仓与盈亏」页

有持仓不在信号池时，「当前持仓」标签页里、表格上面有一行提醒，右端一个「去信号池」的链接
（`_pool_notice`）。它正好在表格正上方靠右：鼠标一停在表上，链接上 2688 个点全部落在工具条上。
做法与「记账」页相同：那一行与表格之间垫一条空当（`_positions_section` 里，`_pool_notice` 交回
"这一句出没出"）；没有那条提醒时不垫。

### 空当从 12 像素加到 16 像素

照搬第一轮的 12 像素，垫完之后量出来**仍然压着**：「去信号池」2688 个点里还有 192 个（最下面两行像素）
落在工具条上。原因是链接与按钮不一样——`st.page_link` 的链接自己高 28 像素，在版面上只占 20 像素的一行，
可点的范围上下各多出 4 像素（外面还有一圈 2 像素）；12 像素的空当给按钮留了 1.6 像素的余量，
给链接就成了 −1.4 像素。

所以把 `ui.TOOLBAR_ROOM` 统一改成 16 像素（两页共用同一个）：链接余 2.6 像素，按钮的余量从 1.6 变成
5.6 像素。代价是「记账」页那两种状态下表格上方的间距从 44 变成 48 像素——用户选的时候看到的说法是
"约 28 像素的空当"，现在是 32；这一点在汇报里告诉了他。没有只给「持仓与盈亏」页单独垫高一点：
两页各垫各的高度，正是这次出错的路子（照搬了一个对别处才够的数）。

两页在 16 像素下都重新量过，结果在 §6 的表里。
