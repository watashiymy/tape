# 表格右上角的工具条盖住「清除筛选」：给它垫出落脚的地方（2026-11-18，当天第四轮）

分支：`claude/exciting-curie-39aec9`（工作区在 `.claude/worktrees/exciting-curie-39aec9`），接在
`feat/journal-delete`（顶端 a3d037f）后面——那条分支改的是同一批文件，写这份记录时它还没有合进 main。
事后补的设计记录。本文与测试里的例子一律用虚构的票和数（仓库是公开的，用户的交易记录不进仓库）。

## 0. 起因

做「历史记录的删除」那一轮时顺带看到的旧问题（那份设计记录的 §7 最后几条之一），主分支上本来就有，
当时没有动，单独拿出来做。

「记账」页的历史记录是一张可编辑的表格（`st.data_editor`）。它右上角有一条表格自带的浮动工具条：
四个小图标——显示 / 隐藏列、下载、搜索、全屏。平时看不见；**鼠标停在表上，或者表里选中着一格**
（点过任何一格之后就是这样，鼠标移开也不变），它就显出来并往上抬，压在表格上方那一行靠右的控件上：

- 有筛选生效时，压住「清除筛选」按钮下面约三分之二。改完一格想清掉筛选，点在按钮下半截没有任何反应，
  再偏一点就点开了表格的搜索框；
- 筛选折叠区展开、没有筛选生效时，压住最右边「理由关键词」输入框的右下角。

## 1. 原因（量出来的）

在 `/tmp` 的副本里量的（虚构账本十条，streamlit 1.61.1，1440×900）。工具条是
`[data-testid="stElementToolbar"]`，绝对定位在表格（`stDataFrame`）里、贴着右缘：

| | 位置（`top`） | 看得见吗 |
|---|---|---|
| 平时 | `-1rem`（−16 像素） | 不透明度 0 |
| 显出来 | `-2.65rem`（−42.4 像素） | 不透明度 1 |

- 它整块宽 105.6、高 46.4 像素（四个图标各 22.4 宽；看得见的那块深色底比整块小一圈，上下左各让 8 像素）。
- 平时它正好缩在表格与上一行之间那 1rem 的空隙里，所以不碍事；显出来时顶边比表格顶边高出 42.4 像素，
  比空隙多出 26.4 像素——这 26.4 像素、贴着右缘 105.6 像素宽的一块，就是它压到上一行的地方。
- 什么时候显出来，装着的前端里写得很清楚（`static/js/` 里那段样式）：鼠标停在表上；鼠标停在工具条自己身上
  （所以从表格往上移、经过它的时候，它一直抬着）；表里选中着一格时干脆**锁在**抬起的位置，鼠标在哪儿都一样
  （前端里"锁住"的条件一共四个，我只验证了「选中一格」这一个）。点一下表格外面别的控件，选中的格子才放开。
- 改之前逐点量到的：选中一格、鼠标移开后，「清除筛选」（80×40 像素）的 3200 个点里有 2160 个落在工具条上
  ——按钮顶边往下 13.6 像素起、整个宽度。真鼠标点按钮下半截：筛选还在，表格的搜索框开了。
  「理由关键词」输入框（175.2×35.6 像素）被压住右边 104.6 像素、下面 24.2 像素；1024 宽下这个输入框只有
  96.3 像素宽，整个宽度都在工具条底下。

**绕不开的两条**：`st.data_editor` / `st.dataframe` 没有关掉这条工具条的参数（看过 1.61.1 的函数签名）；
`app/theme.py` 的样式只许选我们自己的 `.qd-*`，不能靠选中 streamlit 的元素去藏它、挪它。
所以做法只剩一个方向：**表格正上方靠右那一块，不放可点的东西**。

## 2. 摆给用户看的三种做法

没有写方案文档。在 `/tmp` 的副本里把三种都做成能点的，历史记录上方放一条只在预览里有的切换
（连同「现在的样子」，方便对照着复现）。三种在 1440 与 1024 两种宽度下都先量过，确认不再被盖：

| 做法 | 怎么让 | 代价 |
|---|---|---|
| **用到时才留空**（我建议的，现在实现的是它） | 「清除筛选」那一行与表格之间垫一条空当；「筛选」折叠区的最下面也垫一条（只有展开才看得见）。平时——折叠区收着、没有筛选——页面一个像素都不变 | 筛选生效时、筛选框展开时，表格上方的间距从 16 变成 44 像素；平时工具条抬起来仍压在收着的「筛选」那一行的右端 |
| 一直留空 | 表格上方永远垫这条空当 | 绝大多数时候（没在筛选）表格上方也多 28 像素空白 |
| 按钮上移 | 「清除筛选」挪到「历史记录（共 N 条）」那一行的右端；「筛出 N / M 条」那行字留在表格正上方、右端空着 | 按钮离"筛了什么"那行字远了，中间隔着筛选框；折叠区最下面同样要垫 |

**用户的选择**：写下这份记录时还没有回话（预览与问题已经发出）。先照我建议的第一种实现并做完了验收；
他要是选了别的，改的是 `_log_section` 里那几行与对应的测试。

没有摆出来的几种，和不摆的理由：

- **把「筛出 N / M 条 + 清除筛选」那一行挪到折叠区上面**（让收着的折叠区那一行隔在按钮与表格之间，
  一条空当都不用垫）：筛选条件一生效，这一行冒出来，会把正在操作的六个筛选框整体往下顶一行。
- **把空当留到连图标的名称提示也压不到**（见 §6 最后一段）：要约 80 像素，表格上方空出一大截。
- **按钮放左边**：操作按钮一律靠右是用户定的全站规矩。

## 3. 现在的做法

```
平时（折叠区收着、没有筛选）——与改之前一样
  历史记录（共 10 条） ?
  ▸ 筛选
  ┌──────────────────────────── 表格 ─────────────────────────────┐

折叠区展开、没有筛选
  ▾ 筛选
    起（含）  止（含）  标的  类型  来源  理由关键词
    ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░   ← 折叠区最下面的空当（在折叠区里面）
  ┌──────────────────────────── 表格 ─────────────────────────────┐

有筛选生效（折叠区收着或展开都一样）
  筛出 3 / 10 条：类型 卖出                             ⛛ 清除筛选
  ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░ [◉ ⤓ ⌕ ⛶]  ← 空当；工具条抬起来正好落在这里
  ┌──────────────────────────── 表格 ─────────────────────────────┐

筛到一条不剩——没有表格，也就没有工具条，不垫
  筛出 0 / 10 条：理由含「……」                         ⛛ 清除筛选
  没有符合条件的记录——把筛选条件放宽些，或点「清除筛选」。
```

空当是 `app/ui.py::toolbar_room()`，里面只有一句 `st.space(TOOLBAR_ROOM)`，`TOOLBAR_ROOM = "small"`（0.75rem）。
算术：上下各一道元素间的空隙（1rem）加上它，是 **2.75rem，刚好高过工具条上移的 2.65rem**，余 0.1rem
（1.6 像素）。全用 rem，与工具条自己是同一把尺子。

## 4. 几个决定

- **垫在折叠区里面，不垫在它后面。** 折叠区收着的时候里面的东西不占地方，于是平时的页面与改之前
  逐像素相同；垫在后面就成了"一直留空"。
- **平时不垫，认了那一处压。** 折叠区收着、没有筛选时，工具条抬起来压的是「筛选」那一行的右端
  （那一行整行都能点开折叠区，量到的是右端 105.6 × 26.4 像素那一块）。人点的是左边「筛选」两个字，
  为这一块天天空着 28 像素不值——这是"一直留空"那一种做法唯一多出来的好处，摆给用户看了。
- **筛到一条不剩不垫**：没有表格。
- **不看折叠区是开是合**：1.61 的 `st.expander` 可以把开合报给后台（`on_change="rerun"`），那样能做到
  "展开才垫"；但垫在里面已经是这个效果，不必为它多一次整页重跑。
- **只在表格正上方靠右真有可点的东西时才垫**，没有做成"每张表都垫"：上面是小标题、一行字，或者
  右端空着时，工具条压不到任何东西。别的页的情况见 §7。
- **空当是一个有名字的函数，不是两句散着的 `st.space("small")`**：为什么垫、垫多高、什么时候不该垫，
  写在一处；别的页以后要垫，用的是同一个。走顶层 `st.space`（不是 容器.space），测试靠替换它看垫的是哪一档。

## 6. 验证

### 量法

`/tmp` 的隔离副本（工作区里已跟踪的文件 + 一份另造的虚构账本：美的集团 / 贵州茅台 / 招商银行，十条），
在应用自带的浏览器里开，视口设成 1440×900 与 1024×768 各做一遍。主目录的 `journal/` 自始至终没动
（校验和与修改时间前后一致）。

- 位置：`getBoundingClientRect()` 取工具条、表格、「清除筛选」按钮、六个筛选控件的矩形。
- 盖没盖住：对按钮矩形里的点逐个（1 像素一格，80×40 共 3200 个点）调 `document.elementFromPoint`，
  落在按钮自己身上算点得中，落在工具条身上算被盖住；六个筛选控件同样处理（连标题带输入框整块量一遍，
  输入框自己再量一遍）。
- 工具条的两种状态都是用真的指针事件造出来的：把鼠标移到表里某一格上（`:hover` 成立，工具条的
  `top` 变成 −42.4 像素）；点一下那一格、再把鼠标移到侧边栏上（工具条仍在 −42.4 像素、不透明度 1）。

### 结果

每一格是"控件底边到抬起的工具条顶边的距离 / 落在工具条上的点数"。两种宽度、两种触发方式
（鼠标停在表上；选中一格后鼠标移开）量到的数完全一样，所以合成一张表：

| 状态 | 「清除筛选」 | 六个筛选控件 |
|---|---|---|
| 折叠区收起、有筛选生效 | 1.6 像素 / 0 个点 | （收着，不在页面上） |
| 折叠区展开、有筛选生效 | 1.6 像素 / 0 个点 | 85.6 像素 / 0 个点 |
| 折叠区展开、没有筛选 | （没有这个按钮） | 1.6 像素 / 0 个点 |
| 筛到一条不剩 | 没有表格、没有工具条；按钮 3200 个点里 3191 个点得中，其余 9 个落在按钮外面那层容器上（圆角处，别的状态下也是这 9 个） | 0 个点 |
| 平时（折叠区收起、没有筛选） | （没有这个按钮） | （收着）；「筛选」那一行右端被压住——见 §4 |

改之前同样的量法：「清除筛选」3200 个点里 2160 个落在工具条上。

### 真鼠标点过的

1440 与 1024 各一遍，都是先选中表里一格、把鼠标移开，再去点：

- 「清除筛选」的右下角（底边往上 3 像素、宽度的四分之三处，改之前正在工具条底下）：筛选清掉——
  折叠区收起、展开、筛到零条三种状态各点了一次；
- 「理由关键词」输入框的右下角：点进去了，打的字落在框里，回车后筛选生效；
- 1440 下另走了一遍"鼠标从表格往上移、经过工具条、再到按钮最下沿（底边往上约 4 像素）"：点中的是按钮。

### 工具条自己的四个功能

没有动过它，照旧能用。选中一格、工具条抬着的时候：点「显示 / 隐藏列」，列的清单弹出来；点「搜索」，
搜索框出来，打一个代码，表里标出四处；点「全屏」，表格铺满，Esc 回来。**「下载」没有点**（点了会真的往
下载目录里存一个文件），只确认了它的图标正中间点得中。四个图标的名称与列清单里的 "Select all" 是英文，
streamlit 自带的，没有动。

### 没法照人那样做、或者没做的

- 自动化工具的"移动鼠标"是从一点直接跳到另一点，不是连续划过去。上面"经过工具条"那一条是分三步跳的。
- **图标的名称提示会暂时压住按钮**（这次量出来的，改之前也一样）。鼠标在工具条某个图标上停满一秒，
  会冒出它的名称（"Search"、"Download as CSV"……），出在图标上方——工具条抬着的时候，那正是
  「清除筛选」的位置：量到的是按钮 3200 个点里 2135 个落在提示框上（按钮顶边往下 9.5 像素起）。
  鼠标一离开图标它当场消失（挪到图标与提示框之间的空隙里，立刻就没有了，之后按钮整个点得中）；
  但鼠标若是一下子跳进提示框所在的那一块，它不消失，那一下点中的是提示框——自动化的"跳"正好造出了
  这种情况，真人要划得很快才会碰上，挪一下鼠标它就没了。要连它也让开，空当得留到约 80 像素（提示框顶边
  比表格顶边高 74.7 像素），没有这么做。
- 只在应用自带的浏览器（Chromium 内核）、深色主题、100% 缩放、根字号 16 像素下量过；没有换别的浏览器，
  也没有试触屏。
- 没有请独立审查。改动是两处调用加一个四行的函数，上面的验收与变异自查是我自己做的。
- 给用户看的那份副本（里面是他账本的拷贝）只用来摆三种做法，验收没有在它上面做。

## 7. 没做的 / 留给以后

- **别的页有同一个毛病**（顺带扫了一遍八个功能页的默认状态，1440 宽，都没有动）：
  - 「持仓与盈亏」页：有持仓不在信号池时，「当前持仓」表格上方那条提醒右端的「去信号池」链接
    （96×28 像素）**整个**在工具条抬起来的范围里——鼠标停在表上时逐点量过，2688 个点全部落在工具条上；
  - 「任务控制台」页：「本次结果」折叠区展开时，它上面那一行右端的「去增删信号池」链接下半截
    （约 14 像素）在范围里（只按矩形算的，没有用真鼠标验证）；
  - 「回测报告」页：「选择回测」下拉框的底边有 4 像素在范围里。
  「信号」「信号池」两页的表格上方靠右没有可点的东西；首页与「个股K线」没有表格。
  要改的话是同一个办法（`ui.toolbar_room()`），各页的版式要各自看。
- 平时工具条仍压在收着的「筛选」那一行右端（§4）。
- 图标的名称提示（§6 最后一段）。
- 「记账」页页顶那个折叠说明、「恢复上一版」的"先勾再点"，都是上一轮留下的，这次同样没有动。
