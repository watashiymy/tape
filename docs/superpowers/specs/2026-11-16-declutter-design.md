# 减字、重排「记一笔」、按钮靠右（2026-11-16，当天第三轮）

分支：`feat/ui-declutter`（从 main a398bf2 拉出，工作区在 `.claude/worktrees/ui-declutter`）。
这是一份**事后补的设计记录**。流程：用户看过上一轮（任务条 + 记账页）合并后的面板，提了三条；
盘点完直接在隔离的工作区里改，**页面一能看就先开预览给用户**，然后才补测试、真机验收、独立审查。

## 0. 起因

用户（2026-11-16）三条，原话：

1. 「每个子页面 title 旁边的注释小字删掉，比如"按全部记录算出的当前持仓、已实现盈亏与来源对比。"……
   系统其他这类解释性文字也都删掉（比如"填入 6 位代码后，这里会带出名称与该日的价格区间（都取自本地数据，
   离线可用）。"）——对用户而言实在是有理解成本的，可以用"？"来提示，光标聚焦到"？"的时候再弹出提示」
2. 「"记一笔"这里的信息输入框的排版可以再优化一下吧，现在方向、成交日期、代码、股数、成交价都放在同一行，
   "买入"、"卖出"两个单选框跟其他输入框之间空隙又那么大，看起来很别扭」
3. 「操作按钮是否可以统一位置，比如都统一放在右下角或者某个地方。现在"记这一笔"是放在左下角的，
   其他页面的一些按钮有放在右下角的，很不统一。」

## 1. 减字：页面上只留会变的东西

### 判据

往页面上放一句话之前先问：**它会变吗？**

- **会变的留在明面上**，三类：状态与数据（最新结果是哪天的、进度、筛出几条、还有几行没保存、代码带出的
  名称与价格区间）；出了问题时的话（报错、告警、几只持仓拿不到市价）；空白处的一句指路（空态）。
- **不会变的就是解释**，收进最近的那个「？」：页名、区块小标题、卡片标题后面的帮助圆点
  （`theme.help_dot`，悬停或 Tab 键选中才出），输入框标题旁原生的问号，按钮的悬停提示。

这条判据比"哪句该删"好用：它不需要逐句争论有没有用——有用的解释照样留着，只是不再常驻。

首页剩成交额那一行，持仓页剩一句空态（「还没有平仓记录——……」），控制台剩三张卡片各自的「上次运行：……」
——都是会变的东西。

### 几个决定

- **页名后面留一个 `?`，而不是把那句话彻底删掉。** 用户的话是"删掉……可以用 ？ 来提示"。圆点不占地方，
  第一次来的人想知道"这页是干什么的"仍然问得到。八个功能页与手册三页一律都有，不逐页判断哪句值得留。
- **控制台卡片上那句「做什么 / 什么时候跑」拿掉了——这是推翻第一轮（当天上午）自己的决定。** 当时的理由是
  "它们正是第一次用的人点开始之前最需要知道的"，所以从问号里搬到了卡片上。用户这次的反馈正相反：常驻的解释
  读起来是成本。两头都对的做法是问号里说全（本来就说全了），卡片上只留会变的。`guide.CONSOLE_LEAD` 删除，
  不留着没人用的文案。
- **空态只指路。** 「还没有回测结果——点上方的「开始回测」跑一次。」多久、什么时候跑、第一次要多久，
  在那个按钮自己的悬停提示里（光标到按钮上一定先看到）。只有全市场扫描那句多留半句（"全量要很久，第一次
  先去控制台点试跑"）：那是半小时到两小时的事。
- **读表说明挂在哪**：有小标题的表挂小标题后面的 `?`；没有小标题的（「持仓与盈亏」标签页里的两张、
  回测一览）表格上方出一行很短的「读表说明 `?`」（`ui.data_table` 的 `help`，表格为空时不出）。
  初稿把后一种挂在最相关那一列的列头上，独立审查指出那等于没有：列头的悬停提示没有问号可看，
  平仓明细要指的那一列还在横向滚动条外面。原先那个把整句话摆在表格上方的 `hint` 参数删除。
  「当前持仓」那张表不再有总说明：它要说的两件事，一件在那两列自己的列头上，一件在页顶的已知局限里。
- **「默认池子」做成小标签**：它是状态（这个池子不是你自己挑的），不是解释；改过一次之后就不再出现。
  那句完整的话进了小标签的原生悬停提示，所以是纯文字、不带加粗的星号。
- **输入框标题里的括号也是解释**：「理由（为什么做这一笔）」→「理由」（示例文字本来就在输入框里）；
  「股数变化（送股填正、缩股填负）」→「股数变化」+ `?`，空着的框里另摆一个示例「100 或 -50」
  （正负号填反是这一页上不会报错的错）；另两个同理。控制台「更多选项」里的参数标题一样处理：
  「只扫前 N 只（留空=全量）」→「只扫前 N 只」，「留空 = 全量」在空着的框里。
- **「清单基准日某日，可选多少只」留在明面上**（信号池页）：它是会变的事实。初稿把它收进了搜索框的
  悬停说明，独立审查指出这不合自己定的判据。
- **没动的**：记账页与持仓页顶上的两个折叠说明（「这一页记什么、四种记录类型的含义」「这些数字怎么算的、
  已知局限」）——它们本来就是"要看才展开"；侧栏底部的免责声明；从信号页预填过来时表单上方那一句
  （预填的日期是信号日不是成交日，照着记就是一个看着正常的错数——缩成一句，留在明面上）；一切报错与告警。

## 2. 「记一笔」重排

### 改之前的毛病

第一行五格：方向（单选）、成交日期、代码、股数、成交价，比例 1.4:1:1:1:1。单选框只有「买入」「卖出」
两个圆点加四个字，占不满那一格，后面空着一大截；它又和四个带边框的输入框排成一行，高矮形状都不一样。
第一行下面常驻一句灰字，再下面是第二行，按钮单独在卡片左下角。

### 现在的样子

```
记一笔
[ 买入 | 卖出 ]                                             ← 方向：一个切换，自己占一行
代码 ?        成交日期       股数           成交价           ← 四格等宽，每一笔都要填的就这四样
理由                         来源 ?         计划止损价 ?     ← 理由占前两格，逐栏对齐
更多：佣金与印花税、成交时刻、备注 ›
000333 · 美的集团 · 2026-08-03 区间 [70.10, 72.30]
核对  买入 1,000 股 × 71.50 = 71,500.00 元；……共付出 71,517.88 元      [＋ 记这一笔]
```

### 几个决定

- **方向用分段切换（`st.segmented_control`），不用单选、不用下拉。** 它是这张表单的"模式"，先定买还是卖，
  再填别的；分段切换带边框、与输入框同高，单独占一行不显得空。下拉要点两下，二选一不值。
  `required=True`：点已经选中的那个不会变成"都没选"。标题收起——「买入｜卖出」自己就说清了这是什么。
  初值写进 `session_state`（`setdefault`）而不是 `default=`：从信号页预填时也是往这个键里写，两头都给值
  Streamlit 会告警。
- **四格等宽，第二行用嵌套分栏与它逐栏对齐。** 第二行原先写成一行 2:1:1，真机一量与上面差 3 px：
  栏与栏之间的空隙是固定宽度，三栏只有两道空隙、四栏有三道。改成"先对半分、右半边再对半分"之后分毫不差
  （1440 宽下四格左缘 396 / 637 / 878 / 1119，第二行 396 / 878 / 1119）。
- **核对挪到表单底部左侧，紧挨着右下角的主按钮。** 原先它夹在第一、二行之间；那句常驻的灰字拿掉之后，
  它在没填时是空的、填了才出现，夹在中间会让下面几行跟着跳。放在底部：表单中间不动，点按钮之前眼睛正好
  经过它。费用直接取「更多」里两个输入框这一轮的值（它们现在在核对上面）。
- **「其他记录」同一种排法**：「股数调整｜现金分红」切换、一行四格、第二行最后一格是按钮。按钮从
  「记这一笔（其他）」改名「记这一条」——那个括号是给代码看的。

## 3. 操作按钮一律靠右

### 盘点

| 按钮 | 改之前 | 现在 |
|---|---|---|
| 记账：「记这一笔」 | 卡片左下 | 卡片右下（核对在它左边） |
| 记账：「记这一笔（其他）」 | 折叠区左下 | 折叠区右下，改名「记这一条」 |
| 记账：「保存修改」 | 表格左下，提醒在它右边 | 表格下面那一行的最右；提醒在这一行下方、靠右 |
| 记账：「恢复上一版」+ 确认框 | 再下一行的左边，按钮在前 | 同一行，确认框在前、按钮在后（先勾再点） |
| 记账：两个导出、「清除筛选」 | 右（没动） | 导出并进同一行 |
| 控制台：主按钮、「试跑 300 只」 | 标题行右端（没动） | — |
| 控制台：主按钮的悬停说明 | 没有 | 这一下会跑什么、要多久、什么时候跑（`guide.CONSOLE_START_HELP`） |
| 控制台：「沿用上次参数重跑」 | 「更多选项」里左边，说明在它上方 | 同一行：说明在左、按钮在右 |
| 任务条：三个开始按钮 | 各行右端（没动） | — |
| 任务条：「停止」 | 进度那一行的**最左** | 进度条右边 |
| 控制台卡片：「停止」 | 进度条右边、撑满那一栏 | 进度条右边、它自己的宽度（与开始按钮右缘对齐） |
| 首页：「开始准备 / 更新收盘数据」 | 说明下面的左边 | 同一行：说明在左、按钮在右；任务在跑时留在原位、点不了 |
| 首页：「停止」 | 进度条下面的左边，自己画的一份 | 与另两处同一种画法（`ui.running_row`），在进度条与开始按钮之间 |
| 三处的「停止」：悬停说明 | 没有 | 关掉浏览器也不会中断；停掉这个任务会丢什么（扫描：这趟已扫出的信号） |
| 信号池：「加载可选标的清单」「重试」 | 左 | 右 |
| 信号池：「加入信号池」 | 搜索框下面的左边 | 与搜索框同一行的右端 |

规矩两句话：**操作按钮靠右；表单的提交按钮在表单右下角，一行里有几个按钮时主按钮在最右。**
**有东西冒出来、消失的时候，按钮不许跟着挪——尤其不许让一个按钮落到另一个按钮刚才的位置上。**
表格每行的「＋ / −」是表格的一列，「去某页」的链接跟着它解释的那句话，都不在此列。

### 「停止」从最左挪到右边，为什么仍然安全

上一轮把任务条上的「停止」放在进度那一行的最左，写的理由是"与上面几行的开始按钮上下也不对齐"。
真正防住"任务恰好跑完的那一刻，光标底下的按钮从停止变成开始"的是另一条：**进度那一行排在所有任务行
之后**。它来了又走，上面哪个开始按钮都不挪位置；它消失时往上补位的只有任务条下面的内容（小标题、表格），
那里没有开始按钮。这一条没变，测试照旧钉着（顺序、不同行）；"最左"那条是多上的一道保险，为了位置统一撤掉了。

### 首页：两个按钮放进同一行

首页的按钮区在页面**最底下**，"上下错开"在这里防不住：

- 初稿：运行中是「进度 + 停止」一行，没在跑时是「说明 + 开始」一行——两个按钮都在这一区第一行的右端。
  独立审查在真实浏览器里量到位置完全重合：点了停止，手快再点一下，就把刚停的任务又起了一遍。
- 第二稿：照控制台与任务条的办法错开成两行（开始按钮留在上面一行、点不了，停止在下面一行）。
  真机复验仍然不行：任务一停，下面那一行没了、页面变短，浏览器把滚到底的内容整体往下挪，
  上面那一行的开始按钮落到停止原来的位置（1280 宽下量到重合 2 px；没有进度条下面那行灰字时完全重合）。
  反过来把停止放在上面一行，页面没滚到底时又会撞。
- 定稿：**同一行**——进度、停止、然后是那个点不了的开始按钮。开始按钮始终是这一行的最后一个，
  运行前后这一行的高度不变；停止在它左边，任务停下之后那个位置是空的。真机量过（1280 宽，滚到底）：
  停止在 x 972–1050，停下之后开始按钮在 x 1066–1200，横向不相交。

控制台卡片与任务条不受这件事影响：它们下面还有很长的内容，任务结束时页面是从上往下收的。

### 靠右，但不许用按比例的窄栏

初稿把三个按钮放进了按比例分出来的右栏（3:1、4:1）。独立审查在真实浏览器里量到：1024 宽、侧边栏展开时
那一栏只有一百出头到一百三十几像素，「更新收盘数据」「加入信号池」「沿用上次参数重跑」都折成了两行。
现在这三处都是**一个靠右的横向容器**：左边的文字（或搜索框）占剩下的地方，按钮永远是它自己的宽度；
文字太长时是文字折行，或者按钮整个落到下一行的右端。共用的"进度 + 停止"那一行同理。

### 表格下面那一行

一个靠右的横向容器，里面两组：撤销（确认框 + 恢复上一版）一组，导出与保存一组，组内不拆。
1440 / 1280 宽下一行放得下；1024 宽、侧边栏展开时放不下，**整组**折到下一行、仍然靠右——初稿没分组，
折成了「确认框 + 恢复 + 导出 CSV」一行、「导出 Excel + 保存」一行。

"还有几行没保存"那句提醒在这一行的**下面**、靠右。初稿放在上面：它是改了第一格才冒出来的，会把整行按钮
顶下去——独立审查量到 1024 宽下「恢复上一版」正好落到「保存修改」原来的位置上，确认框若恰好勾着，
奔着保存去的那一下就成了恢复。放在下面，哪个按钮都不动（真机量过，五样东西的位置逐一相同）。
同一个道理，录入卡片底部那一行两栏**顶端对齐**：核对那两行是填完最后一格才冒出来的，底端对齐时
按钮会被它顶下去（1024 宽下 48 px），顶端对齐则不动。

审查之外，处理意见时自己抓到的两件事：

- 上面第一条里说的"错开两行仍然会撞"——只有在真实浏览器里把页面滚到底再点停止才看得出来。
- 给 `sits_on_the_right` 加自测之后，全量测试里**另一条不相干的测试**（两个进程同时写日志那条）变红，
  单跑却是绿的。原因：AppTest 跑脚本时把 `sys.modules["__main__"]` 换成那份脚本、跑完不换回来；
  那条测试用 spawn 起子进程，子进程会先把父进程的 `__main__` 按路径重跑一遍——前一条留下的若是
  `AppTest.from_function` 的临时脚本（跑完就没了），子进程直接退出。`tests/conftest.py` 加了一个
  每条测试结束后把 `__main__` 换回原样的夹具，测试之间不再靠这种残留互相影响。
