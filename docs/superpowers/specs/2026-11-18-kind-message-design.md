## 0. 起因

做历史记录的删除交互那一轮顺带看到的旧问题（`2026-11-18-journal-delete-design.md` §7 列着），主分支上本来就有。

「记账」页「历史记录」表里，「类型」是个下拉格子，没有设成必填：选中它按删除键、或者在下拉里选最上面那个空项，
这一格就空了。这时点「保存修改」会被拦下——拦下是对的，可给人看的那句话是：

> 无法解释的记录类型 'nan'，只支持 buy/sell/adjust/dividend

两处不对：`'nan'` 是「格子空着」在程序里的样子，使用者没填过这个词；后面四个英文词是存进文件的键，页面上别处都叫
买入 / 卖出 / 股数调整 / 现金分红。面板文案的规矩（用户定的）：不出现实现细节和开发者术语，中文里不夹英文值。

## 1. 出处

`src/quant/journal/schema.py::validate_trade` 原先写的是 `kind = str(row.get("kind") or "").strip()`。
清空的格子交回来不是 None，是 NaN；NaN 算真值，`NaN or ""` 还是 NaN，`str` 之后成了 "nan" 三个字母——于是走进了
「类型认不出来」（`BAD_KIND`）而不是「缺少类型」（`MISSING`）那一支，`BAD_KIND` 那句又把 `KINDS` 那四个键原样拼了出来。
同一类毛病两天前在日期那一格上修过一次（清空的日期是 `pd.NaT`，见 `2026-11-16-status-bar-journal-design.md`）。

这句话有三个地方会看到：

1. 页面顶上「**没有保存**（下面这些行改坏了……）」那一条（`journal_ui.save_edits`）；
2. 删除确认框里「**没有删除，也没有保存**……」那一段（`journal_ui.delete_trades`——删除会连同表里没保存的改动一起保存，所以也过校验）；
3. 「记一笔」表单的报错（`journal_ui.submit`）。表单上类型是个必选的切换，填不出空值，这一处实际出不来这句。

## 2. 改了什么

| 情形 | 原先 | 现在 |
|---|---|---|
| 类型那一格空着 | 无法解释的记录类型 'nan'，只支持 buy/sell/adjust/dividend | 缺少记录类型（买入/卖出/股数调整/现金分红） |
| 类型是个认不出来的词（页面上填不出来，手改文件才会有） | 无法解释的记录类型 'split'，只支持 buy/sell/adjust/dividend | 记录类型「split」认不出来，要重新选一种（买入/卖出/股数调整/现金分红） |
| 被拦下那一行前面的「是哪一行」，日期正是清空的那一格 | T1（None 000333）：缺少成交日期…… | T1（000333）：缺少成交日期…… |
| 同上，代码是清空的格子 / 代码只有空白 / 日期代码都空 | T1（2026-08-03 nan）、T1（2026-08-03    ）、T1（None None） | T1（2026-08-03）、T1（2026-08-03）、T1 |

- `schema.validate_trade`：类型空不空改问 `schema.is_blank`（None / 空串 / 只有空白 / NaN / NaT / `pd.NA` 都算空——
  最后一种原先会当场抛 TypeError）。**问题码与「哪些算阻断」一个没动**：空着的类型本来就该是 `MISSING`，
  它与 `BAD_KIND` 都在 `BLOCKING_CODES` 里，该拦的照样拦，只是说法对了。
- 两句里列的可选项取自同一处（`schema.KIND_NAMES`，顺序同 `KINDS`）。原先「缺少」那句手写着「分红」，
  现在与页面一样叫「现金分红」。
- `journal_ui._which_row`（新，`blocking_rows` 用它）：被拦下的每一行前面那段「记录号（日期 代码）」，日期、代码
  哪个空着就不写哪个，都空着只剩记录号。这一段不在 `schema.py` 里，但它就是那句话的前半截——那一行多半正是因为
  某一格被清空才被拦下的，空格子照原样拼进去，页面上就是「None」「nan」。

## 3. 几个决定

- **认不出来那句说「要重新选一种」，不说「只能是……」**。手改文件的人若写的正是「买入」两个字（文件里该写的是键），
  「『买入』认不出来，只能是买入……」是一句自相矛盾的话；而在历史表那一格的下拉里重新选一次，哪种写错法都改得好
  （真实浏览器里走过：那一行的类型在表里是空的，下拉里选「买入」、保存，存进去了）。
- **认不出来的那个词用「」括起来、照原样写**（只去掉两头的空白）：他得知道是文件里哪个词不对。不用程序的写法
  （带英文单引号）。
- **「是哪一行」里空着的那一样直接不写**，不补「日期空着」之类的字：缺的是什么，冒号后面那句校验的话会说。
- **没有把「类型」「来源」两列设成必填**。那是另一种补法（格子根本清不空），但会改变表格的手感，要做先问使用者。
  「来源」清空后保存会存成空、别处显示成「—」，没有报错可言，没有动。
- 那张 `st.data_editor` 照旧不带 key。

## 4. 同一个文件里其余的话

`schema.py` 里每一句都用虚构的行造出来看过，按「使用者从页面上触发得了吗、露不露 nan / None / 存进文件的键」分：

| 句子（例） | 页面上怎么来的 | 处理 |
|---|---|---|
| 缺少成交日期：……／成交日期 2026-11-19 晚于今天 2026-11-18／买入必须填写股数／股数调整为 0 没有意义……／缺少标的代码：……（代码是空串时） | 表单没填完、表里改坏 | 干净，没动 |
| 代码 'nan' 不是 6 位数字，请确认没打错 | 表里把「代码」那一格**按删除键**清空（同一个毛病：NaN 被当成了字） | 第一轮没动、列出来问；**第二轮堵上了**（§8） |
| 买入 1.00005e+06 股不是 100 股的整数倍／卖出 1.5e+06 股，超过当前持仓 1.2e+06 股／买入的股数必须为正，实际 -1.5e+06 | 一百万股及以上的数（前两句：录入表单记下之后的「请复核」；第三句：表里把股数改成负数后保存） | 第一轮没动；第二轮改了（§8） |
| 代码 '333' 不是 6 位数字，请确认没打错 | 录入表单填了三位的代码，记下之后的「请复核」 | 第一轮没动；第二轮改了（§8） |
| 日期 '八月二十七' 无法解析……／股数的值 'abc' 不是数字 | 页面上触发不了：表单与表格里这两种格子只收日期 / 数字；文件里手改成这样，读文件那一步就先报错了 | 没动 |
| 未知字段 […]，可用字段：[…] | 写代码时字段名打错才会有，不是给使用者看的 | 没动 |

**「代码」清空那一条比措辞要紧，所以单独拎出来而不是顺手改掉。** 那句「代码 'nan' 不是 6 位数字」是一条**警告**，
保存那条路只看阻断项，所以页面上看不到这句话；看得到的是后果——**那一行被存进去了，文件里代码是空的**。
真实浏览器里用虚构账本复现过：选中「代码」那一格按删除键，点「保存修改」，提示是「已保存：改了 1 行」。
之后「持仓与盈亏」页会列出「有一行记录读不出来（类型 卖出、代码 空、日期 ……），已跳过」，下一次保存也会因为
这一行被拦下（文件里读回来的是空串，校验认得空串），所以不是完全无声；但设计上「缺少标的代码」是该当场拦下的。
修法与类型那一处相同（空不空问 `is_blank`），可它会让一个原先存得进去的操作变成被拦下——那不是改措辞，
第一轮的范围是措辞，所以当时没有动、列出来问；使用者说「堵上」之后在第二轮改了（§8）。

> **更正（2026-11-19）**：这一段的第一版还写着「点进格子把字删光再回车也一样，两种清法交回来的都是空值、不是空串，
> 从页面上把代码清空怎么清都拦不住」。这半句是错的。第二轮在后台直接看了表格交回的值：按删除键交回的是空值，
> 把字删光交回的是**空串**——后一种一直拦得住。第一轮那次「把字删光」的操作其实没有落进编辑框里，按下去的
> 仍然是格子上的删除（那一格显示成了「—」，而真把字删光时它是空白的）。漏的只有按删除键那一种。

另两条没动的理由：`1.5e+06` 是数字格式（`:g`）在一百万以上的写法，不属于 nan / None / 键，但同样不是给人看的
（算盈亏那一层已经为此换过写法，`pnl._qty`）；`'333'` 外面那对英文单引号是把值按程序的写法打出来的结果，值本身是
使用者自己敲的。都拿不准算不算第一轮的范围，当时列在这里；第二轮一并改了。

## 8. 第二轮：堵上「代码」清空也能保存，数与引号也改了（2026-11-19）

使用者看过 §4 之后的原话：「堵上」。三处一起做（第一轮交回时说过：点「堵上」就连那两处措辞一起改）。

### 改了什么

| 情形 | 原先 | 现在 |
|---|---|---|
| 历史表里选中「代码」按删除键，再点「保存修改」 | **存进去了**，提示「已保存：改了 1 行」，文件里那一行的代码是空的 | 拦下：记录号（日期）：缺少标的代码：不知道是哪只票的记录没有意义 |
| 同上，留着这处改动去删另一条 | 那一条删掉了，代码是空的这一行也一起写进去了 | 不删、不存，原因写在确认框里 |
| 一百万股的非整手买入 | 买入 1.00005e+06 股不是 100 股的整数倍 | 买入 1,000,050 股不是 100 股的整数倍 |
| 卖出超过持仓（百万股） | 卖出 1.5e+06 股，超过当前持仓 1.23457e+06 股（持仓还被舍掉了一位） | 卖出 1,500,000 股，超过当前持仓 1,234,567 股 |
| 表里把股数改成负的 | 买入的股数必须为正，实际 -1.5e+06 | 买入的股数必须为正，实际 -1,500,000 |
| 成交价带三位小数且上千 | 成交价 1688.12 不在当日区间 […]（原样是 1688.125，被舍成了六位有效数字） | 成交价 1688.125 不在当日区间 […] |
| 填了三位的代码 | 代码 '333' 不是 6 位数字，请确认没打错 | 代码「333」不是 6 位数字，请确认没打错 |

- `schema._check_symbol`：代码空不空改问 `is_blank`，与类型同一个修法。问题码与 `BLOCKING_CODES` 没动——
  缺代码本来就是 `MISSING`、本来就该拦；变的是「按删除键清空的格子」终于被认成了空。**这是这条分支上唯一一处
  会让原先存得进去的操作变成存不进去的改动。**
- `schema._num`（新）：校验信息里的数照原样写——不用科学计数法、不舍成六位有效数字、末尾多出来的 0 与小数点不拖着、
  写出来是 0 的数不带负号。股数与金额带千分位；成交价不带。`schema.py` 里六处 `:g` 全部换成了它。

### 几个决定

- **成交价不带千分位**。它在句子里紧挨着当日区间，而区间一直写成 `[1600.00, 1700.00]`（表单底下那行核对里也是）；
  「成交价 16,000 不在当日区间 [1600.00, 1700.00] 内」一句话里两种写法。股数与金额带千分位，是页面上别处的写法
  （核对那一行、删除的确认框、持仓与盈亏页的提示）。区间那半句没有动。
- **日常的数一个字没变**：150 股、500 股、-7.1、715 这些原先怎么写现在还怎么写（有测试钉着），变的只有上千的数多了
  千分位、上百万的数不再是科学计数法、小数不再被舍。
- **不像 6 位数字的代码照旧只提醒、不拦**（港股通、基金、打错一位都可能）——连真的敲了 nan 三个字母也一样，
  那是他填的，不是空格子。代码两头的空白照旧去掉再认。
- 三处数字格式的小工具（这里的 `_num`、`pnl._qty`、`journal_ui._exact`）各管各的句子，没有并成一个：
  三处要的小数位与千分位不一样，而且 `pnl` 与页面那一层都不该被校验这一层反过来引用。

### 两种清法交回的东西不一样（更正第一轮的说法）

在预览副本的校验入口加了一行日志（只改了 `/tmp` 里那份一次性的副本），在真实浏览器里各清一次再点保存，直接看后台收到的值：

| 清法 | 交回的值 | 格子里显示 | 原先 | 现在 |
|---|---|---|---|---|
| 选中格子按删除键 | `nan`（空值） | — | 代码：**存进去了**；类型：拦下，但话是「'nan'…」 | 都拦下，话是对的 |
| 点进格子把字删光再回车 | `''`（空串） | 空白 | 一直拦得住 | 照旧拦下 |

第一轮写的「两种清法都一样」是错的（§4 里已更正）。教训记在这里：自动化工具往表格里按键之前，先确认焦点真的在
编辑框里（`document.activeElement` 是不是那个 `TEXTAREA`）；格子里显示「—」还是空白，本身就是在说交回的是哪一种。

### 测试与验证

- 先写、先看着红（15 条：按删除键清空的代码被判成警告、`pd.NA` 当场抛错、页面级的两条里文件真的被写了、
  各句里的 `e+06` 与 `'333'`），再改代码。
- `tests/test_journal_schema.py`：代码是六种「空」时都是 `MISSING` 且阻断；敲了字的怪代码（含 `nan` 三个字母）照旧只提醒；
  两头带空白的好代码不提醒；上百万的股数、金额写全带千分位；日常的数与原先一字不差；成交价照输入写、不带千分位；
  六种会带数的句子里都没有科学计数法；怪代码用「」引。
- `tests/test_journal_refusal_wording.py`（页面级）：两种清法（送 `None` / 送空串）点保存都被拦下、文件与上一版都没动、
  没有「已保存」；留着清空的代码去删另一条——不删不存、原因在确认框里；表单记下一百万股的非整手、三位的代码之后，
  那句「请复核」是新的写法。
- 全量测试：2860 通过、1 跳过（接在第一轮自己那四个提交后面时）；改接到三件后续任务合在一起的
  `feat/journal-delete` 后面之后 2877 通过、1 跳过（多出来的是另两件的测试）。只挪测试位置的那个提交单独检出来跑过，也是绿的。
- **变异自查**：这一轮的改动 23 处单点变异，第一轮 22 处红；漏的一处是「代码两头的空白不去掉」——原有的行为
  没有测试钉着，补了一条之后也红。
- **真机验收**（`/tmp` 里的隔离副本、虚构账本，1440×900）：
  1. 选中「代码」按删除键 → 保存：页面顶上「没有保存（……）：记录号（2026-08-24）：缺少标的代码：……」，
     没有「已保存」，文件的指纹没变。
  2. 留着这处改动点另一行的垃圾桶 → 确认框写「表里另有 1 行改动还没保存，会一起保存」→ 点「删除」：框不关，
     框里是「没有删除，也没有保存（……）」加同一句，页面顶上没有东西。
  3. 点进「代码」把字删光再回车（先确认了焦点在编辑框里）→ 保存：同样拦下。
  4. 表单里填三位的代码记一笔：「……已记下，但请复核：代码「333」不是 6 位数字，请确认没打错」。
  5. 表单里买入 1000050 股：「……请复核：买入 1,000,050 股不是 100 股的整数倍（可转债/科创板另有规则）」。
  6. 表单里卖出 1500000 股（账上有 1,001,350 股）：「……请复核：卖出 1,500,000 股，超过当前持仓 1,001,350 股，
     是不是漏记了一笔买入？」；1024×768 下折成两行，没有横向溢出。
- 这一轮同样没有另请独立审查。
