# 「类型」留空时的那句报错：不出现 nan 与存进文件的键（2026-11-18，当天第四轮）

分支：`claude/interesting-haslett-2afdd0`，**压在 `feat/journal-delete`（a3d037f）上面**——那条分支改了同一批文件，
做这件事时它还没合进 main。事后补的设计记录。本文与测试里的例子一律用虚构的票和数（仓库是公开的，用户的交易记录不进仓库）。

## 0. 起因

做历史记录的删除交互那一轮顺带看到的旧问题（`2026-11-18-journal-delete-design.md` §7 列着），主分支上本来就有。

「记账」页「历史记录」表里，「类型」是个下拉格子，没有设成必填：选中它按删除键、或者在下拉里选最上面那个空项，
这一格就空了。这时点「保存修改」会被拦下——拦下是对的，可给人看的那句话是：

> 无法解释的记录类型 'nan'，只支持 buy/sell/adjust/dividend

两处不对：`'nan'` 是「格子空着」在程序里的样子，使用者没填过这个词；后面四个英文词是存进文件的键，页面上别处都叫
买入 / 卖出 / 股数调整 / 现金分红。面板文案的规矩（用户定的）：不出现实现细节和开发者术语，中文里不夹英文值。

## 1. 出处

`src/quant/journal/schema.py::validate_trade` 原先写的是 `kind = str(row.get("kind") or "").strip()`。
清空的格子交回来不是 None，是 NaN；NaN 算真值，`NaN or ""` 还是 NaN，`str` 之后成了 "nan" 三个字母——于是走进了
「类型认不出来」（`BAD_KIND`）而不是「缺少类型」（`MISSING`）那一支，`BAD_KIND` 那句又把 `KINDS` 那四个键原样拼了出来。
同一类毛病两天前在日期那一格上修过一次（清空的日期是 `pd.NaT`，见 `2026-11-16-status-bar-journal-design.md`）。

这句话有三个地方会看到：

1. 页面顶上「**没有保存**（下面这些行改坏了……）」那一条（`journal_ui.save_edits`）；
2. 删除确认框里「**没有删除，也没有保存**……」那一段（`journal_ui.delete_trades`——删除会连同表里没保存的改动一起保存，所以也过校验）；
3. 「记一笔」表单的报错（`journal_ui.submit`）。表单上类型是个必选的切换，填不出空值，这一处实际出不来这句。

## 2. 改了什么

| 情形 | 原先 | 现在 |
|---|---|---|
| 类型那一格空着 | 无法解释的记录类型 'nan'，只支持 buy/sell/adjust/dividend | 缺少记录类型（买入/卖出/股数调整/现金分红） |
| 类型是个认不出来的词（页面上填不出来，手改文件才会有） | 无法解释的记录类型 'split'，只支持 buy/sell/adjust/dividend | 记录类型「split」认不出来，要重新选一种（买入/卖出/股数调整/现金分红） |
| 被拦下那一行前面的「是哪一行」，日期正是清空的那一格 | T1（None 000333）：缺少成交日期…… | T1（000333）：缺少成交日期…… |
| 同上，代码是清空的格子 / 代码只有空白 / 日期代码都空 | T1（2026-08-03 nan）、T1（2026-08-03    ）、T1（None None） | T1（2026-08-03）、T1（2026-08-03）、T1 |

- `schema.validate_trade`：类型空不空改问 `schema.is_blank`（None / 空串 / 只有空白 / NaN / NaT / `pd.NA` 都算空——
  最后一种原先会当场抛 TypeError）。**问题码与「哪些算阻断」一个没动**：空着的类型本来就该是 `MISSING`，
  它与 `BAD_KIND` 都在 `BLOCKING_CODES` 里，该拦的照样拦，只是说法对了。
- 两句里列的可选项取自同一处（`schema.KIND_NAMES`，顺序同 `KINDS`）。原先「缺少」那句手写着「分红」，
  现在与页面一样叫「现金分红」。
- `journal_ui._which_row`（新，`blocking_rows` 用它）：被拦下的每一行前面那段「记录号（日期 代码）」，日期、代码
  哪个空着就不写哪个，都空着只剩记录号。这一段不在 `schema.py` 里，但它就是那句话的前半截——那一行多半正是因为
  某一格被清空才被拦下的，空格子照原样拼进去，页面上就是「None」「nan」。

## 3. 几个决定

- **认不出来那句说「要重新选一种」，不说「只能是……」**。手改文件的人若写的正是「买入」两个字（文件里该写的是键），
  「『买入』认不出来，只能是买入……」是一句自相矛盾的话；而在历史表那一格的下拉里重新选一次，哪种写错法都改得好
  （真实浏览器里走过：那一行的类型在表里是空的，下拉里选「买入」、保存，存进去了）。
- **认不出来的那个词用「」括起来、照原样写**（只去掉两头的空白）：他得知道是文件里哪个词不对。不用程序的写法
  （带英文单引号）。
- **「是哪一行」里空着的那一样直接不写**，不补「日期空着」之类的字：缺的是什么，冒号后面那句校验的话会说。
- **没有把「类型」「来源」两列设成必填**。那是另一种补法（格子根本清不空），但会改变表格的手感，要做先问使用者。
  「来源」清空后保存会存成空、别处显示成「—」，没有报错可言，没有动。
- 那张 `st.data_editor` 照旧不带 key。

## 4. 同一个文件里其余的话

`schema.py` 里每一句都用虚构的行造出来看过，按「使用者从页面上触发得了吗、露不露 nan / None / 存进文件的键」分：

| 句子（例） | 页面上怎么来的 | 处理 |
|---|---|---|
| 缺少成交日期：……／成交日期 2026-11-19 晚于今天 2026-11-18／买入必须填写股数／股数调整为 0 没有意义……／缺少标的代码：……（代码是空串时） | 表单没填完、表里改坏 | 干净，没动 |
| 代码 'nan' 不是 6 位数字，请确认没打错 | 表里把「代码」那一格**按删除键**清空（同一个毛病：NaN 被当成了字） | **没动，等使用者发话**，见下 |
| 买入 1.00005e+06 股不是 100 股的整数倍／卖出 1.5e+06 股，超过当前持仓 1.2e+06 股／买入的股数必须为正，实际 -1.5e+06 | 一百万股及以上的数（前两句：录入表单记下之后的「请复核」；第三句：表里把股数改成负数后保存） | 没动，等使用者发话 |
| 代码 '333' 不是 6 位数字，请确认没打错 | 录入表单填了三位的代码，记下之后的「请复核」 | 没动，等使用者发话 |
| 日期 '八月二十七' 无法解析……／股数的值 'abc' 不是数字 | 页面上触发不了：表单与表格里这两种格子只收日期 / 数字；文件里手改成这样，读文件那一步就先报错了 | 没动 |
| 未知字段 […]，可用字段：[…] | 写代码时字段名打错才会有，不是给使用者看的 | 没动 |

**「代码」清空那一条比措辞要紧，所以单独拎出来而不是顺手改掉。** 那句「代码 'nan' 不是 6 位数字」是一条**警告**，
保存那条路只看阻断项，所以页面上看不到这句话；看得到的是后果——**那一行被存进去了，文件里代码是空的**。
真实浏览器里用虚构账本复现过，两种清法都一样：选中「代码」那一格按删除键，或者点进格子把字删光再回车——
交回来的都是空值，不是空串；点「保存修改」，提示是「已保存：改了 1 行」。也就是说，从页面上把代码清空，怎么清都拦不住。
之后「持仓与盈亏」页会列出「有一行记录读不出来（类型 卖出、代码 空、日期 ……），已跳过」，下一次保存也会因为
这一行被拦下（文件里读回来的是空串，校验认得空串），所以不是完全无声；但设计上「缺少标的代码」是该当场拦下的。
修法与类型那一处相同（空不空问 `is_blank`），可它会让一个原先存得进去的操作变成被拦下——那不是改措辞，
这一轮的范围是措辞，所以没有动。

另两条没动的理由：`1.5e+06` 是数字格式（`:g`）在一百万以上的写法，不属于 nan / None / 键，但同样不是给人看的
（算盈亏那一层已经为此换过写法，`pnl._qty`）；`'333'` 外面那对英文单引号是把值按程序的写法打出来的结果，值本身是
使用者自己敲的。都拿不准算不算这一轮的范围，列在这里。

## 5. 测试

先写、先看着它们失败（13 条红，原因都是预期的那一个），再改代码。

- `tests/test_journal_schema.py`：类型是六种「空」（NaN / `pd.NA` / NaT / None / 空串 / 只有空白）时都是 `MISSING`
  且阻断；清空的格子那句话里没有 nan、None、四个键，有「类型」与四个页面上的名字；认不出来的值被点出来、
  列的是页面上的名字、码仍是 `BAD_KIND`；两句里列的名字同一串、同一顺序。
- `tests/test_dashboard_journal.py`（页面级）：清空类型点保存——文件不动，报错里是「T1（2026-08-03 000333）：」、
  「类型」与四个名字，没有 nan / None / NaT / 键；清空类型后去删另一条——确认框里是同一句，文件不动；清空日期点保存——
  「T1（000333）：」；`blocking_rows` 逐种情形（都在 / 日期空 / 代码是清空的格子 / 代码只有空白 / 代码两头带空白 / 都空）
  钉住那段「是哪一行」；README 里引的那句「缺少记录类型（……）」必须是页面上真会出现的那一句。

## 6. 验证

- 全量测试：2833 通过、1 跳过（接手时的基线 2814 通过、1 跳过）。必须带 `PYTHONPATH=src`。
- **变异自查**（在工作区的拷贝里做）：这次改的每一处各改坏一种或几种，共 20 处单点变异。第一轮 19 处红；漏的一处是
  「那段『是哪一行』里的日期原样打出来（带时分秒）」——原有的行为没有测试钉着，补了一条断言之后也红。
- **真机验收**（`/tmp` 里的隔离副本、**虚构账本**，没有拷真实账本；1440×900，最后一条另看了 1024×768）：
  1. 类型那一格按删除键清空 → 点「保存修改」：页面顶上是「没有保存（……）：记录号（2026-08-03 000333）：
     缺少记录类型（买入/卖出/股数调整/现金分红）」，文件没动。在下拉里选最上面的空项清空，结果相同。
  2. 留着那处改动去点另一行的垃圾桶 → 确认框里先写「表里另有 1 行改动还没保存，会一起保存」→ 点「删除」：
     框不关，框里是「没有删除，也没有保存（……）」加同一句，页面顶上没有东西，文件没动。
  3. 空着表单点「记这一笔」：「这一笔没有记下来（……）：缺少标的代码：……；买入必须填写股数；买入必须填写成交价」。
  4. 日期那一格清空 → 保存：「记录号（000333）：缺少成交日期：……」；同一次里另一行代码是空的：「记录号（2026-08-24）：
     缺少标的代码：……」。
  5. 把副本文件里一行的类型手改成 `split`：那一行的类型在表里是空的；点保存：「记录号（2026-09-01 600519）：
     记录类型「split」认不出来，要重新选一种（买入/卖出/股数调整/现金分红）」。1024 宽下两句各折成两行，没有横向溢出。
