# 面板文案面向使用者（2026-09-05）

## 0. 起因

用户原话：页面上很多表述其实可以隐藏——「使用说明」页头那句「面板自带的手册。这一页讲……」完全没必要展示；
`config/universe.local.yaml` 这类系统实现细节也没必要展示。使用者不关心系统怎么实现，只想知道怎么用。
**合理的引导、准确的表达、易用的功能**才重要。从这个角度优化。

## 1. 一条规则

面板是给**使用者**的。正常状态下页面上的文字里**不出现实现细节**：

| 不出现 | 例子 | 去哪儿了 |
|---|---|---|
| 文件路径 / 文件名 | `config/universe.local.yaml`、`output/scan/<日期>.csv`、`.meta.json`、`data/cache/` | README |
| 内部键 | `ma_cross`、`universe`、`scan.min_avg_amount` | 只用显示名；键留在文件与 README |
| 命令行开关与命令 | `--limit`、`python scripts/run_*.py` | README §2 / §3 |
| 库名与机制 | baostock、streamlit、parquet、独立进程、SIGTERM、TTL | README |
| 版本号与设计文档编号 | 「v0.1 基线」「v0.5.0 之前的产物」「§3.2」 | 代码注释 / 设计文档 |
| 文档自述与自辩 | 「这一页讲……」「上一版这里写的是假话」「这不是 bug」「有测试钉着」 | 删；结论改成对使用者有用的那半句 |

**仅两处例外**：
1. **错误信息**可以指名坏掉的文件——使用者只能手工修它，路径就是修法。
2. 「你的数据与备份」一节**一次性**列出属于使用者的两个文件——「换电脑要拷什么」的答案本身就是路径。

判据：一句话删掉之后使用者少了什么可做的事？什么都不少，就删。

## 2. 改什么

### 2.1 说明手册：四页 → 三页
- 「自定义策略」整页是写代码的说明，搬到 `docs/custom-strategy.md`（README 指过去）。模板代码的可执行测试跟着搬。
- 「命令行等价用法」一节缩成「命令行」三句话：能在终端跑、命令见 README、终端与面板别同时跑（互相踢连接）。
- 「你的数据在哪（哪些文件不进 git）」→「你的数据与备份」：只保存在本机、不随代码分发；两个文件各一行；换电脑怎么带走。
- 「安全提示」：面板能在本机执行任务、只在本机用、不要暴露到局域网；从项目根目录启动时默认只监听本机（本仓库自带的配置）。命令行开关、lsof 证据留在 README。
- 其余各节：去路径、去键、去开关、去版本号、去自辩。策略表头只用显示名。
- 页头副标题不再讲「这一页讲什么、另外三页在哪」；页尾目录改名「更多说明」，不加导语。

### 2.2 侧栏
- 删两条常驻说明（「第一次用先看使用说明」「本面板可在本机启动任务……详情见控制台」）——第一条是导航自述，第二条是控制台页头已经说了的话。
- 安全警告改成**条件显示**：监听地址不是本机时才亮（`st.get_option("server.address")`）。本仓库从根目录启动时它就是 `127.0.0.1`，天天对着一条不适用的警告等于没有警告。
- 保留一句「仅供学习研究，不构成投资建议」。

### 2.3 功能页
- 控制台：卡片帮助不再写产物路径与 `.meta.json`，改说「结果在哪看」；回测结果卡上方的目录名换成「策略 时间」；「加进信号池」那步不再带文件路径；结果读不出时说「可能还在写入」而不是抛类型名。
- 信号池：不再说「当前池子来自哪个文件」（默认池子还没改过时说一句「这是默认池子」，其余时候不说）；底部那行只说「改动立即生效」；候选清单说明不提数据源与文件。
- 信号：＋ 按钮帮助不提文件。
- 回测报告：总览提示不带版本号；残缺结果的提示先说怎么办（重跑），目录名只在「一直如此」那半句里出现。
- 记账：备份说明不再要求使用者认识 `.bak` 文件——加一个**「↶ 恢复上一版」**按钮（勾确认再点，换回上一版；刚才那版成为备份，再点一次换回来）。这是「易用的功能」替代「知道路径」的典型一例。
- 各处「本地缓存 data/cache/」→「本地已下载的行情」。

### 2.4 纯函数层
- `steps.pool_status` 不再接收/显示来源文件。
- `progress` 的 extras 不再显示「输出 = 路径」（outputs 元组照旧供渲染层读产物）。
- `view.start_button_state` 的提示去掉「（baostock 单会话）」。

## 3. 不做
- 落地页仍是「使用说明」（v0.2.1 的决定；此次只改文字与去噪，不动信息架构）。
- 内部键、脚本文件名、URL 一个不改；老书签只有 `/guide-custom` 会消失（那页搬去了 docs）。
- README 保留全部实现细节——它就是给操作者/开发者的那份。

## 4. 测试
- 文案层测试改为钉**新的**事实：用户可见字面量里不出现内部键（注册表驱动）、说明正文里不出现两个用户数据文件之外的路径、JOB_HELP 有「结果在哪」。
- 侧栏：监听本机 → 无警告；改成 `0.0.0.0` → 每一页侧栏都有警告。
- 恢复上一版：换回、再换回、无备份时禁用、坏备份时一个文件都不动、不留临时文件。
- `docs/custom-strategy.md` 里的模板代码真实导入并跑一段行情（原测试搬家）。

## 6. 落地页换成「任务控制台」（同日，用户定）

- `CONSOLE_PAGE` 加 `default=True`；主组只留 任务控制台 / 信号；「使用说明」并进「手册」组（使用说明 / 读懂回测 / 边界与安全）。
- 控制台新增 `_first_run_hint()`：三个任务的状态文件一个都没有时，给一条去「使用说明」的 `st.page_link`；跑过一次就消失。
- streamlit 规则：默认页挂在 `/`、自己的 `url_path` 不参与路由，不认识的路径回落到默认页。真机实测 `/console`、乱写的路径都落到控制台，**但先弹「Page not found」**（09-14 截图确认，09-05 只读页面文字漏看了），老 `/console` 书签请改根地址；`/guide` 可直接打开。页对象上的 url_path 不动，测试侧按它算哈希照常切页。
- v0.2.1 定的「手册当落地页」到此为止：一本手册当首页，天天用的人每次都要多点一下；引导改由流水线的就绪状态、`?` 帮助与首次链接承担。
