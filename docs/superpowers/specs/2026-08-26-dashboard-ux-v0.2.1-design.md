# 面板体验升级 v0.2.1 设计文档

- 日期：2026-08-26
- 状态：待实施
- 前置：v0.2.0 已完工（471 项离线 + 3 项联网测试全绿）
- 用户诉求三项：① 页面内加使用说明 ② UI 太粗糙、不好看 ③ 处理控制台告警

## 1. 告警处置（先说结论，逐条核实过）

| 告警 | 处置 | 依据 |
|---|---|---|
| `st.components.v1.html` → `st.iframe`，**2026-06-01 后移除** | **必须改**（今天 2026-08-26，已过期 2 个多月） | 现版本 1.61.1 仍能跑，但任何一次 `pip install -U streamlit` 都可能让面板直接崩 |
| `use_container_width` → `width`，**2025-12-31 后移除** | **必须改**（已过期 8 个月），7 处 | 同上。`width='stretch'` 等价 `True`，`width='content'` 等价 `False` |
| 建议装 `watchdog` | **不做** | 只影响开发时热重载速度，且要先 `xcode-select --install`（几 GB 的命令行工具）。对按需运行的本地面板无价值 |
| 建议 `streamlit skills` | **不做** | Streamlit 在推销自家 agent 技能，与本项目无关 |

### 1.1 `st.iframe` 迁移的陷阱（已实测，不可想当然）

- `st.iframe` **没有 `scrolling` 参数**（实测签名只有 `src/width/height/tab_index`）；
- `st.html` **不是**它的替代品：`st.html` 不套 iframe 且**默认忽略 JavaScript**，用它渲染 plotly 报告会得到空白页；
- `st.iframe` 的 `src` 接受 `Path`，且文档明确"HTML 文件会被读取并直接嵌入"——**直接传 `run / "report.html"` 这个 Path**，比自己 `read_text` 更省事，同时消掉一次全文件读取（report.html 约 5 MB）。

因此 `page_backtest` 里的 `report_html = (run / "report.html").read_text(...)` 整行删除，改为 `st.iframe(run / "report.html", height=650)`。**注意**：该文件仍需保留在 `_REQUIRED_FILES` 的存在性检查里（否则半截目录又会崩页），只是不再预读内容。

### 1.2 迁移的回归风险

`use_container_width=True` → `width="stretch"` 是等价替换，但**必须有测试钉住**：这 8 处散布在 5 个函数里，漏改一处就会在未来某次升级时报错，而 AppTest 不会因为参数名过时而失败（现在只是打告警）。加一条源码级断言测试：`app/dashboard.py` 中不得再出现 `use_container_width` 或 `components.v1.html`/`components.html`。这类"防回退"测试很少见但这里合适——废弃 API 会静默复活（比如复制粘贴旧代码）。

## 2. 视觉方向：金融电报（Financial Telegraph）

**为什么不用默认样式**：现在是 Streamlit 出厂外观——浅色底、系统字体、等宽的卡片方阵。对一个每天要盯数字的工具，问题是**信息层级全平**：股票代码、收益率、按钮文字视觉权重一样，眼睛没有落点。

**定的调性**：暗色底 + 琥珀金主色 + 衬线中文标题 + 等宽数字。灵感来自旧交易所报价板与金融电报——权威、密而不乱、数字优先。**不是**赛博朋克霓虹，**不是**紫色渐变那套 AI 默认审美。

### 2.1 色彩（`.streamlit/config.toml` 定基调）

```toml
[theme]
base = "dark"
primaryColor = "#C8963E"              # 琥珀金：主按钮、选中态、强调
backgroundColor = "#12141A"           # 近黑石板，非纯黑（纯黑对比过硬伤眼）
secondaryBackgroundColor = "#1A1D26"  # 卡片/侧栏，与底色只差一档
textColor = "#E8E4DC"                 # 暖白，非纯白
```

**关键决策：基础配色走 `config.toml` 而不是 CSS 注入。** Streamlit 的内部 class 名（`.st-emotion-cache-xxxx`）每版都变，靠它做样式的面板升级必挂——本项目刚被两个过期 API 咬过一次，不能在同一个坑里再摔。`config.toml` 是官方支持面。

CSS 只用于 `config.toml` 表达不了的**排版层级**，且只选择我们自己包出来的语义化容器（如 `<div class="qd-metric">`），不碰 Streamlit 内部 class。

方向色沿用 A 股惯例、与 K 线图一致：**红涨 `#D94A4A` / 绿跌 `#3E9E7A`**。这是全局铁律——收益率、涨跌幅、盈亏都用它，不许某处红绿反过来。

### 2.2 字体

| 用途 | 字体 | 理由 |
|---|---|---|
| 标题 | **Noto Serif SC** | 衬线中文，编辑感、权威感。仪表盘几乎都用无衬线，这个选择本身就是差异点 |
| 正文 | **Noto Sans SC** | 中文正文可读性，与标题同族协调 |
| 数字/代码/日志 | **IBM Plex Mono** | 工业气质、数字辨识度极好（0 有斜杠、1 有底衬），比 Menlo 有性格 |

加载方式：`st.markdown` 注入一个 `@import` 指向 Google Fonts，并**必须写 fallback 链**（`"Noto Serif SC", "Songti SC", serif`）——离线或 Google 被墙时不能变成豆腐块。macOS 自带 Songti SC / PingFang SC / Menlo 兜底。

### 2.3 排版与布局原则

1. **数字最大最亮**：指标卡的数值用 IBM Plex Mono、字号显著大于标签，标签降为小号灰字。现在两者一样重。
2. **发丝线代替方框**：卡片用 1px 低对比分隔线 + 留白划分，不用四面描边（描边多了像 Bootstrap 示例）。
3. **表格右对齐数字、等宽**：金额、涨跌幅、比率一律右对齐 + 等宽字体，眼睛能竖着扫。股票代码也用等宽（前导零才对得齐）。
4. **色只用在有意义处**：琥珀金只给可操作元素与选中态；红绿只给方向；其余靠灰阶层级。禁止为了"好看"给无语义的元素上色。
5. **状态徽标做成有底色的 pill**（运行中=琥珀、成功=绿、失败=红、已停止=灰），比现在的纯 emoji 文字更容易扫到。

### 2.4 各页具体改造

- **通用页头**：每页顶部一行——页名（衬线大字）+ 一句话说明（灰色小字）+ 右侧当前任务状态 pill。取代现在直接甩控件的开局。
- **回测报告**：指标卡改 2 行 × 4 列，数值等宽放大；总收益/回撤按正负上红绿色；`st.iframe` 嵌图表；交易明细表格数字列右对齐 + 用 `column_config` 给金额加千分位、给比率加百分号。
- **个股K线**：标的选择器加名称（现在只有代码）；图上方补一行"本次回测在该标的上的成交笔数/盈亏"小结。
- **今日信号 / 扫描**：信号表格加 `column_config`——`amount` 千分位、`pct_chg` 百分号 + 红绿、`amount_ratio_20d` 用 `ProgressColumn` 可视化放量倍数（这一列是判断信号质量的关键，值得视觉突出）。
- **任务控制台**：三卡片改为等宽三列并排（现在是纵向堆叠，要滚很久）；日志区固定高度等宽滚动；进度条下方的文案分成"主状态"与"细节"两行。

## 3. 页面内使用说明（诉求 ①）

分两层，避免把说明堆成一堵墙：

### 3.1 新增「使用说明」页（放在侧栏第一位，默认落地页）

不只讲"点哪个按钮"，也讲**怎么看懂输出**——这是学习项目，看懂比会点重要。结构：

1. **三个任务分别是什么**：全市场扫描（雷达，只报买入）/ 每日信号（跟踪已选池，报买卖）/ 回测（历史检验）。配一张闭环图：扫描发现 → 加入 `universe` → 每日信号跟踪卖出。
2. **典型工作流**：收盘后（17:30 之后，因为 baostock 那时才更新当日数据）跑扫描 → 看信号表 → 感兴趣的加进配置 → 每天跑每日信号。
3. **怎么读扫描结果**：逐列解释；重点说 `amount_ratio_20d`（放量倍数）比 `pct_chg`（涨跌幅）更值得看，以及"同板块多只信号本质是同一笔押注"这个机械规则看不出来的陷阱。
4. **怎么读回测指标**：逐项解释总收益/年化/最大回撤/夏普/胜率/盈亏比，并**如实写明本项目的实测结论**：两个内置策略都大幅跑输等权买入持有（116% / 49% vs 401%），回撤只有其 1/3；这是诚实结果不是 bug，原因是标的为十年长牛蓝筹、对趋势跟随最不利。
5. **两个内置策略的思路**：双均线（看相对位置、不看量、迟钝）vs 唐奇安（看突破、必须放量、反应快、出场急）。
6. **已知局限**：涨跌停判定是近似、除权按分红再投资、夏普 rf=0、沪深300 是价格指数不含分红、扫描池仅主板非 ST。
7. **安全提示**（单独成块、醒目）：面板能在本机执行脚本，**禁止** `--server.address 0.0.0.0` 暴露到局域网。
8. **命令行等价用法**：三条命令，说明与按钮完全等价。

### 3.2 就地帮助（不跳页也能看懂）

- 每张任务卡片右上角一个 `st.popover("?")`：这个任务做什么、大概多久、参数含义、产物在哪；
- 参数控件用 `help=` 挂 tooltip（如 `--limit`："只扫前 N 只，试跑用；留空=全量约 3010 只"）；
- 每个数据表格上方一行灰色小字，解释关键列；
- 空态文案改成有指导性的："暂无回测结果 —— 点上方「开始」按钮，或在终端跑 `python scripts/run_backtest.py`（约 4 分钟）"。

**文案纪律**：说明里的每个数字（3010 只、约 20 分钟、116%）都必须与项目真实实测一致，不许现编。实测来源：README 与设计文档。

## 4. 分层与可测性

Streamlit 页面本身难做单测，因此：

- **纯函数下沉到 `src/quant/runner/view.py`**（已存在）或新增 `src/quant/report/fmt.py`：
  - `fmt_amount(x)` 千分位、`fmt_pct(x)` 百分号带符号、`direction_color(x)` 返回红/绿/中性
  - `column_config` 的构造函数（返回 dict，可断言）
  - 状态 pill 的文案与色（`status_pill(state) -> (text, color)`）
- **UI 层只做组装**。新增的每个纯函数都要有单测（含 0、负数、None、极大值的边界）。
- CSS 与字体作为单一常量集中一处（`app/theme.py`），便于统一修改与在测试里断言"没有裸写十六进制色值散落各处"。

## 5. 测试策略

- **防回退**：源码断言 `app/` 下不再出现 `use_container_width`、`components.html`、`components.v1.html`。
- **纯函数**：格式化/配色/pill 文案的正反用例与边界。
- **AppTest**：五页（新增使用说明页）全部渲染无异常；`st.iframe` 迁移后回测报告页仍无异常；半截目录仍走友好提示而非崩页（回归 v0.2.0 的修复）。
- **真实验收**：`streamlit run` 实际启动，逐页截图人工核对（暗色主题生效、字体生效、数字等宽右对齐、红绿方向正确）；确认控制台**不再出现**这两条废弃告警。
- **回归**：既有 471 项测试必须全绿；回测/扫描链路未被波及。

## 7. 不做（明确排除）

- 不引入前端构建链（React/自定义组件）——Streamlit 原生 + 少量 CSS 足够，引入构建链会让这个学习项目的维护成本翻倍
- 不做多主题切换（亮/暗），只做暗色一套并做好
- 不依赖 Streamlit 内部 emotion class 名做样式
- 不加装饰性动画（交易面板上跳动的元素是干扰而非愉悦）
- 不新增运行时依赖（字体走 CDN + 系统兜底）
