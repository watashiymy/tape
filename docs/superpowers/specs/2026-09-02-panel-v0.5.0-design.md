# 面板 v0.5.0 设计：说明页拆分 · 任务流水线化 · 文案精简 · 开源准备

状态：设计定稿（2026-09-02）。分支 `feat/v0.5-panel-ux`。

## 0. 由来

用户提了三件事，外加一个开放性问题：

1. 「使用说明」页内容太多，按内容拆成子页面；
2. 全市场扫描 / 加入信号池 / 每日信号这三件事有执行先后，**视觉上**要一眼看出来
   （明确说了「不一定在功能上做严格的限制」）；
3. 页面文字繁琐，适当精简；并且——如果这个系统要开源或当成产品售卖，还有哪些可优化。

第 3 条的后半段是**问题**不是工单，答案落在 §7 与最终汇报里，只把「顺手且明显有价值」
的那几条升级成里程碑。

支撑材料：一次 13 个 agent 的并行审计（6 视角审计 + 6 份对抗性复核 + 汇总），
每条结论都要求给出 `文件:行号`，复核阶段逐条回代码核实。协调者另行亲自复核了全部
载荷性事实（见 §1）。

## 2. M1：让 pyproject 与 README 说的话在陌生人机器上成真

「诚实优先」是本项目的第一价值观，而目前唯一一处**文档在撒谎且没有测试守着**的地方
就是打包元数据。先修它，因为后面每个里程碑都要在它之上验收。

- `openpyxl` 进 `dev` 与新增的 `excel` extra；`export.py` 的报错文案改成能照做的那条命令。
- `streamlit>=1.61,<2`：1.61.1 是唯一实测跑过的版本。**只承诺跑过的那一档**，不猜中间版本。
- 其余依赖补上界（`baostock` 的 `get_data()` 就因上游变动炸过一次，README §8 记着）。
- `version` → `0.5.0`，并新增 `tests/test_packaging.py` 把它与 README 首行标题对账
  ——版本号从此有单一事实来源，散落三处的老毛病由测试钉住。
- README 里的「1782 passed」在任何新克隆上都拿不到：`test_journal_store.py:454` 在没有
  `journal/trades.csv` 时 `pytest.skip`（全仓唯一条件跳过）。改成如实写法。
- `requires-python` **不动**：`>=3.12` 虽无代码依据，但 3.11 从没跑过一次测试，
  写进去就是拿没验证的承诺换用户。

## 3. M2：开源准备里「顺手且明显有价值」的部分

- 清掉 README 与 docs 里的个人绝对路径与系统用户名（陌生人看到的第一条可执行命令
  现在是 `cd /Users/watashi/...`）。
- `.gitignore` **只追加**两行（`.DS_Store`、`.streamlit/secrets.toml`）。既有 11 行一个字不动：
  `tests/test_user_data_split.py` 逐文件名钉着它们。
- `.streamlit/config.toml` 补两条**安全默认**：
  - `[browser] gatherUsageStats = false`——1.61.1 默认为 `true`，这是一台装着真实成交
    记录的机器，无条件关掉；
  - `[server] address = "127.0.0.1"`——把回环绑定从「文档纪律」变成默认值。
    代价必须如实写进 README：该配置按**当前工作目录**查找，从别的目录启动就不加载，
    所以 README 那段 `lsof` 实测证据要注明「那是 streamlit 出厂默认，本仓库根目录下
    已被 config.toml 覆盖」。安全默认 + 说清它的边界，比只留一句纪律强。
- LICENSE **不代选**：许可证是法律决定，还要署名。列进给用户的开放问题。

## 4. M3：两个「不报错但结论错」的现存缺陷

这两条都属于本项目一路在防的那一类，必须排在任何 UI 改造之前。

**4.1 扫描徽标撒谎**：`is_full` 改判「成功判定数 == 池子总数」，并在有失败时把失败数
摆到徽标文案与 tooltip 里（「失败的票没有结论，不等于没信号」）。
不新增 schema 字段——`failed` 早在 `_REQUIRED_KEYS` 里，零向后兼容风险。
也不设百分比阈值（凭空发明的常量与「不猜也不编」相抵）。

**4.2 读-改-写丢更新**：`store.append_trade` / `apply_edits` 与 `config_edit.write_local_universe`
用 `fcntl.flock` 把**整段**「读 → 改 → 写」包成临界区。只锁 `save` 不管用——丢的是
读到的那份旧快照。这不与 v0.2.0 设计里「拒绝锁文件」的决定冲突：那条拒绝的理由是
「陈旧锁无人回收」，而 `flock` 由内核在 fd 关闭/进程退出时自动释放。

**不做**：baostock 取数的退避重连。它改的是 0.5~2 小时长跑的网络路径，离线测不真，
风险大于当下收益；如实记进 README 已知局限。

## 5. M4：「使用说明」拆成 1 枢纽 + 3 子页

**分页**（字数相加正好 10931，不重不漏）：

| 页 | url_path | 装哪几节 | 字数 |
|---|---|---|--:|
| 使用说明（落地页，侧栏第一位不变） | `guide` | tasks + workflow + scan | 2231 |
| 读懂回测 | `guide-metrics` | metrics + strategies | 3563 |
| 自定义策略 | `guide-custom` | custom | 1883 |
| 边界与安全 | `guide-limits` | limits + userdata + safety + cli | 3254 |

`metrics` 与 `strategies` 必须同页（前者的归因表被后者引用）；`limits` 与 `safety`、
`userdata`、`cli` 同页（`limits` 末句「完整清单见 README」与安全提示是同一类"读一次"内容）。

**实现约束**：

- `guide.SECTIONS` **一个字不改、一节不重排**——它的键与顺序被 `test_guide.py` 逐字钉住，
  `Section.key` 还是全项目定位一节的手段。只在其上加一层 `GUIDE_PAGES` 索引
  （`section_keys` 拼错 = import 期 `KeyError`，响亮失败）。
- 侧栏新增一个「手册」组，紧跟主组之后——它是侧栏第一项的续页，挨着才读得通。
  组名不含「使用说明」四字，避免侧栏出现两处同名。
- 落地页底部一条紧凑目录（`st.page_link`）。**必须用 `page_link` 不用 `button`**：
  说明页不许出现 button（`test_dashboard_guide.py:205` 钉着）。
- 页对象登记表（`ui.bind_pages` / `ui.page_ref`）：`st.page_link` 收 Page 对象，
  按下标从组里取「第几个」日后一定错位，照抄 `ENTRY_PAGE` 的既有套路。
- **`/guide` 的坏书签**：拆分后落地页仍是 default，`/guide` 依旧 404。这是 Streamlit
  的路由行为，不是本次引入的。如实写进 README，不假装修好了。

**不做**：「说明页 · 全文」隐藏页（把刚拆掉的墙原样再砌一遍）；子页 `visibility="hidden"`
（进了子页侧栏没有高亮项，「我在哪」失灵）。

## 6. M5：任务控制台改成「每日流水线 + 研究工具」两区

现状三卡等宽并排的**唯一**理由是「纵向堆叠要滚很久」（`pages_console.py:204`），
语义为零——列的来源就是 `jobs.JOBS` 的字典序。而真实的闭环是：

    全市场扫描（发现） → 人工研究 → 加进信号池 → 每日信号（每天跟踪买卖）

其中「加进信号池」不是可运行的任务，是页面上的人工动作；「回测」根本不在这条链上。

**改法**：

- 页顶一行 `theme.flow(...)` 闭环图——窄屏自动折行，是「无论列怎么塌都还读得懂顺序」的兜底。
- 「每日流水线」区：`st.columns([1, .14, 1, .14, 1])`，三张卡片 + 两个箭头轨。
  中间那张是**人工步骤卡片**：灰色 pill、没有开始按钮、两个 `page_link` 通往信号池与今日信号。
- `st.divider()` 之后「研究工具（不在这条链上）」区：回测卡片整幅宽，指标网格恢复 `per_row=4`。
- 排班写成模块级常量 `_PIPELINE` / `_TOOLS`，渲染前**响亮**校验它们的并集 == `jobs.JOBS`
  ——将来加了第四个任务却忘了排版，宁可当场 `RuntimeError`，也不要那张卡片静默消失。
- 每张卡片一行「就绪状态」（上次扫描哪天扫了多少只 / 池子里几只 / 最新信号哪天），
  判断与文案下沉到 `src/quant/runner/steps.py` 纯函数，可单测。
- 软引导**只加文字不加闸门**（用户明确说了不做硬限制）。

**刻意不加 ①②③ 编号**：面板自己的说明页已经在用一套（`guide.py` 的 `_CLI`：
①扫描 ②每日信号 ③回测），README §2 是第三套（①回测 ②每日信号 ③扫描 ④面板）。
再引入一套流水线编号，用户会在两页之间看到互相矛盾的数字，而**没有任何测试会红**
——正是本项目最忌讳的静默不一致。顺序由箭头与位置表达，已经足够。
（顺带在 M6 把 `_CLI` 那三个装饰性编号去掉，三套减为两套，剩下的 README 入口编号
在 M7 注明「那是入口序，不是执行序」。）

## 7. M6：文案精简——砍重复与自述，不砍诚实结论

审计逐字统计后的结论很反直觉，如实记下来：**面板文案 17083 字里真正的问题不是
「解释理由」，而是「同一件事在同一屏说三到四遍」和「注定过期的副本」。**
所以本里程碑的收益预期也要如实：面板文案约 −700 字（−4%），README 约 −3%。
真正量级的改善来自 M4 拆页（一屏可见 10931 → 2231）与折叠，**靠折叠不靠删**。
提交信息里不许写「−15%」那种好看但没根据的数字。

**必须原样保留**：安全提示、诚实结论（跑输躺平 / 叠加层是纯代价 / 幸存者偏差 / 已知局限）、
「不构成投资建议」、会导致误操作的警告（一次全量扫描 0.5~2 小时）。

**要砍的**：控制台「同时只允许一个任务」三连、记账页同屏逐字重复、信号池页四处讲同一件事
且同一个数字连报两次、今日信号页页头与空态都写「17:30」、README §4 那张已经过期的
「说明页有八节」目录表（删表改指针）、用户可见文案里的 7 处内部版本号与设计文档编号。

## 8. M7：文档同步

README 现在同一份文件里自相矛盾（`:25` 写 1782、`:460` 的目录树写 1039），§4 的目录表
过期在项目最在意的地方（策略数量、诚实结论那节的名字）。一并同步，并把
「加一个策略只改这里一行」这句已被实测证伪的话改成实话（实测注册第 4 个策略后
`test_guide.py` 2 项红，还要改 `_STRATEGIES` 表与 `PARAM_HELP`）。

## 9. 明确不做（附理由）

- **多租户 / 任务队列 / 无状态前端**：推翻两条已归档决定却没有新证据，且前提
  （能不能这么卖、数据能不能商用）都还没答复。
- **journal 换 SQLite / migrations 骨架**：迁移基建服务的正是「改列」，而 `COLUMNS`
  自 v0.3.0 定型至今没动过。M3 的 flock 已解决真实存在的丢单问题。
- **i18n 框架 / 文案外置成 YAML**：外置后 `{占位符}` 拼错不再是 import 期 `KeyError`，
  而是页面上渲染出字面量 `{ma_total}`——看着像排版故障，没人会当数据错误上报。
  同时会毁掉 AST 扫描假话、frozen dataclass 结构断言、191 项 FACTS×README 逐字对账三条防线。
  且没有第二语种用户。
- **entry_points 插件发现 / overlays 注册表 / provider 工厂 / mypy --strict / 削减注释**：
  过度抽象比重复更有害。叠加顺序是语义不变量，注册表会把它降级成字典插入序这种隐式约定；
  那 56 处缺注解的参数真的是 `Any`；`src/` 34% 的注释密度里几乎每段长注释都对应一次实测事故。
- **CHANGELOG / CI / issue 模板 / 徽章**：`git tag` 无输出、`git remote` 为空、没有第二个
  贡献者。给一个从没发过版的仓库手写版本历史，是新造一份没有对账对象的文档。
  真要 push 公开远端那天再一起做。
- **往 CSV / 导出里加免责声明行**：会静默破坏面板读取与「导出可直接放回去」这条自救路径。

## 10. 验收

- 全量 `pytest` 绿，且新增测试覆盖：packaging 版本对账、扫描徽标带失败数、并发写日志不丢单、
  四页说明的分节完整性（并集 == SECTIONS 且不重不漏）、控制台排班校验。
- 真机面板（仅 127.0.0.1）逐页走一遍：四页说明、控制台两区与箭头、四档窗口宽度、
  page_link 跳转不打断正在跑的任务的轮询、零弃用告警。
- 用户数据 `sha256` 前后不变（`config/universe.local.yaml`、`journal/trades.csv`）；
  `output/scan/` 既有 CSV 一个不动。
