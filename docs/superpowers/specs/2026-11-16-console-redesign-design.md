# 任务控制台改版 + 全局主题（2026-11-16）

分支：`feat/console-redesign`（从 main 63490f1 拉出，工作区在 `.claude/worktrees/console-redesign`）。
这是一份**事后补的设计记录**：用户要求「尽可能加快开发的进度」，流程从简——先在临时目录搭可点的原型给用户看，
用户确认（「开工」）后直接移植并补测试，没有单独走"设计文档评审 → 实施计划"两轮。

## 0. 起因与用户决定

用户（2026-11-16）三条要求：

1. 优化「任务控制台」的布局、交互与视觉——「把你自己当成一个产品经理」「让第一次接触这个系统的人也能轻松上手」；
2. 全局优化整个系统的 UI，「看看有没有开源的、比较流行的 UI 设计组件可以使用」；
3. 尽可能加快开发的进度。

给用户看过的另外两条路，都没选：**保留左右两栏只做减法**（解决不了结果表被挤、两栏高度不齐）；
**向导式一步步点**（每天多点几下，也和"不强制顺序"的既有决定冲突——三步的频率本来就不同）。

## 1. 改之前的毛病（真机上看出来的）

同一份真实数据、1440×900：

| | 改之前 | 改之后 |
|---|--:|--:|
| 页面高度 | 2892 px（3.2 屏） | 1562 px（1.7 屏） |
| 常驻文字 | 4355 字 | 754 字 |

- 「开始 / 停止 / 重跑」三个按钮等权重，两个参数框摆在按钮前面像必填——第一次来的人不知道先点哪个；
- 任务做什么、什么时候跑、多久，只在标题旁的问号里；
- 扫描结果表挤在半幅宽的卡片里，说明页说"最该看"的「放量倍数」一列被挤出了可视区；
- 几个月前那次运行的日志与一条 100% 的进度条一直占着版面，两张卡片高度差出几屏，「研究工具」在第三屏；
- 实时日志框从头显示：30 行的尾部只看得见开头九行，最新一行（运行中是进度、没跑成是 traceback 的结论）要自己滚；
- 同一条流程在一屏里画了三遍（页顶的流程条、人工步骤那一行、卡片之间的箭头）。

## 2. 版式

每个任务一张**整幅宽**的卡片（原生 `st.container(border=True)`），自上而下就是流程的顺序：

```
页头
[首次引导]                       ← 只在从没跑过任何任务时出现
每日流水线
  ┌ 全市场扫描 ──────────── [试跑 300 只] [开始扫描] ┐
  ↓
  人工步骤：加进信号池 ……        去看扫描结果 · 去增删信号池
  ↓
  ┌ 信号跟踪 ──────────────────────── [开始跟踪] ┐
研究工具
  ┌ 回测 ──────────────────────────── [开始回测] ┐
```

卡片上常驻的只有四样：标题与状态 pill、一句「做什么 / 什么时候跑」（`guide.CONSOLE_LEAD`，时长与时刻取自 FACTS）、
「最新结果」是哪天的（扫描与信号跟踪沿用 `steps.scan_status / signal_status`；回测新增 `steps.backtest_status`：
最近一次是哪个策略、什么时候跑的、共几次——三张卡片都按**磁盘上的结果**说话，不按"面板起没起过它"说话）、一个主按钮。
其余按状态摊开或收起：

| 状态 | 卡片上摊着的 | 折叠区 |
|---|---|---|
| 没跑过 | — | 更多选项 |
| 运行中 | 进度条（或转圈）+ **停止** + 一行细节 + 日志尾部 | 完整日志、更多选项 |
| 成功 | 一行「上次运行：完成，……」 | 更多选项、运行日志、本次结果（**今天跑完的默认展开**，更早的收起） |
| 失败 / 已停止 | "停在哪儿"的进度条 + 细节 + 没保存结果的说明 + 日志尾部 | 完整日志、更多选项 |

几条刻意的决定：

- **停止按钮不占主按钮的位置**（它在进度条旁）。任务恰好跑完的那一刻，光标底下的按钮不许从「停止」换成「开始」——点下去就是又一趟十几分钟的扫描。
- **试跑是一个按钮**（`jobs.TRIAL_LIMIT = 300`）。说明页一直建议第一次先扫前 300 只，过去要自己把 300 敲进输入框。按钮上写着多少只、扫的就是多少只：输入框里另填的只数不顶掉它，基准交易日照样带上。
- **参数用折叠而不是"点了才渲染"**：控件一直在页面上，填过的值不会因为收起而丢。
- **填了的参数写在卡片明面上**（审查后补）：折叠区默认收起，填过的只数 / 日期不写出来就一个字都看不见，而主按钮照样按它跑——
  上午试跑时填的 30 只，下午点「开始扫描」以为是全量。所以主按钮下方多一行「『更多选项』里已填：……」（`view.params_summary`），
  全留空时不出现。这行字与重跑那句共用同一套写法：策略写显示名、勾选项不写 "= True"。
- **点击在"参数一到手"时就处理**（审查后改）：初稿是记下点击、等整张卡片渲染完再起任务——中间任何一处抛错这次点击就丢了，
  失败提示也落在卡片最底下。现在先用两个空容器把"按钮下方的提示"与"运行面板"的位置占好，折叠区里的参数控件一渲染出来就处理点击，
  启动失败的那句话落在按钮正下方。
- **重跑挪进「更多选项」**，要沿用什么参数直接写在按钮上方（v0.5.0 是悬停提示），悬停里不放第二遍。
- **日志尾部自动滚到底**：定高的 `st.container(height=…, autoscroll=True)` 里放随内容长的 `st.code`。
- **首次引导只在适用时出现**：控制台上的三个任务都没跑过时（`process.has_ever_run(runs, names)`）一条 `.qd-callout` + 去「使用说明」的链接；
  状态文件坏了也算"跑过"。只问这一页上的任务——首页那个收盘数据任务跑过不算。
- **"今天跑完"的口径**：`finished_at` 是面板**第一次发现**任务结束的时刻（`process._finish`），不是进程退出的那一秒。
  昨晚起了任务就关掉页面、今天早上再打开，它记的是今天早上——那份结果会被摊开。这正合用：你确实还没看过它。
- **互斥提示只说给别的卡片听**：正在跑的那张自己摊着进度，不对自己再说一遍。「关掉浏览器也不会中断」从页顶常驻挪到运行中那一行。

**保留不动的既有决定**：两区（每日流水线 / 研究工具）、不加 ①②③ 编号（顺序由位置表达）、人工步骤只占一行、
帮助圆点不用 popover、全局互斥与状态文件损坏时的 fail-safe（一个按钮都不给）、所有"如实说、不猜"的文案。

**随之拿掉的**：页顶的流程条与"三步频率不一样"那句（`CONSOLE_FLOW` / `CONSOLE_FLOW_NOTE` / `CONSOLE_TOOLS_NOTE` 三个常量删除——
版式本身已是流程图，频率写进了每张卡片自己那一句；说明页「三个任务分别是什么」一节的闭环图不受影响）。
`theme.rail()` 从横箭头改成向下的箭头，那条只为换箭头而存在的媒体查询一并删掉。

## 3. 全局主题

`.streamlit/config.toml` 的 `[theme]` 从 4 项扩到二十来项，把原生控件拉到与 `.qd-*` 同一套语言：三套字体栈与
`app/theme.py` 一致、`baseRadius` / `buttonRadius` 0.25rem、边框与表格线用发丝线、链接琥珀金、
红 / 绿 / 橙黄 / 蓝灰这几组内置色全部改指色板（`st.info` 用中性灰，不引入色板外的蓝）、行内代码不再是绿字、
`[theme.sidebar]` 比页面深一档（新增 `palette.SIDEBAR`）。**一行 CSS 都没有为原生控件写**——仍然只走官方配置面。
`tests/test_theme.py` 逐项比对：配置里的每个色值都必须在色板里找得到。

按钮统一：图标一律走 `icon=`（与侧栏同一套 Material 图标），不再把 ▶ ⏹ ↻ ＋ ↶ 拼在文字前面（控制台、三页的控制条、
首页、记账、信号池）。表格每行的「＋ 加入」「＋ 记一笔」「− 移除」是表格列的文字，原样保留。

### 开源组件库：调研结论是不引入

后台代理在临时环境（Streamlit 1.61.1 + Python 3.14）里装过、跑过，**没有在浏览器里看渲染效果**：

| 库 | 版本 · 日期 | 机制 | 结论 |
|---|---|---|---|
| streamlit-antd-components | 0.3.2 · 2024-01 | iframe | 两年没更新；测试里只读 |
| streamlit-option-menu | 0.4.0 · 2024-10 | iframe | 停更；原生 `st.segmented_control` 已覆盖 |
| streamlit-shadcn-ui | 1.5.0 · 2026-11 | 组件 v2（shadow root） | 很活跃，但固定灰色调与字体（README 明说不跟随 Streamlit 的样子），7 段动画，测试里驱动不了 |
| streamlit-aggrid | 1.2.1 · 2025-12 | iframe | 测试里只读 |
| streamlit-elements | 0.1.0 · 2022-04 | iframe | 在 1.61.1 上回调不触发，已不可用 |
| streamlit-extras | 1.6.0 · 2026-05 | Python 封装 + CSS | 自己已把 `stylable_container` 标为弃用，改推 `st.container(key=…)`；`steps` 运行时拉 Google Fonts |

共性：任何自定义组件在 `AppTest` 里都是点不动、设不了值的未知元素，而面板有 560 多项测试靠它驱动。
本次用到的全部是原生组件：带边框的容器、紧凑折叠区、主 / 次 / 文字三级按钮、定高自动滚动容器。

## 4. 测试

先写测试、看它失败、再移植实现；钉着旧版式的测试改写成新版式的要求。工作区内全量通过
（另有 1 项因工作区没有使用者的记账文件而跳过，与本次无关）。

**独立审查**（子代理只读审查，结论"修完再合并"，无安全或互斥缺陷）指出并已修的：折叠区里的参数悄悄生效（见上）、
点击处理得太晚（见上）、五处"改坏了测试也不红"的空洞（别的卡片的重跑、没有进度条时的停止按钮、结束后的停止按钮、
失败时摊着的日志尾部——原测试被折叠区里的全文满足而空转、"没有保存任何结果"那句的接线）。顺带修的小问题：
回测卡片的"还没跑过"说错了话、扫描 meta 损坏时多说一句"还没跑过"、"没有保存任何结果"那句三张卡片共用扫描的措辞
（现按任务各说各的）、`argv` 不是列表 / 指标文件不是字典时整张卡片渲染不出来、扫描那一句没说第一次要久得多、
"会在日志里说明"没说日志在哪、主题项的名字没有防错（现逐项对 streamlit 自己的选项表）。
没有采纳的两条：提示框的字色与底色由 streamlit 从那几个基色派生（不是色板里的值）——字色派生得更亮是为了可读，不动；
警告框用了琥珀——它出厂就是黄色，改指琥珀只是让它落在色板里，在配置里注明了这是"琥珀只给可操作元素"的唯一例外。

**变异自查 35 条全部抓住**（故意改坏一处、确认对应测试变红、还原）：卡片塞回并排的列、日志尾部不滚到底 / 失去定高、
试跑不带只数 / 被输入框顶掉、正在跑的卡片重复互斥提示、旧结果默认摊开、成功后仍摊日志、开始不是主按钮、
首次引导常驻 / 把首页的任务也算上、两张卡片顺序颠倒、停止按钮常驻 / 结束后还在 / 没有进度条时没了、参数露在折叠区外、
填了的参数不写出来 / 只写在折叠区里 / 策略写成内部键、点击等读完日志才处理、失败提示落到卡片底、别的卡片的重跑不受互斥约束、
失败时不摊日志尾部、"没保存结果"那句不出现 / 不分任务、回测不按磁盘结果说话、状态读不出来时补一句"还没跑过"、
结果文件形状不对就崩、argv 不是列表就崩、按钮文字拼回字符图标、主题混进色板外的颜色 / 主题项写错名字、
卡片那一句不带实测时长 / 不提第一次要久得多、说明里又只说"在日志里"。

一条 AppTest 的坑（实测）：**带 `icon=` 的 `st.expander` 会被 AppTest 当成 `st.status`**（它靠"有没有图标"区分两者），
读 `.state` 直接抛 `Unknown Status state`，并混进 `at.status`。所以折叠区一律不带图标。

## 5. 真机验收（2026-11-16）

把工作区的 `app/` 与 `config.toml` 同步到两个临时目录起服务（使用者自己那份面板仍在 main 上跑，不受影响）：

- 真实数据（符号链接到本机 `output/` 等）：空闲 / 成功态；「本次结果」展开后结果表整幅宽，「放量倍数」列可见；1024 宽下主按钮与试跑同排、人工步骤的两个链接折行而不是被截断。
- 隔离的演示目录：首次引导；伪造的"扫描运行到 60%"——进度、停止、日志尾部自动滚到 `[1800/3010]`；点「停止」真的结束了那个进程，卡片转「已停止」、其余按钮解禁；伪造的失败态——traceback 摊在卡片上。
- 隔离目录里点「开始回测」起了一个**真任务**：运行中（转圈、停止按钮、其余卡片禁用并点名）→ 约 10 秒后成功 → 「本次结果」自动展开出指标卡。
- 其余页面：三页控制条、首页、记账、信号池的按钮都是文字 + 图标；提示框是中性灰；侧栏深一档。

## 6. 这轮没做的

- 其他页面的**结构**调整（比如「信号」「回测报告」页顶部的控制条仍是"开始 + 常驻的停止"两个按钮）——等使用者看过控制台的效果再定。
- IBM Plex Mono 仍从 Google Fonts 加载（离线时回落 Menlo）。要彻底去掉这条外部依赖，可以用 `theme.fontFaces` 自托管字体文件，需要往仓库里加字体文件，未做。
- 主按钮上是白字配琥珀底（Streamlit 自动选的前景色），对比度偏低；配置面没有"主按钮文字色"这一项，不写内部 class 的 CSS 就改不了。
