# 持仓占比：占比条与环形图二选一（2026-11-18，当天第二轮）

分支：`feat/weights-forms`（从 main c811f1c 拉出，工作区在 `.claude/worktrees/weights-forms`）。
事后补的设计记录。本文与测试里的例子一律用虚构的票和数（仓库是公开的，用户的交易记录不进仓库）。

## 0. 起因

上一轮把「持仓占比」那张图铺满了整行。用户接着问（原话）：

> "持仓占比"使用饼图来呈现会不会更直观？

我把三种画法用同一组数摆在一起给他看（聊天里的一张对比图，可以在 3 只与 8 只之间切换）：
现在的条形图、环形图、满格 100% 的占比条，并建议用占比条。他的回复（原话）：

> 能否做多种形态？可以自行选择是以"占比条"还是"环形图"的形式呈现数据

## 1. 三种画法各自的毛病

| 画法 | 好在哪 | 毛病 |
|---|---|---|
| 原先的条形图（条长按**最大的那只**比） | 谁多谁少一眼看得出 | 最长的一根永远顶满整行：占 45% 的那只看着像 100%，读不出"不到一半"。它根本不是一张占比图 |
| 环形图 | "整体的几分之几"一眼就是；券商 App 都这么画 | 持仓一多小块细得看不清；差不多大的两块分不出谁大；要给每块上不同的颜色 |
| 占比条（条的满格是**全部持仓**） | 既看得出各占整体多少，持仓再多也只是多几行，不用分颜色 | 没有"一个圆"那种一眼的整体感 |

原先那张图是我上上轮定的，用户问之前我没意识到它的条长其实不表示占比。

## 2. 做法

**标题一行**：左边小标题「持仓占比（按市值）」+ 帮助圆点（两种画法各是什么、环形图什么时候把后面的并成「其他」、
「按成本」是什么意思），右端一个横排单选「占比条 / 环形图」。一个靠右的横向容器——标题的字短，
占剩下的地方，切换是它自己的宽度（操作一律靠右）。

**占比条（默认）**：一行一只——名称、条、百分比、市值、标记。五栏是一张 CSS 网格，每行的五个格子都是
网格的直接子元素，所以名称成一列、两列数字右对齐成两列，条占剩下的宽度。条宽就是占比本身，
后面一道发丝灰的底表示全部持仓；占比再小也留 2px。

**环形图**：圆环（SVG，`minicharts.donut`，以 data URI 放进 `<img>`——`st.html` 会删内联 svg）居中，
右边一行一块的清单：色块、名称、百分比、市值、标记；放不下时清单折到圆环下面。圆环里不写字
（img 里的 SVG 用不了页面的字体）。从十二点方向起顺时针按市值由大到小排，块与块之间留一道缝、不描边。

- **最多单独画五只**，排在后面的并成「其他 N 只」（`analytics.fold_weights`）。**正好多出一只时不并**：
  画一块「其他 1 只」不如画它自己，块数一样、名字还在。占比条不并，有几只列几只。
- **颜色**：同一个琥珀由亮到暗的五档（`palette.PRIMARY_RAMP`，第一档就是主色），按大小排队——
  不是类别色；红绿在这个面板里专门表示涨跌，不拿来分块。并出来的「其他」与排到第六的那一只用灰。
  五档是算出来的（见 §3）。五只这个上限就是色板的档数，两处有测试钉着相等。

**「按成本」单独一格**：没有本地行情的持仓按成本顶上（漏掉它，其余几只的占比就都虚高了）。初稿把
「（按成本）」跟在金额后面写成一串，真机上看到带标记的行把金额那一栏撑宽了，别的行的金额离百分比老远、
个位也对不齐——拆成金额后面单独的一小格；没有标记的行照出一个空格子，网格才不错位。

**为什么是 HTML 而不是 plotly**：上一轮那张 plotly 条形图的毛病都出在"图里的字"上——条外标注画到图外被裁、
为了不裁留的固定边距在窄栏里把条挤没、纵轴被猜成数值轴。这一块没有需要交互的东西（数都写在明面上），
用页面自己的 HTML：字是页面的字，窄了自己让。`charts.position_weights_chart` 连同它的测试删除，
`_bar_margins` / `_text_px` 只剩「来源对比」在用。

**选了哪种记多久**：`st.radio(..., persist_state="session")`（Streamlit 1.61 的参数）——这次打开面板期间
一直记着，去别的页转一圈回来还是它；刷新页面回到默认。Streamlit 默认是控件一不渲染就把值丢掉
（首页趋势图的 60 / 120 / 全部、K 线的周期就是这样，那几处这一轮没动）。
没有做"下次打开还记得"：那要多存一个本地设置文件，用户没提。

## 3. 琥珀的五档是怎么定的

用 dataviz 技能自带的校验脚本按"有序色阶"校验，对的是页面底色：

| 档 | 色值 | OKLCH 明度 |
|---|---|---|
| 0（主色） | `#C8963E` | 0.705 |
| 1 | `#AF812F` | 0.635 |
| 2 | `#976D20` | 0.565 |
| 3 | `#7F5A10` | 0.495 |
| 4 | `#684700` | 0.425 |

判据三条，测试里用纯 Python 钉着同样的三条：色相不变（相差不到 5°）；相邻两档明度差不小于 0.06
（实际 0.07）；最暗一档对页面底色的对比度不低于 2:1（实际 2.18:1）。第一次试的是明度降到 0.35，
最暗一档只有 1.61:1、融进底色——所以只有五档：再往下排一档看不见，挤得更密分不开。

## 4. 验收

**真机**（Chrome；一份副本是用户账本的拷贝，另一份换着账本看状态）：

- 1440 宽：三只持仓的两种画法；8 只（环形图是前五只 + 「其他 3 只」，其中带「按成本」）；正好 6 只
  （第六只单独画成灰色）；只有 1 只（占比条顶满、环形图是不带豁口的整圈）；占比极小的（98.5% / 1.2% / 0.3%，
  小的两只在两种画法里都还看得见）；没有名称的持仓。
- 1024 × 768、侧边栏展开：标题与切换在同一行；占比条的条那一栏宽 236px；环形图的圆环 160px 与清单 265px
  并排居中、没有折行；页面不出横向滚动条。上面还有盈亏曲线时，曲线在上、持仓占比在下。
- 选了环形图 → 从侧边栏去「记账」→ 回来：还是环形图。
- 真实的 `journal/trades.csv` 没动。

**测试**：全量 2759 过（上一轮 2734），1 跳过。新增的钉：琥珀五档的三条判据；环形图的弧（顺序、弧长、缝、
整圈、极小的块）；并「其他」的规则（正好多出一只不并、并出来的块带不带「按成本」）；两种画法的 HTML
（条宽就是占比、五个格子一行、转义、色块与色板对得上、超出色板用灰）；页面接线（默认占比条、标题在左切换在右、
切到环形图、八只与六只、无市价的标记、曲线在上占比在下、没有持仓时整块不出、选择记到会话里）。

**变异自查**：在工作区的拷贝里逐处改坏 47 处，46 处被测试抓到。活下来的一处是「并出来的"其他"也拿琥珀色」——
最多画五只、色板正好五档时，"其他"总落在色板之外，那句判断平时碰不到。把颜色档的分配抽成了
`journal_ui.weight_steps`（纯函数）并单独钉住，那一处与它的另一种改法重跑都被抓到。

**这一轮没有做独立审查**（上一轮做了，挑出五处）：改动小得多，而且上一轮栽过的几类——窄窗口下的每一种状态、
圆点提示框出不出视口、文案在别的情形下是不是真话——这次都照着逐项过了一遍；过的时候自己抓到一处：
圆点里原先写「最多单独画五只」，可正好六只时是六块都画，已改成「不超过六只时一只一块；再多就只单独画前五只」。
