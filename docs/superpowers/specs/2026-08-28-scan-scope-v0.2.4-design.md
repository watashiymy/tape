# 扫描范围记录与产物隔离 v0.2.4 设计文档

- 日期：2026-08-28
- 状态：待实施（用户已批准"一并修复"）
- 前置：v0.2.3 清单落盘 + 就绪闸门修复

## 1. 要解决的问题（已用真实数据坐实）

`run_market_scan.py` 的产物文件名只有日期（`output/scan/<date>.csv`），**不记录本次扫了多少只**。
于是 `--limit N` 的试跑会**静默覆盖**同一天的全量扫描结果。

本地实际状态（2026-08-28 查证）：

| 文件 | 信号数 | 真实来源 |
|---|---|---|
| 2026-08-21.csv | 2 | `--limit 50` 试跑 |
| 2026-08-24.csv | 3 | **原为全量扫描 86 条，被试跑覆盖** |
| 2026-08-25.csv | 110 | 真全量，完好 |
| 2026-08-26.csv | 2 | 试跑 |
| 2026-08-27.csv | 0 | **原为全量，被 `--limit 3` 覆盖** |

5 份里只有 1 份是真全量。两份全量结果已永久丢失（`output/` 不在版本控制内）。

**危害**：面板显示"08-27 无信号"时，用户无法分辨这是全市场真没机会、还是一次 3 只票冒烟测试的残渣。
这与本项目一路在防的"不报错但结论错"同源——数据看着正常，结论是错的。

## 2. 方案（两条一起做，缺一不可）

### 2.1 试跑写独立文件名，永不覆盖全量结果

```
全量：output/scan/2026-08-27.csv
试跑：output/scan/2026-08-27_limit30.csv
```

规则：`--limit` 给定时，文件名追加 `_limit{N}`。这样：
- 全量结果**在文件系统层面**就不可能被试跑覆盖（不是靠约定，是靠路径）
- 同一天不同规模的试跑互不覆盖（`_limit30` 与 `_limit300` 各一份）
- 相同规模重跑仍覆盖自己（符合预期：那是同一件事重做）

### 2.2 每份扫描记录自己的范围（元信息伴生文件）

CSV 是给人看和给 pandas 读的，**不往里塞元信息列**（会污染每一行、且信号数为 0 时无处安放）。
改用伴生 JSON：

```
output/scan/2026-08-27.meta.json
{
  "date": "2026-08-27",
  "scanned": 3010,          // 实际扫描只数
  "pool_total": 3013,       // 扫描池总数（--limit 前）
  "limit": null,            // 试跑时为 N
  "is_full": true,          // scanned == pool_total
  "signals": 86,
  "skipped": {"stale": 2, "insufficient_history": 0, "is_st": 0,
              "low_liquidity": 534, "no_signal": 2388},
  "failed": 0,
  "elapsed_s": 1258,
  "started_at": "2026-08-27T18:32:11"
}
```

**为什么单独一个文件而不是塞进 CSV**：信号数为 0 时 CSV 只有表头，没有任何地方能承载"我扫了 3010 只"这个事实——
而"扫了 3010 只得 0 条信号"与"扫了 3 只得 0 条信号"正是本次要区分的核心。

原子写（tmp + `os.replace`），与 `cache.py` / `symbols.py` 一致。

### 2.3 面板显示范围

「今日信号」页的扫描区块与「任务控制台」的扫描结果，标题旁显示范围徽标：

- `全量 3010 只` — `is_full` 为真
- `试跑 30 只` — 有 limit（用与"运行中"不同的中性灰，不抢眼但看得见）
- `范围未知` — 没有 meta 文件（v0.2.4 之前的老产物）

**老产物兼容**：读不到 meta 时不报错、不猜，显示"范围未知"并在 tooltip 说明
"该文件产生于记录范围之前，无法判断是全量还是试跑"。诚实优于编造。

## 3. 分层与可测性

```
src/quant/signal/scan_meta.py    # ScanMeta 数据类 + save/load + scan_csv_path(date, limit)
scripts/run_market_scan.py        # 调用：算路径、收尾写 meta
app/ui.py / app/pages_signals.py  # 读 meta、渲染徽标
```

`scan_csv_path(date, limit)` 是纯函数（日期 + limit → 路径），单测覆盖：
无 limit、有 limit、limit 为 0（应视为无效，由既有参数校验拦）。

**面板选文件的顺序**：同一天若既有全量又有试跑，**优先显示全量**（用户关心的是真结果）；
全量不存在才回退到试跑，并明确标注是试跑。这个优先级要有测试钉住。

## 4. 测试

- `scan_csv_path`：三种输入的路径正确性
- `ScanMeta` 往返：字段保真、原子写、损坏文件响亮报错（沿用项目既有约定）
- **覆盖隔离回归测试**（本次的核心）：先造全量产物 → 跑 `--limit 3` → 断言
  ① 全量 CSV **逐字节未变** ② 新产物落在 `_limit3` 路径 ③ 两份 meta 各自正确
  先对未修代码跑确认失败（现在会覆盖）
- 面板优先级：只有全量 / 只有试跑 / 两者都有 / 都没有 / 有 CSV 无 meta（老产物）
- AppTest：五种状态下「今日信号」页均无异常

## 5. 不做

- 不迁移已有的老产物（无法反推它们的范围，猜测比"范围未知"更糟）
- 不做产物清理/归档策略（YAGNI）
- 不改 CSV 的列结构（下游 pandas 读取行为不变）
