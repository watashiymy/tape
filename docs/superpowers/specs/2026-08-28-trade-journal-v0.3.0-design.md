# 交易日志 v0.3.0 设计文档

- 日期：2026-08-28
- 状态：待实施（用户已批准范围：日志 + 持仓 + 已实现盈亏）
- 前置：v0.2.4（1138 项离线 + 3 项联网测试全绿）

## 1. 目标

记录**真实发生的每一笔交易**，支持筛选与导出，并据此算出当前持仓与已实现盈亏。

**为什么这个功能对本项目特别有价值**：系统此前只能回答"机械规则在历史上表现如何"，
回答不了"**你本人的决策质量如何**"。有了日志 + 盈亏，才能把两者摆在一起比——
这也是本项目自始至终那个问题（技术分析对散户到底有没有用）唯一诚实的检验方式。

## 2. 数据模型

### 2.1 存储：`journal/trades.csv`，**纳入 git 版本控制**

- 位置不放 `data/`：那里混着 `cache/` 与 `symbols.parquet`（都已 gitignore），语义混淆。
  新建 `journal/` 目录，语义明确——"你的数据，要留住"。
- **纳入版本控制**：交易记录不可再生，git 历史等于免费的审计轨迹与撤销能力
  （误删一行可以 `git checkout` 找回）。这是本地仓库，不外传。
- 格式选 CSV 而非 SQLite/parquet：可直接用 Excel 打开、可 git diff、可手工修，
  且量级极小（一年几十到几百行）。不新增存储依赖。
- **写入必须原子**（tmp + `os.replace`，沿用 cache.py 既有模式）；
  `dtype={"symbol": str}` 全程强制——本项目已两次踩过前导零被吃掉的坑（`000333` → `333`）。

### 2.2 行类型（`kind`）

一份诚实的盈亏必须容纳现实里会改变持仓与损益的四件事：

| kind | 含义 | 必填 | 对持仓 | 对已实现盈亏 |
|---|---|---|---|---|
| `buy` | 买入 | 数量、成交价 | +股数，建仓位 | — |
| `sell` | 卖出 | 数量、成交价 | −股数，按 FIFO 消耗批次 | 产生已实现盈亏 |
| `adjust` | 送股/转增/拆股导致的股数变化 | 数量（可正可负） | ±股数，**成本总额不变**（摊薄单位成本） | — |
| `dividend` | 现金分红到账 | 金额 | 不变 | 计入已实现收益 |

**为什么必须有 `adjust`**：送股不是交易，但你的股数确实变了。没有它，
持仓数会与券商对不上，后续每一笔卖出的 FIFO 配对全错——而且**不会报错**，
只会给出一个看着正常的错数字。这正是本项目一路在防的失败模式。

**为什么必须有 `dividend`**：A 股蓝筹年化股息 2–4%，长期持有下这部分收益不小。
静默忽略分红的盈亏是系统性低估。

UI 上 `buy`/`sell` 是主路径，另两种收在"其他记录"里，不干扰日常录入。

### 2.3 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `trade_id` | str | 稳定主键（时间戳+序号），编辑/删除靠它定位，不靠行号 |
| `date` | date | 成交日期 |
| `time` | str \| null | 成交时刻（可空——多数人事后补记只记得日期） |
| `symbol` | str | 6 位代码 |
| `name` | str | 名称，从 `data/symbols.parquet` 自动带出（v0.2.3 的产物，离线可用） |
| `kind` | str | 见上表 |
| `shares` | float | 股数（`adjust` 可为负；`dividend` 留空） |
| `price` | float | 成交价（`dividend` 留空） |
| `amount` | float | 现金流金额。买卖=股数×价格；`dividend`=到账金额 |
| `fee` | float | 佣金+过户费，默认按 settings.yaml 的成本模型**自动算**，可改成券商实际值 |
| `tax` | float | 印花税（仅卖出），同上自动算可改 |
| `source` | str | **信号来源**：`ma_cross` / `donchian` / `discretionary`(自主决策) / `other` |
| `stop_plan` | float \| null | 入场时**计划**的止损价 |
| `reason` | str | 理由（用户要求的核心字段） |
| `note` | str | 备注 |

**两个我主动加的字段，理由**：

- **`source`（信号来源）**——这是整个功能里学习价值最高的一个字段。
  记满一段时间后可以分组统计："照系统信号做的交易" vs "自己拍脑袋做的交易"，
  哪一类更赚钱。**这直接回答了"这套系统到底帮没帮上我"**，
  而这个问题没有这个字段就永远回答不了。
- **`stop_plan`（计划止损价）**——入场时写下你打算在哪里认输。
  事后可自查"我有没有守住自己的计划"。不守纪律是散户亏损的头号原因，
  而这是唯一能把它变成可测量数据的办法。

## 3. 校验：用系统自己的数据帮用户抓错

这是本系统相对通用记账工具的**独有优势**——它手里有行情。

| 校验 | 规则 | 严重度 |
|---|---|---|
| 代码存在性 | 必须是 6 位数字；能在 `symbols.parquet` 里查到则自动带出名称 | 查不到 → 警告（可能是新股/退市股，不阻断） |
| 成交价合理性 | 与该日缓存中的 `[low, high]` 比对，超出区间 → **警告** | 警告（不阻断：可能是缓存没这只票，或盘后交易） |
| 日期 | 不得晚于今天；非交易日 → 警告 | 未来日期 → 阻断；非交易日 → 警告 |
| 数量 | 买入须为 100 整数倍 | 买入非整手 → 警告（可转债/科创板规则不同，不阻断） |
| 卖超持仓 | 卖出股数 > 该标的当前持仓 | **警告并在持仓页持续标红**（不阻断：可能是漏记了买入，事后补即可） |

**原则：阻断只用于逻辑上不可能的事（未来日期）**。其余一律"警告 + 记下来"——
这是日志，首要职责是**如实记录发生了什么**，而不是替用户否定现实。
但错误必须显眼、持续可见，不能记完就沉没。

价格区间校验是本功能最实用的一条：录入时打错一位（7.15 记成 71.5）在通用记账软件里
无人可查，这里能当场发现。

## 4. 持仓与盈亏（`src/quant/journal/pnl.py`，纯函数、重点单测）

### 4.1 FIFO 批次配对

买入建批次（含买入费用进成本），卖出按**先进先出**消耗批次：

```
已实现盈亏 = 卖出净得（股数×价格 − 佣金 − 印花税）
           − 被消耗批次的成本（含当初的买入费用，按比例分摊）
```

`adjust` 按比例调整**现存批次的股数**，**总成本不变**（送股摊薄单位成本，这是正确口径）。
`dividend` 直接累加进已实现收益，不动批次。

### 4.2 输出

- **当前持仓**：代码/名称/股数/持仓成本/单位成本/最新价（读本地缓存）/浮动盈亏/
  **数据一致性标记**（卖超、股数为负等）
- **已实现盈亏**：逐笔平仓明细（配对关系可追溯：卖出对应哪些买入批次）+ 汇总
- **汇总指标**：总已实现盈亏、胜率、盈亏比、平均持仓天数——
  **刻意与回测报告用同一套指标口径**，这样才能把"你的实际交易"和"策略回测"并排比较
- **按 `source` 分组的对比**：信号交易 vs 自主决策，各自的胜率与盈亏比

### 4.3 明确的已知局限（写进文档与页面）

- 浮动盈亏依赖本地行情缓存；没缓存的标的显示"—"而非 0
- 未处理配股、要约收购等复杂公司行为——遇到时用 `adjust` + `note` 手工记
- 不做税务口径（境内个人股票交易暂免所得税，但不做任何税务建议）

## 5. 界面（新增「交易日志」页，侧栏第三位）

1. **录入区**：表单（日期/代码/方向/数量/价格/理由/来源/止损计划）。
   代码输入后自动带出名称与该日价格区间；费用自动按成本模型算好可改。
   **从信号一键记账**：「今日信号」与扫描表的每行加"记一笔"按钮，
   预填代码/名称/日期/方向/来源=对应策略 —— 闭环：发现信号 → 决策 → 留痕。
2. **日志表**：可筛选（日期区间 / 标的多选 / 方向 / 来源 / 理由关键词），可编辑与删除。
3. **持仓区**：当前持仓 + 一致性告警。
4. **盈亏区**：已实现盈亏汇总、逐笔明细、按来源分组对比。
5. **导出**：CSV 与 Excel 两个按钮，**导出的是当前筛选后的结果**（所见即所得）。
   - CSV 必须用 **`utf-8-sig`**（带 BOM）——否则 Excel 打开中文全是乱码，这是最常见的踩坑
   - Excel 需新增依赖 `openpyxl`（纯 Python、体积小、pandas 官方推荐引擎）

## 6. 分层

```
journal/trades.csv                  # 用户数据（git 跟踪）
src/quant/journal/__init__.py
src/quant/journal/store.py          # 读写、原子落盘、dtype 保证、trade_id 生成
src/quant/journal/schema.py         # 字段定义、行类型、校验规则（纯函数）
src/quant/journal/pnl.py            # FIFO 配对、持仓、盈亏、分组统计（纯函数，重点单测）
src/quant/journal/export.py         # CSV(utf-8-sig) / Excel 导出
app/pages_journal.py                # 页面
```

面板只做渲染与编排，全部计算在 `src/` 且纯函数可测——沿用本项目既定分层。

## 7. 测试

- **FIFO 引擎**（核心）：单买单卖、多批次部分卖出、卖超持仓、adjust 摊薄、
  dividend 累加、买卖交错、同日多笔顺序；**每个盈亏数字手算对照**，
  含费用分摊的小数精度（金额一律 `round(x, 2)`）
- **校验规则**：正反用例，尤其价格越界与卖超的**警告而非阻断**语义
- **存储**：往返保真、前导零、原子写、并发写、损坏文件响亮报错
- **导出**：CSV 的 `utf-8-sig` BOM 存在性（用字节断言，不是"看着没乱码"）、
  Excel 可被 openpyxl 读回且中文正确、导出内容 == 当前筛选结果
- **AppTest**：空日志 / 有数据 / 有一致性告警 三态渲染无异常
- 回归：1138 项既有测试全绿

## 8. 不做

- 不做多账户 / 多币种
- 不做自动对接券商（无公开 API，且涉及资金安全）
- 不做税务计算
- 不做配股等复杂公司行为的自动处理（用 adjust + note 手记）
