# quant_demo — A 股日线技术信号系统 v0.2.0

一个**纯学习用**的 A 股日线研究流水线：拉数据 → 算指标 → 策略出目标仓位 → 历史回测（含 A 股交易规则与成本）→ 绩效报告 → 收盘后的每日信号提示与全市场扫描（v0.1.1 新增）。这三个任务既能在命令行跑，也能在面板上点按钮跑（v0.2.0 新增的任务控制台）。目标是把这条链路跑通且**跑对**，不是产出能赚钱的策略；内置的双均线、唐奇安通道突破只是用来验证流水线的样品。

> **免责声明**：本项目仅用于个人学习与技术验证，所有输出（回测结果、每日信号、图表）**不构成任何投资建议**。回测收益是历史数据上的模拟结果，包含多处已知近似（见文末「已知近似与局限」），与真实交易结果必然存在差距。据此实盘操作的一切后果自负。

## 2. 四个入口，按这个顺序用

### ① 回测：`scripts/run_backtest.py`

```bash
.venv/bin/python scripts/run_backtest.py                      # 跑 settings.yaml 里配置的全部策略
.venv/bin/python scripts/run_backtest.py --strategy donchian  # 只跑一个
.venv/bin/python scripts/run_backtest.py --refresh            # 丢弃缓存，全量重拉行情
.venv/bin/python scripts/run_backtest.py --config 别的.yaml
```

首次运行会联网拉 10 只标的约 10 年日线（每标的一个 parquet 落到 `data/cache/`），之后只增量补最近的部分，很快。输出目录 `output/<策略名>_<YYYYmmdd_HHMMSS>/`：

| 文件 | 内容 |
|------|------|
| `metrics.json` | 总收益/年化/最大回撤/夏普/交易次数/胜率/盈亏比/平均持仓天数。**最后写入**，当完成标记用：目录里没有它 = 回测中途被打断的半截目录，面板会自动忽略，直接删掉即可 |
| `config_snapshot.json` | 本次回测用的完整配置留档（股票池/起点/本金/成本/策略参数），改配置后对比历史结果不用猜当时用的什么参数 |
| `equity.csv` | 日频净值曲线 |
| `trades.csv` | 每笔成交（含成交价、股数、佣金、印花税、平仓盈亏、持仓自然日） |
| `skipped.csv` | 被约束挡掉的订单（涨停顺延/跌停顺延/T+1/资金不足一手），**排查"信号有但没成交"先看这个** |
| `report.html` | 净值曲线（策略 vs 沪深300 vs 等权买入持有）+ 回撤曲线 |
| `kline_<代码>.html` | 单标的 K 线 + ▲买入 ▼卖出 标注，调策略主要看它 |

**样品策略实测结果**（2016-01-04 ~ 2026-08-24，10 只主板蓝筹，本金 500 万，含全部成本；年化为日历年化）：

| | 总收益 | 年化 | 最大回撤 | 夏普(rf=0) | 交易次数 |
|---|--:|--:|--:|--:|--:|
| ma_cross（双均线） | 117.4% | 7.6% | -15.2% | 0.97 | 243 |
| donchian（唐奇安突破） | 49.3% | 3.8% | -12.4% | 0.57 | 436 |
| 等权买入持有 | 412.5% | 16.6% | -40.4% | — | — |
| 沪深300（价格指数，不含分红） | 31.5% | 2.6% | -45.6% | — | — |

两个样品策略都**大幅跑输"买入后躺平"**，但最大回撤只有其约 1/3。对长牛蓝筹池（反复震荡把趋势跟随洗出场）这是诚实且典型的结果，不是 bug；池子本身有幸存者偏差，见文末「已知近似与局限」。

### ② 每日信号：`scripts/run_daily_signal.py`（收盘后跑）

```bash
.venv/bin/python scripts/run_daily_signal.py
```

增量更新行情 → 各策略对各标的算最新一日目标仓位 → 与前一交易日比对，输出**新增**的 BUY/SELL 清单（终端表格 + `output/signals/<交易日>.csv`）。

- **必须收盘后跑**：baostock 的当日日线约 **17:30 之后**才更新，早跑会因"全部标的数据未更新"退出（退出码 1）。实践中 18:30 之后再跑最稳。
- 非交易日跑会明确提示"今天不是交易日，以下是最近交易日 X 的信号"，不会假装是今天的新信号。
- 只有部分标的数据落后（多半是停牌）时，会打印出来并跳过它们，其余照常扫描。
- 「今日无新信号」是绝大多数日子的正常结果。

### ③ 全市场扫描：`scripts/run_market_scan.py`（v0.1.1，收盘后跑）

```bash
.venv/bin/python scripts/run_market_scan.py                     # 全量：沪深主板非 ST（实测扫描池 3010 只，见 §4）
.venv/bin/python scripts/run_market_scan.py --limit 300         # 只扫前 300 只（试跑/验证环境用）
.venv/bin/python scripts/run_market_scan.py --date 2026-08-21   # 以指定交易日为基准（补扫历史某天）
```

固定池之外的"雷达"：扫描全部**沪深主板非 ST**股票，只报当日**新触发的 BUY**（全市场的 SELL 对未持仓者无意义），按当日成交额降序输出。终端展示前 `scan.top_n` 条 + 各类跳过计数汇总，全量落到 `output/scan/<交易日>.csv`。

- **定位闭环（重要）**：扫描只是发现工具，本身不下结论。流程是——扫描发现 → 人工研究 → 看中的加进 `settings.yaml` 的 `universe` 固定池 → 此后的持有/**卖出**信号由入口 ② `run_daily_signal.py` 每日跟踪。不加进 `universe` 的票没有人管卖出。
- **预估耗时**（2026-08-24 实测拆解；逐票串行取数是 baostock 单连接的天花板）：耗时 = **固定开销约 2–4 分钟**（拉全市场清单约 11500 行逐行分页，每次扫描一次，实测 133 秒）+ **每票约 0.5–2 秒**（逐票增量取数，网络往返主导：热缓存 30 只中位 0.51 秒/只、均值 0.88 秒/只，冷缓存抽样 0.9–2.5 秒/只——缓存省的是不重拉 400 自然日窗口的历史，省不掉每票一次联网往返，所以热缓存不比冷缓存明显快）。全量约 3200 只**单次预估 0.5–2 小时**（小样本实测外推，未做全量实跑），请当成挂机任务。中断随时 Ctrl-C，重跑不会重拉已缓存的历史。日常建议 `--limit` 试跑确认环境正常再上全量，嫌慢等将来接入全市场快照源（接口已留插槽）。
- **每票判定链**（依次过滤，汇总里分开计数）：数据未更新（停牌/退市中）→ 历史不足 130 根 K 线（最慢指标 MA60 需暖机）→ 当前为 ST → 20 日均成交额低于 `scan.min_avg_amount`（流动性差的票信号无意义且 0.1% 滑点假设失效）→ 才进策略判定。
- `--date` 给非交易日、或当日 17:30 前数据未更新时，明确提示后退出（与入口 ② 同一口径）；单票取数失败自动重试一次，仍失败记入失败清单继续扫，不会因一只票废掉全场。

## 3. 面板任务控制台（v0.2.0 新增）

三个入口脚本都能在页面上启动、停止、重跑：侧边栏「任务控制台」页有完整的参数控件、进度、日志与结果；既有三页顶部另有一条精简控制条（状态 + 开始/停止）。

> **安全提示**：面板会在**本机**执行脚本，等于一个本地命令执行入口。启动时**必须**加 `--server.address 127.0.0.1` 显式绑定回环地址，**切勿**用 `--server.address 0.0.0.0` 或任何内网地址。

```bash
.venv/bin/streamlit run app/dashboard.py --server.address 127.0.0.1
```

**别指望默认值是安全的**——这里原先写着"`streamlit run` 默认只监听本机，保持默认即可"，v0.2.1 实跑证明那是假话：

```console
$ streamlit run app/dashboard.py --server.port 8531
$ lsof -nP -iTCP:8531 -sTCP:LISTEN
Python  79141 watashi  6u  IPv6 ...  TCP *:8531 (LISTEN)          ← 所有网卡

$ streamlit run app/dashboard.py --server.port 8532 --server.address 127.0.0.1
Python  80013 watashi  6u  IPv4 ...  TCP 127.0.0.1:8532 (LISTEN)  ← 只有本机
```

不带地址参数时监听的是 `*:8501`（**所有网卡**，启动日志里那两行 `Network URL` / `External URL` 就是证据）。同一网段的人打开就能点你的「开始」按钮，也就等于能在你机器上执行命令。绑定回环之后那两行 URL 不再打印。面板另外刻意不暴露 `--config`（避免任意路径读取），任务一律用 `config/settings.yaml`。

### 三个任务怎么点

| 卡片 | 参数控件 | 等价命令 |
|---|---|---|
| 全市场扫描 | `--limit`（留空 = 全量）、`--date`（留空 = 最近交易日） | `run_market_scan.py [--limit N] [--date YYYY-MM-DD]` |
| 每日信号 | 无 | `run_daily_signal.py` |
| 回测 | 策略下拉（留空 = 全部策略）、`--refresh` 勾选 | `run_backtest.py [--strategy X] [--refresh]` |

- `▶ 开始` 按控件里的参数起一个新任务；`⏹ 停止` 只对正在跑的那个任务可用；`↻ 重跑` 沿用上次的参数（上次的命令行会重新过一遍参数白名单，改坏了的状态文件会被拒绝）。
- 参数控件只在控制台页。既有三页顶部的精简控制条按**默认参数**运行——全市场扫描的默认就是**全量**（0.5–2 小时），要限量或指定日期请去控制台。
- 面板只接受白名单参数（日期必须是 `YYYY-MM-DD` 的真实日期、`--limit` 是 1–10000 的正整数、策略只能从注册表里选），命令一律以参数列表方式执行，不经过 shell。

### 进度怎么读

- 扫描的日志里有 `[1250/3010]` 这样的进度行 → 进度条 + "1250/3010（41%），已用 12分38秒，预计剩余 ~19分钟，信号 15 条，失败 0 只"。ETA 是**线性外推**，冷/热缓存混合时偏差不小，只当参考。
- 每日信号与回测没有可数的总量 → 不画进度条，只有转圈 + 阶段文字 + 已用时长（宁可不显示，不显示假数字）。
- **ETA 只在任务还在跑时给**。任务停掉/崩掉之后进度条留在停下的位置（那是"停在哪儿"的存档，据此判断要不要补跑），但文案换成 完成 / 失败 / 已停止，不再报剩余时间。
- 状态徽标：⚪ 空闲 / 🔵 运行中 / ✅ 成功 / ❌ 失败（带退出码）/ ⏹ 已停止。退出码 1 = 脚本自己退出（最常见的是"数据未更新到今天，17:30 后再试"），2 = 参数错，-15 = 被停止，-9 = 被强杀。
- 卡片下方是日志尾部 30 行，`完整日志` 展开是全文；日志文件留在 `output/runs/logs/<run_id>.log`，**不自动清理**（留着事后排查，`output/` 在 .gitignore 里）。
- 跑完直接在卡片里出结果：扫描 / 每日信号 → 当次 CSV 表格；回测 → **每个策略**一组指标卡。

### 停止 = 温和退出（SIGTERM）

点「停止」发的是 **SIGTERM 给整个进程组**，不是 `kill -9`：脚本有机会走完手上这一只票、让缓存原子落盘。10 秒内没退才升级到 SIGKILL。实测 `--limit 3` 的扫描收到 SIGTERM 后 0.06 秒退干净（退出码 -15，`pgrep -f run_market_scan.py` 为空），卡片转为「⏹ 已停止」，其余任务的「开始」立刻解禁。中断过的扫描重跑不会重拉已缓存的历史。

### 关掉浏览器不会停掉任务

任务是**分离进程**（自成会话与进程组），语义与 `nohup ... &` 一致：

- 关掉浏览器标签、关掉整个浏览器 → 任务继续跑；
- 连 Streamlit 服务一起 Ctrl-C 停掉 → 任务照样继续跑；
- 重开面板会从 `output/runs/<任务名>.json` 认领仍在跑的任务，进度接着显示；
- 想真的停掉它，只有点「停止」（或自己 `kill` 状态文件里的那个 pid）。

### 同时只允许一个任务

baostock 是**单会话**：两个任务并发会互踢下线，还更慢。所以只要有任务在跑，控制台三张卡片、以及其余页面控制条上的「开始」**全部禁用**，并提示是谁在跑。这条由 runner 层强制（按钮禁用只是第一道），不靠自觉。

### 命令行入口全部保留

三个脚本的参数与产物一个字没改，面板只是替你敲命令，**两种方式等价**，可以混用。已有的 `nohup ... &` / cron 用法不受影响。两点差别要知道：

- 命令行起的任务不写 `output/runs/`，面板看不到它的进度（产物照样出现在页面上）；
- 因此**它也不参与上面那条互斥**——命令行已经在跑扫描时，别再去面板点「开始」，否则两个 baostock 会话互踢。

### 各任务耗时（实测，不是估计）

说明页里的耗时都出自下面这几次真实运行，**改这里就要同步改说明页**（`tests/test_guide.py` 会逐条对账）：

| 任务 | 实测 | 出处 |
|---|---|---|

## 5. 配置：`config/settings.yaml`

```yaml
universe: ["600519", "600036", "601318", "600900", "000333",
           "600030", "600276", "601088", "600887", "601899"]
benchmark: "000300"
backtest:
  start: "2016-01-01"
  capital: 5000000
costs:
  commission_rate: 0.00025
  commission_min: 5.0
  stamp_tax:
    - {until: "2023-08-27", rate: 0.001}
    - {from: "2023-08-28", rate: 0.0005}
  slippage: 0.001
strategies:
  ma_cross: {fast: 20, slow: 60}
  donchian: {entry_n: 20, exit_n: 10, amount_n: 20, amount_ratio: 1.5}
scan:
  history_days: 400        # 每票拉取历史窗口（自然日），约 270 根 K 线 > MA60 暖机两倍
  min_avg_amount: 50000000 # 20 日均成交额门槛（元）
  top_n: 20                # 终端打印条数（CSV 始终存全量）
```

| 段 | 含义与注意 |
|----|-----------|
| `universe` | 股票池，6 位数字代码（交易所前缀由 provider 自动补）。**只放沪深主板**：引擎按 10% 涨跌停建模，创业板/科创板 20% 会算错。默认 10 只跨行业高流动性白马 |
| `benchmark` | 基准指数代码，默认沪深 300 |
| `backtest.start` | 回测与取数起点。改早了要重新联网补历史（缓存会自动回补头部缺口） |
| `backtest.capital` | 虚拟本金。每标的固定额度 = `capital / len(universe)`，**不随权益浮动**。500 万不是随便定的：茅台一手十余万，本金太小会静默买不进 |
| `costs.commission_rate` / `commission_min` | 佣金万 2.5、单笔最低 5 元，买卖双边收 |
| `costs.stamp_tax` | 仅卖出收，按**成交日**分段：2023-08-28 之前 0.1%，之后 0.05%。写成 `{until: ...}` / `{from: ...}` 的闭区间列表，日期含当日；找不到覆盖当日的区间会直接报错（不静默用旧税率） |
| `costs.slippage` | 滑点 0.1%，买入价 ×1.001、卖出价 ×0.999，顺带涵盖过户费等杂费 |
| `strategies` | 键名必须是注册表里的策略名（`ma_cross` / `donchian`，见 `src/quant/strategy/__init__.py`），值是构造参数。**这一段删空或键名拼错**，每日信号与全市场扫描脚本会直接退出报错而不是天天空跑 |
| `scan` | 全市场扫描（入口 ③）参数。`min_avg_amount` 是最值得按需调的：门槛越低扫出的票越多、但流动性假设越不可信 |

策略规则：

- **ma_cross**：MA(fast) 在 MA(slow) 之上 → 目标仓位 1，否则 0（状态式，等价于上穿买/下穿卖）。
- **donchian**：收盘价 > 前 `entry_n` 日（**不含当日**）最高收盘 **且** 当日成交额 > `amount_ratio` × 前 `amount_n` 日平均成交额 → 入场；收盘价 < 前 `exit_n` 日（不含当日）最低收盘 → 出场；其余持有不变。窗口若含当日，"收盘 > N 日最高"永不成立，会得到全 0 的死信号——测试里有专门的回归用例守着。

**分层原则**：策略层只认行情 DataFrame，不知道数据从哪来；引擎只认目标仓位序列，不知道策略逻辑；UI 只做渲染，不含业务逻辑——面板要起任务，判断与解析也全在 `src/quant/runner/`（面板本身写不了单元测试，把逻辑挤出 UI 层是把缺陷挡在外面的关键手段）。

**四条绝不能改的语义**（改了回测结论全部作废，来龙去脉见设计文档 §4）：

1. **信号用后复权价 `adj_*`，撮合/涨跌停判定/成本计算用原始价**。前复权会随每次除权改写历史（引入未来信息）；而整手、最低佣金、涨跌停只有在真实价位上才有意义。
2. **T 日收盘算信号 → T+1 日开盘成交**（引擎内是 `positions.shift(1)`）。杜绝"当日收盘信号当日成交"的未来函数。
3. **每标的固定额度 = 初始本金 / N，不随权益浮动**，各标的账本互不挪用；赚到的钱留作闲置现金，不放大下一轮仓位。
4. **印花税仅卖出且按成交日分段**（2023-08-28 前 0.1%，之后 0.05%）。用现行税率回溯 2016-2023 会把那段历史的卖出成本低估一半。

引擎每日循环：应用除权因子（调持仓股数 + 把昨收折算到今日价格体系）→ 比对目标仓位生成订单 → 约束检查（停牌跳过 / 买单遇涨停顺延 / 卖单遇跌停顺延 / T+1 当日买入不可卖 / 不足一手放弃）→ 原始开盘价 ± 滑点撮合、计佣金与印花税 → 原始收盘价估值记净值（停牌标的沿用最近可得收盘价）。被挡掉的订单全部写进 `skipped.csv`。

## 7. 已知近似与局限（重要，看结果前先看这里）

**交易规则层面**

- **涨跌停判定是近似**：用「原始开盘价 ≥ 昨收 × 1.095（或 ≤ 0.905）」或「当日 high == low 的一字板」判定。真实盘口的排队、封板中途打开、部分成交都无法复现。
- **ST 期间的 5% 涨跌幅未建模**：数据层检测到 ST 只写告警，引擎仍按 10% 处理。默认股票池是非 ST 白马，影响有限；换池子时要留意。
- **只支持主板 10% 涨跌幅**，创业板/科创板 20% 的分支没写。
- **除权除息按"分红再投资"假设**：除权日持仓股数 × (今日因子/昨日因子)，现金不变。结果是**持仓股数会变成非整数**，与真实账户"现金分红入账、股数不变"有出入。
- **成交假设过于友好**：以次日开盘价 ± 0.1% 滑点**全额**成交，不考虑冲击成本、流动性不足、部分成交。
- **停牌日整行被过滤**，不进指标计算也不交易，等价于信号顺延到复牌后。

**绩效与基准层面**

- **夏普比率用 rf = 0**（简化口径）。中国无风险利率约 1.5–2%，真实夏普应比这里低一些。
- **CAGR 已改为日历年化**（首末日期跨度 ÷ 365.25，即 CAGR 的标准定义），不再按 bar 数 ÷ 252 折算——旧口径会把收益塞进更短的"年"里，系统性高估约 3.8%（相对）。夏普年化仍沿用业界惯例 √252：A 股一年实际只有约 243 个交易日，√(252/243) ≈ 1.018，夏普因此约被高估 2%。
- **沪深 300 是价格指数，不含成分股分红**，相对策略净值有每年约 2–3% 的天然劣势——**不要拿它当主要参照**。报告里的「等权买入持有」基准用后复权价（分红再投资口径），与策略同权，才是主要对照组。
- **现金不计利息**，闲置资金收益为 0，长期会低估机会成本对比。
- **胜率/盈亏比/平均持仓天数只统计已平仓交易**，回测末尾仍持仓的那一笔不计入；持仓天数是自然日不是交易日。

**样本与方法层面**

- **股票池有幸存者偏差**：这 10 只是**今天**回头挑出来的高流动性白马，2016 年时并不知道它们会走成这样。回测收益天然偏乐观，退市股、掉队股一只都没有。
- **策略参数没有调优也没做样本外检验**（无参数扫描、无前进分析）。现有 `metrics.json` 只是"这条流水线能跑出数"的证据，不是策略有效性的证据。
- **数据未与交易所对账**：baostock 是免费源，复权因子、停牌标记、成交额都按它给的用。

**全市场扫描层面（v0.1.1）**

- **逐票串行取数是 baostock 单连接的天花板**：单次全量预估 0.5–2 小时（固定开销约 2–4 分钟 + 每票约 0.5–2 秒，见入口 ③ 的实测拆解；与设计文档 §3.4 的 30–60 分钟量级预估一致，但其"已缓存的票秒过"不成立——缓存省不掉每票一次增量联网往返，实测热缓存无法加速扫描本身）。接口分层已留好快路径插槽（如 akshare 全市场快照），需要时替换"当日 bar 来源"即可，扫描逻辑不用动。
- **排序用当日成交额而非策略强度分**——简单、普适、可解释；"哪个信号更强"的策略特定排序留给 top-K 组合（v0.2）。
- **扫描发现的票没有回测背书**：回测仍只跑固定 `universe`；扫描池按"当天"的在市清单取，对当日扫描本身无幸存者偏差，但某只票扫出来 ≠ 策略在它身上历史有效。加池观察前别赋予信号超出"技术条件今天满足了"的含义。
- **不扫创业板/科创板/北交所/ST**：与引擎 ±10% 涨跌停假设保持一致（这些板 20%/5% 的分支没建模），将来做 top-K 回测可无缝衔接。

**工程层面**

- akshare 备选 provider 在设计文档里列了，**v0.1 没有实现**——baostock 挂了就得现写。
- **面板任务控制台有两个已知的互斥漏洞**（设计文档 §8.1，暂不修）：① 面板重启过、且任务日志超过 10 分钟没有新输出时，会按"PID 多半被复用"处理而放开互斥；② 起任务的互斥是"先查后起"，毫秒级同时点击（多标签页）理论上能起两个任务。单人本机使用概率极低，修法的复杂度与收益不成比例。命令行起的任务同样不参与互斥（见 §3）。
- 无实盘/模拟盘对接、无盘中与分钟级、无定时任务与推送（面板只能手动点，不含调度）、无组合级风控与止损（都在 v0.2+ 的计划里）。

## 8. 开发备忘（三个月后的自己大概率会再踩）

- **baostock 的 `rs.get_data()` 用不得**：0.9.3 版翻页分支调用了 pandas 早已删除的 `DataFrame.append`，首页满 2000 行就抛 `AttributeError`，10 年日线（约 2579 行）必然触发。`BaostockProvider` 里已经改成 `next()` / `get_row_data()` 逐行迭代，别改回去；`tests/test_baostock_integration.py` 有联网回归用例守着（`pytest -m network`）。
- **数据缓存的增量判据用的是"已请求过的起始日"**（`data/cache/<代码>.meta.json` 里的 `covered_start`），不是"缓存里最早那根 K 线的日期"——后者在 start 落在非交易日（比如默认的 2016-01-01 元旦）时恒为真，会让增量分支变成死代码、每次全量重拉。
- 增量取数会**回拉 5 天重叠**：盘中跑过一次的话，当天那根未收盘的 K 线会进缓存，靠重叠重拉 + `keep="last"` 覆盖修正。缓存疑似脏了就 `--refresh`。
- 提交前跑全量测试：`.venv/bin/python -m pytest`。做变异测试时务必加 `PYTHONDONTWRITEBYTECODE=1` 并 `-B`，且先 `rm -rf` 相关 `__pycache__`——等长度改写源码会命中陈旧 `.pyc`，结果完全不可信。
