# quant_demo — A 股日线技术信号系统 v0.5.0

一个**纯学习用**的 A 股日线研究流水线：拉数据 → 算指标 → 策略出目标仓位 → 历史回测（含 A 股交易规则与成本）→ 绩效报告 → 收盘后的每日信号提示与全市场扫描（v0.1.1 新增）。这三个任务既能在命令行跑，也能在面板上点按钮跑（v0.2.0 新增的任务控制台）。目标是把这条链路跑通且**跑对**，不是产出能赚钱的策略；内置的双均线交叉、唐奇安通道突破、时序动量（v0.4.0 新增）只是用来验证流水线的样品。v0.4.0 还给全部策略加了两个可开关的**叠加层**（200 日趋势过滤 + ATR 追踪止损，见 §5），默认开启——它们对回测数字的真实影响（相当大，且方向可能出乎意料）在下面 ① 的实测表里如实列着。

> **免责声明**：本项目仅用于个人学习与技术验证，所有输出（回测结果、每日信号、图表）**不构成任何投资建议**。回测收益是历史数据上的模拟结果，包含多处已知近似（见文末「已知近似与局限」），与真实交易结果必然存在差距。据此实盘操作的一切后果自负。

## 1. 安装

需要 Python ≥ 3.12（当前开发环境 3.14.7 + pandas 3.0.5）。

```bash
git clone <仓库地址> quant_demo && cd quant_demo
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"
```

依赖：pandas / pyarrow / baostock / PyYAML / plotly / streamlit；`[dev]` 额外装 pytest 与 openpyxl。openpyxl 只有「记账」页导出 Excel 才用得上，单独装是 `pip install -e ".[excel]"`（CSV 导出不需要它）。数据源 baostock **免费、无需 token、无需注册**。

依赖的版本下界一律是**实测跑过的那一档**（例如 `streamlit>=1.61`：面板用到的 `st.navigation` / `st.Page` / `st.logo` / `ButtonColumn` 都晚于 1.30，写 1.30 就是让人装出一个"装得上、跑起来必崩"的组合）；上界一律给到下一个大版本。

跑测试确认环境正常：

```bash
.venv/bin/python -m pytest
# 期望：全部通过；末行还会带 1 skipped 与 3 deselected（原因见下）
.venv/bin/python -m pytest -m network   # 想跑联网集成测试时用这个
```

那 3 项 deselected 是需要联网的 baostock 集成测试；**1 项 skipped 是正常的**——它检查「本机那份交易日志还读得动」，而新克隆本来就没有日志（`journal/trades.csv` 是用户数据、不进版本控制）。本机记过账之后这一项就不再跳过。

这里刻意**不写具体条数**：每加一条用例它就过期一次，而它没有任何对账对象（不像 §2 那些实测结论有 `tests/test_guide.py` 逐字盯着）。`tests/test_packaging.py` 会拦住任何想把数字写回来的改动。

**所有命令都要在项目根目录执行**——脚本里的 `data/cache`、`output/`、`config/settings.yaml` 都是相对路径。

## 2. 四个入口，按这个顺序用

### ① 回测：`scripts/run_backtest.py`

```bash
.venv/bin/python scripts/run_backtest.py                      # 跑 settings.yaml 里配置的全部策略
.venv/bin/python scripts/run_backtest.py --strategy tsmom     # 只跑一个（ma_cross / donchian / tsmom）
.venv/bin/python scripts/run_backtest.py --refresh            # 丢弃缓存，全量重拉行情
.venv/bin/python scripts/run_backtest.py --config 别的.yaml
```

首次运行会联网拉 10 只标的约 10 年日线（每标的一个 parquet 落到 `data/cache/`），之后只增量补最近的部分，很快。输出目录 `output/<策略名>_<YYYYmmdd_HHMMSS>/`：

| 文件 | 内容 |
|------|------|
| `metrics.json` | 总收益/年化/最大回撤/夏普/交易次数/胜率/盈亏比/平均持仓天数。**最后写入**，当完成标记用：目录里没有它 = 回测中途被打断的半截目录，面板会自动忽略，直接删掉即可 |
| `config_snapshot.json` | 本次回测用的完整配置留档（股票池/起点/本金/成本/策略参数），改配置后对比历史结果不用猜当时用的什么参数 |
| `equity.csv` | 日频净值曲线 |
| `trades.csv` | 每笔成交（含成交价、股数、佣金、印花税、平仓盈亏、持仓自然日） |
| `skipped.csv` | 被约束挡掉的订单（涨停顺延/跌停顺延/T+1/资金不足一手），**排查"信号有但没成交"先看这个** |
| `report.html` | 净值曲线（策略 vs 沪深300 vs 等权买入持有）+ 回撤曲线。面板「回测报告」页内嵌的就是它 |
| `kline_<代码>.html` | 单标的 K 线 + ▲买入 ▼卖出 标注。**v0.5.0 起默认不生成**，加 `--klines` 才有——见下面「产物体积」 |

**产物体积（v0.5.0 瘦身）**：一次 10 只标的的回测，产物从 **53 MB 降到 5.2 MB**（实测）。省下的是十个 `kline_<代码>.html`——每个 4.8 MB，因为各自内嵌了一整份 plotly.js。而面板的「个股K线」页**从来不读**它们：标的清单读 `config_snapshot.json` 的 `universe`，图是拿本地缓存的行情**现场重画**的。也就是说那 48 MB 只服务「把单个 HTML 拷出去离线看」这一个用途，需要时加 `--klines` 即可。

积攒下来的差别很大：本机曾因此攒到 3.0 GB。想给已有的老产物瘦身（**只删 K 线 HTML，回测结果一件不动**）：

```bash
find output -name "kline_*.html" -delete
```

跑之前可以先用 `find output -name "kline_*.html" | wc -l` 看看会删掉几个。删掉之后老回测在面板上照常可看——标的清单会从 `config_snapshot.json` 取。

**样品策略实测结果**——两套口径并列，都来自真实重跑，数字与说明页由 `tests/test_guide.py` 逐字对账，不许拍脑袋改。

**v0.1 基线（无叠加层）**：2016-01-04 ~ 2026-08-24，10 只主板蓝筹，本金 500 万，含全部成本；年化为日历年化。历史结论留档，永不重算：

| | 总收益 | 年化 | 最大回撤 | 夏普(rf=0) | 交易次数 |
|---|--:|--:|--:|--:|--:|
| ma_cross（双均线） | 117.4% | 7.6% | -15.2% | 0.97 | 243 |
| donchian（唐奇安突破） | 49.3% | 3.8% | -12.4% | 0.57 | 436 |
| 等权买入持有 | 412.5% | 16.6% | -40.4% | — | — |
| 沪深300（价格指数，不含分红） | 31.5% | 2.6% | -45.6% | — | — |

两个样品策略都**大幅跑输"买入后躺平"**，但最大回撤只有其约 1/3。对长牛蓝筹池（反复震荡把趋势跟随洗出场）这是诚实且典型的结果，不是 bug；池子本身有幸存者偏差，见文末「已知近似与局限」。

**v0.4 当前默认（三策略 + 双叠加层开）**：同池同本金，区间终点更新到 2026-08-31，其余口径同上：

| | 总收益 | 年化 | 最大回撤 | 夏普(rf=0) | 交易次数 |
|---|--:|--:|--:|--:|--:|
| ma_cross（双均线） | 8.6% | 0.8% | -15.2% | 0.15 | 368 |
| donchian（唐奇安突破） | 16.6% | 1.5% | -14.1% | 0.26 | 412 |
| tsmom（时序动量） | 6.5% | 0.6% | -17.4% | 0.14 | 457 |
| 等权买入持有 | 414.4% | 16.6% | -40.4% | — | — |
| 沪深300（价格指数，不含分红） | 33.3% | 2.7% | -45.6% | — | — |

没看错：**叠加层把三个策略的总收益全部打到了个位数到两成之间**。为了搞清代价出在哪，另做了同池同区间的归因重跑（每格一次完整回测，总收益）：

| 总收益 | 无叠加层 | 只开趋势过滤 | 只开止损 | 双开（当前默认） |
|---|--:|--:|--:|--:|
| ma_cross | 118.5% | 78.9% | 25.8% | 8.6% |
| donchian | 49.0% | 16.7% | 49.5% | 16.6% |
| tsmom | 87.0% | 74.1% | 1.0% | 6.5% |

（「无叠加层」列即基线口径在新终点的复现：118.5% / 49.0% vs 基线的 117.4% / 49.3%，差额就是多出的一周行情——这同时是流水线自身的回归对照。）三个如实结论：

- **趋势过滤的保费**：长牛蓝筹每次回踩 200 日线都被强制离场、修复后高位接回，佣金、印花税、滑点照付一整轮（ma_cross 交易次数 245 → 366 笔）。
- **ATR 止损的保费更贵，且对慢信号是灾难**：止损全部在下跌里触发（定义如此），而"止损后保持空仓、直到基础信号先归零再转正"这条防回补封锁，对 250 日动量这种慢信号意味着**卖在暴跌底部后长期缺席**——tsmom 单开止损时每只票都有一次 490~866 个自然日的空窗（最长 866 个自然日，贵州茅台），87.0% 直接打到 1.0%。donchian 自带的 10 日新低出场比 3×ATR 更早触发，所以止损对它几乎无感（49.0% → 49.5%）。
- **保费没换来多少保额**：ma_cross 回撤 -15.2% 原地不动，donchian 从 -12.4% 反而恶化到 -14.1%（强制出场再接回，接回点位更差），只有 tsmom 真的从 -26.6% 降到 -17.4%。这一样**不是 bug**：止损与趋势过滤的价值样本是持续单边下行（2018 年那种），在十年长牛池里权重太小，保险费白交了。默认仍保持开启——本项目优先"回撤可控的规则化"而不是收益最大化；想复现无叠加口径，把 `settings.yaml` 里两个 `enabled` 改成 `false` 即可。

### ② 每日信号：`scripts/run_daily_signal.py`（收盘后跑）

```bash
.venv/bin/python scripts/run_daily_signal.py
```

增量更新行情 → 各策略对各标的算最新一日目标仓位 → 与前一交易日比对，输出**新增**的 BUY/SELL 清单（终端表格 + `output/signals/<交易日>.csv`）。

- **必须收盘后跑**：baostock 的当日日线约 **17:30 之后**才更新，早跑会因"全部标的数据未更新"退出（退出码 1）。实践中 18:30 之后再跑最稳。
- 非交易日跑会明确提示"今天不是交易日，以下是最近交易日 X 的信号"，不会假装是今天的新信号。
- 只有部分标的数据落后（多半是停牌）时，会打印出来并跳过它们，其余照常扫描。
- 「今日无新信号」是绝大多数日子的正常结果。
- v0.4.0 起 SELL 可能来自**叠加层**而不只是基础策略：ATR 追踪止损触发、或收盘跌破 200 日线，都会让目标仓位归 0，与基础策略自己的离场在信号清单里长得一样（信号只比对目标仓位的日间变化）。想知道是谁触发的，看当天 K 线与 200 日线、前高的相对位置。

### ③ 全市场扫描：`scripts/run_market_scan.py`（v0.1.1，收盘后跑）

```bash
.venv/bin/python scripts/run_market_scan.py                     # 全量：沪深主板非 ST（实测扫描池 3010 只，见 §4）
.venv/bin/python scripts/run_market_scan.py --limit 300         # 只扫前 300 只（试跑/验证环境用）
.venv/bin/python scripts/run_market_scan.py --date 2026-08-21   # 以指定交易日为基准（补扫历史某天）
```

固定池之外的"雷达"：扫描全部**沪深主板非 ST**股票，只报当日**新触发的 BUY**（全市场的 SELL 对未持仓者无意义），按当日成交额降序输出。终端展示前 `scan.top_n` 条 + 各类跳过计数汇总，全量落到 `output/scan/<交易日>.csv`（`--limit N` 的试跑落到 `output/scan/<交易日>_limit{N}.csv`，见下"产物隔离"）。

- **定位闭环（重要）**：扫描只是发现工具，本身不下结论。流程是——扫描发现 → 人工研究 → 看中的加进 `settings.yaml` 的 `universe` 固定池 → 此后的持有/**卖出**信号由入口 ② `run_daily_signal.py` 每日跟踪。不加进 `universe` 的票没有人管卖出。
- **趋势过滤开启时（v0.4.0 默认）扫出的 BUY 会明显变少**：价格在自己 200 日线下方的票一律不出 BUY，下行行情里可能连续多日全场零信号。这是特性不是故障——趋势过滤的本意就是"下行环境不做多"；上市不足 200 根 K 线的新股同样因均线未成形而扫不出来。
- **预估耗时**（2026-08-24 实测拆解；逐票串行取数是 baostock 单连接的天花板）：耗时 = **固定开销约 2–4 分钟**（拉全市场清单约 11500 行逐行分页，实测 133 秒；自 v0.2.3 起清单落盘到 `data/symbols.parquet`，**7 天内的直接复用**，所以这笔固定开销实际每周只付一次，`--refresh-symbols` 可强制重拉）+ **每票约 0.5–2 秒**（逐票增量取数，网络往返主导：热缓存 30 只中位 0.51 秒/只、均值 0.88 秒/只，冷缓存抽样 0.9–2.5 秒/只——缓存省的是不重拉 400 自然日窗口的历史，省不掉每票一次联网往返，所以热缓存不比冷缓存明显快）。全量约 3200 只**单次预估 0.5–2 小时**（小样本实测外推，未做全量实跑），请当成挂机任务。中断随时 Ctrl-C，重跑不会重拉已缓存的历史。日常建议 `--limit` 试跑确认环境正常再上全量，嫌慢等将来接入全市场快照源（接口已留插槽）。
- **每票判定链**（依次过滤，汇总里分开计数）：数据未更新（停牌/退市中）→ 历史不足 130 根 K 线（最慢指标 MA60 需暖机）→ 当前为 ST → 20 日均成交额低于 `scan.min_avg_amount`（流动性差的票信号无意义且 0.1% 滑点假设失效）→ 才进策略判定。
- **两道就绪闸门**（v0.2.4，与清单来源**解耦**——`data/symbols.parquet` 命中与否都拦得住）：① **交易日校验**：`--date` 给了周末/节假日，查一次交易日历后当场退出，不会让人等两小时才知道日期填错；② **数据就绪校验**：扫过的标的**全部**没更新到基准日（典型是 17:30 前跑），判为"数据未就绪"而非"今日无新信号"，非零退出且**不写 CSV**——那份空 CSV 会出现在面板「今日信号」页，与一次正常的无信号扫描逐字难分。部分标的落后（多半停牌）不算未就绪，照常扫描落盘。
  - v0.2.3 到 v0.2.4 之间这道闸门曾被绕过：当时它的唯一实现是"拉全市场清单拿到空表就抛错"，而清单落盘复用后那个调用根本不发生，于是周六也能"扫描成功"。教训：**闸门不能挂在某条数据路径的副作用上**。
- **产物隔离与范围记录**（v0.2.4）：`--limit N` 的试跑写到 `<交易日>_limit{N}.csv`，全量结果在**文件系统层面**就不可能被一次冒烟测试覆盖（不靠"记得别在有全量结果的那天试跑"这种约定）。每份产物还带一个伴生的 `<同名>.meta.json`，记下这一趟的 `scanned` / `pool_total` / `limit` / 跳过明细 / 耗时；面板据此在扫描区块标题旁显示 `全量 3010 只` / `试跑 30 只` 徽标。
  - 起因是已经发生的数据丢失：本地 5 份扫描 CSV 里 3 份被试跑覆盖（08-24 原本 86 条信号、08-27 原本全量），而 `output/` 不在版本控制内，找不回来。更贵的是面板显示"某日无信号"时，分不出是全市场真没机会还是一次 3 只票的残渣。
  - 元信息**不塞进 CSV**：信号数为 0 时 CSV 只有表头，没有任何一行能承载"我扫了 3010 只"这个事实——而这正是要区分的核心。老产物（v0.2.4 之前，有 CSV 无 meta）面板显示"范围未知"并说明原因，不猜也不迁移。
- 单票取数失败自动重试一次，仍失败记入失败清单继续扫，不会因一只票废掉全场；但**全部**失败（断网/限流）等于一只都没完成判定，同样判为无结论、非零退出、不落盘。

### ④ 面板 TAPE：`streamlit run app/dashboard.py`

```bash
.venv/bin/streamlit run app/dashboard.py --server.address 127.0.0.1
```

（`--server.address 127.0.0.1` 不是可选项，原因见 §3 的安全提示。）

面板自 v0.2.2 起叫 **TAPE**（取自 "reading the tape" 看盘——报价纸带上滚动的价与量正是本系统唯一的输入），侧边栏与浏览器标签页都用这个名字。

侧边栏八个页面、分三组（v0.2.2 起是原生导航链接，每页有独立 URL，可收藏、可分享，浏览器前进/后退可用；v0.3.1 起按组分段）：主组（无标题）是 **使用说明**（v0.2.1 新增，默认落地页，面板自带的手册，见 §4）、**任务控制台**（v0.2.0 新增，见 §3；v0.2.2 从末位提到第二位——它是最常用的操作入口）、**今日信号**（读 `output/signals/` 的清单与历史；页尾"全市场扫描"区块展示 `output/scan/` 最新一份扫描结果，标题带扫描日期——注意核对是不是今天的）；「交易日志」组（v0.3.0 新增，v0.3.1 拆成两个子页，见下）是 **记账**（记你真实成交的每一笔，历史日志可筛选/改删/导出）、**持仓与盈亏**（按整本日志算出的当前持仓、已实现盈亏与来源对比）；「研究」组是 **信号池**（v0.2.2 新增，增删 `config/settings.yaml` 的 `universe`，见下）、**回测报告**（选历史某次回测看指标表/净值图/成交明细）、**个股 K 线**（选标的看买卖点标注）。

展示部分只读 `output/` 与 `data/cache/`：没结果可看就是还没跑过 ①/②/③，页面会提示对应命令与预计耗时。自 v0.2.0 起面板**还能启动这三个脚本**——用法与语义见 §3。

### 信号池：在页面上增删 `universe`（v0.2.2 新增）

`config/settings.yaml` 的 `universe` 就是「每日信号」每天替你盯的那批标的（**不在池子里的票没有任何人管它的卖出**）。v0.2.2 起不用再开编辑器手改，两条路：

- **「今日信号」页的扫描表**：每行末尾一个 **＋**，看到信号当场加进池子；已在池中的那一行显示 `✓ 已在池中`（点了也不会重复写）。这条路**不联网**——扫描 CSV 里的每一只都是扫描时 `get_all_symbols` 筛过的（沪深主板、非 ST、上市满 400 天），成员资格由那份文件本身作证。
- **标的名称**：读 `data/symbols.parquet`（全市场清单，含每只票的名称，由入口 ③ 落盘），扫描 CSV 作为补充与覆盖；两处都查不到时显示 `—`。没有这个文件时名称只能来自扫描 CSV，而扫描只记录出过信号的标的，多数标的会是 `—`——跑一次入口 ③ 即可补齐。
- **「信号池」页**：上方是当前池子（代码 / 名称 / 最新价 / 每行一个 **− 移除**），下方按代码或名称搜索添加。候选清单点「加载可选标的清单」才拉——跑过全市场扫描的话，本地 `data/symbols.parquet` 里 7 天内的那份直接复用（瞬时）；没有或已过期才联网，那是一次约 **2–4 分钟**的请求（全市场清单约 11500 行分页），拉到后 6 小时内走缓存。只想移除标的的话不必加载。

**写的是哪个文件**（v0.3.2 改了落点）：面板写 `config/universe.local.yaml`
——它是**你的数据**，不受版本控制（改池子不会再让 `git status` 变脏，也不会把你的
关注标的推到远端）。`config/settings.yaml` 里那份 `universe` 降级为**种子**
（新装机器的默认池子，随代码分发）；本地文件一存在就以它为准，「信号池」页顶部
直接写明当前池子来自哪个文件。删掉本地那份即可回到默认池子。细节见 §5「你的数据在哪」。

写入规则（池子驱动全部三个脚本，所以规则从严）：

| 规则 | 为什么 |
|---|---|
| 只写本地文件，`config/settings.yaml` **逐字节**不动 | 种子是项目决策（受版本控制、有测试钉着）；用户改自己的池子不该产生一份与代码无关的 diff。本地文件由面板整份重写——它没有注释要保 |
| 本地文件损坏 / 为空 / 不是列表 → **报错并指名路径**，绝不回退到种子 | 悄悄回退 = 你盯着 7 只自选股，而三个脚本每天在扫种子那 10 只，且永不报错 |
| 必须是 6 位数字，且必须在扫描池内 | YAML 1.1 会把裸写的 `000333` 当八进制读成 219；ST（±5%）与次新股会让按主板 ±10% 建模的引擎口径失真而不报错 |
| 至少留 1 只 | 空 `universe` 会让每日信号打印误导性的"全部标的数据均未更新"退出、回测在 `equal_weight_hold` 深处抛 `No objects to concatenate`（v0.1.1 已修过一次） |
| 写完立刻 `load_settings` 复核，不符就**回滚原文件**并报错 | 宁可这次操作失败，也不能留下一个坏配置 |
| 落盘走临时文件 + `os.replace` 原子替换 | 中途 Ctrl-C / 断电不会留下半截配置 |

改动即时对命令行生效（读的是同一份合并结果），所以面板上加完票可以直接 `.venv/bin/python scripts/run_daily_signal.py` 验证它被纳入。移错了再加回来即可，因此这里**不设二次确认弹窗**。

**离线时**：拉不到扫描池清单（断网、baostock 抽风、当日清单未更新）→ 页面明说原因，「加入」暂不可用，**表格与 − 移除照常**（移除不需要那份清单）；配置读不到或被改坏（种子或本地文件任一）→ 「信号池」页只显示一句明确的错误（含是**哪个**文件、怎么脱身）、什么都不改，「今日信号」页照常显示信号，只是不出 ＋ 列。两种情况都不崩页。

### 交易日志：记你真实成交的每一笔（v0.3.0 新增）

前面三个入口回答的都是"**机械规则在历史上表现如何**"。它们回答不了"**你本人的决策质量如何**"——而后者才是"技术分析对散户到底有没有用"这个问题的唯一诚实检验。交易日志补上后一半：记录 → 持仓 → 已实现盈亏，并把**照系统信号做的交易**与**自己拍脑袋做的交易**分组对比。自 v0.3.1 起它在侧栏是一个组、两个子页：**记账**（录入 + 历史日志 + 导出）与**持仓与盈亏**（持仓 / 平仓明细 / 来源对比，收在三个标签页里）。

数据落在 `journal/trades.csv`，**不进版本控制**（v0.3.2 起；它是你的真实交易记录，仓库一推到任何远端就全公开了）。撤销靠的是**每次写盘前自动另存的上一版** `journal/trades.csv.bak`（只留一层）——误删一行就从那里取回，长期备份用页面上的导出。写盘一律临时文件 + `os.replace` 原子替换（备份也走同一套），代码列全程按字符串处理（`000333` 不会变成 `333`）。详见 §5「你的数据在哪」。

**四种记录类型**，缺一种盈亏就会静默算错：

| 类型 | 含义 | 必填 | 对持仓 | 对已实现盈亏 |
|---|---|---|---|---|
| `buy` **买入** | 买入成交 | 股数、成交价 | 加股数，建一个成本批次（买入费用计入成本） | — |
| `sell` **卖出** | 卖出成交 | 股数、成交价 | 减股数，按**先进先出**消耗批次 | 产生已实现盈亏 |
| `adjust` **股数调整** | 送股/转增/拆股导致的股数变化 | 股数（送股填正、缩股填负） | 加减股数，**成本总额不变**（摊薄单位成本） | — |
| `dividend` **现金分红** | 分红到账 | 到账金额 | 不变 | 计入已实现收益 |

后两种收在录入区下面的「其他记录」折叠区里（一年只用几次），但**不是可有可无的**：送股不是交易，你的股数却确实变了——不记的话持仓数会与券商对不上，此后每一笔卖出的先进先出配对全错，**而且不会报错**，只会给出一个看着正常的错数字。分红同理：A 股蓝筹年化股息 2–4%，长期持有下静默忽略它是对收益的系统性低估。

**录入时系统帮你抓错**（这是本项目相对通用记账工具的独有优势——它手里有行情）：

- 输入代码后自动带出**名称**（`data/symbols.parquet` + 扫描 CSV）与该日的**价格区间** `[low, high]`（`data/cache/`），两者都离线可用；
- **成交价超出当日区间 → 警告**。71.5 打成 715 在通用记账软件里无人可查，这里当场看得出来；
- 佣金与印花税按 `config/settings.yaml` 的成本模型**自动算好**（与回测**同一个函数**，口径不会分叉），可改成券商实际扣款；印花税按**成交日**取税率（补记 2023-08-28 之前的卖出会用当时的千分之一）；
- 卖出股数超过当前持仓、送股却没有对应持仓、行里缺股数/价格 → 在持仓区**持续告警**，不是记完就消失的提示。

**阻断只用于逻辑上不可能的事**（未来日期，录入表单干脆让它选不出来；以及一张没填完的表单）。其余一律"警告 + 记下来"：可能是缓存里没这只票、可能是盘后大宗、可能是漏记过一笔买入。这是日志——首要职责是**如实记录发生了什么**，而不是替用户否定现实。

**「今日信号」页两张表的每行都有「＋ 记一笔」**：预填代码/名称/日期/方向/来源并跳到日志页。**不预填成交价**——信号那天的收盘价不是你的成交价，填上去就是一个看着正常的错数字。

**筛选与导出**：日期区间 / 标的 / 类型 / 来源 / 理由关键词，条件留空即不限制。导出的是**当前筛选后的结果**（所见即所得），CSV 与 Excel 各一个按钮。CSV 用 `utf-8-sig`（带 BOM），Excel 双击打开中文不乱码；格式与 `journal/trades.csv` **完全相同**，可以直接放回去当日志用。Excel 导出需要 `openpyxl`（已写进 `pyproject.toml`）。

**改与删**：日志表可直接编辑，改完按「保存修改」才落盘；删除要先勾「删除」列再保存（两步是刻意的——这份文件不可再生，一键删除误点一下就没了）。改动一律按**记录号**（`trade_id`）定位、不按行号：表里显示的是筛选后的行，按行号写盘会改掉别人那一笔且不会报错。保存前每行都过一遍校验，有阻断项就整批拒写并说明是哪几行。

**汇总指标（胜率 / 盈亏比 / 平均持仓天数）与回测报告用同一套口径**（同一个函数算的），所以可以把「持仓与盈亏」页的数字和「回测报告」页并排比。一次卖出吃掉两个买入批次算两笔往返；平手（不赚不亏）计入亏损那一边。

**已知局限**（看数字之前先看这里）：

- **浮动盈亏依赖本地行情缓存** `data/cache/`。没缓存的标的最新价与浮动盈亏显示 `—`，**不按 0 算**（0 会被读成"亏掉全部本金"）。想让它有数就先跑一次回测或每日信号。
- **未处理配股、要约收购等复杂公司行为**。遇到时用 `adjust` + 备注手工记，并自己复核一遍成本。
- **不做税务口径，也不构成任何税务建议**。费用只算佣金与印花税；红利税之类请按券商实际扣款填进「佣金」栏。
- 持仓与盈亏是**按你记的日志**算出来的，不是券商数据。漏记一笔，后面全错——所以卖超与读不懂的行会在持仓区持续告警，别忽略它们。
- 一笔都还没平仓时，已实现盈亏显示 `—` 而不是 `0.00`：那不是"不赚不亏"，是还没有任何已实现结果。

**Cmd+C 热键修复的人工验收（v0.2.2）**：Streamlit 用 `hotkeys` 绑单键快捷键（`c` 清缓存、`r` 重跑），而它的过滤器**不看修饰键**，于是在面板里选中文字按 Cmd+C 会弹出 "Clear caches?"。修法是包一层 `hotkeys.filter`，让带 Cmd/Ctrl/Alt 的组合不进热键系统。这段是浏览器行为，测试覆盖不到，改动后请手动过一遍两步：

1. 打开任意带表格的页（如「今日信号」），用鼠标选中表格里的文字 → **Cmd+C** → 应正常复制到剪贴板，**不弹**任何对话框；
2. 点一下页面空白处，**裸按 `c`** → 仍应弹出清缓存对话框。第 2 步是反向验证：证明修复只挡掉了修饰键组合，没把 Streamlit 的快捷键整个禁掉。

## 3. 面板任务控制台（v0.2.0 新增）

三个入口脚本都能在页面上启动、停止、重跑：侧边栏「任务控制台」页有完整的参数控件、进度、日志与结果；既有三页顶部另有一条精简控制条（状态 + 开始/停止）。

> **安全提示**：面板会在**本机**执行脚本，等于一个本地命令执行入口。启动时**必须**加 `--server.address 127.0.0.1` 显式绑定回环地址，**切勿**用 `--server.address 0.0.0.0` 或任何内网地址。

```bash
.venv/bin/streamlit run app/dashboard.py --server.address 127.0.0.1
```

**别指望 streamlit 的出厂默认是安全的**——这里原先写着"`streamlit run` 默认只监听本机，保持默认即可"，v0.2.1 实跑证明那是假话。以下是 **streamlit 的出厂行为**（不是本仓库现在的行为，原因见下）：

```console
$ streamlit run app/dashboard.py --server.port 8531
$ lsof -nP -iTCP:8531 -sTCP:LISTEN
Python  79141 youruser  6u  IPv6 ...  TCP *:8531 (LISTEN)          ← 所有网卡

$ streamlit run app/dashboard.py --server.port 8532 --server.address 127.0.0.1
Python  80013 youruser  6u  IPv4 ...  TCP 127.0.0.1:8532 (LISTEN)  ← 只有本机
```

不带地址参数时监听的是 `*:8501`（**所有网卡**，启动日志里那两行 `Network URL` / `External URL` 就是证据）。同一网段的人打开就能点你的「开始」按钮，也就等于能在你机器上执行命令。

**v0.5.0 起本仓库把安全绑定变成了默认值**：`.streamlit/config.toml` 里写了 `[server] address = "127.0.0.1"`，所以在项目根目录下启动时，上面第一条命令实测已经绑到 `127.0.0.1:8531`、两行 URL 也不再打印。**但这层兜底有边界**：streamlit 按**当前工作目录**查找 `$CWD/.streamlit/config.toml`，从别的目录启动就不加载、静默退回出厂默认。所以命令行那个参数仍然值得养成习惯，别把安全完全押在"我肯定在项目根目录下"这个前提上。

同一份配置里还有 `[browser] gatherUsageStats = false`：streamlit 出厂默认会向其官方端点上报使用统计，而这台机器上同时存着你的真实成交记录，关掉它没有任何代价。

面板另外刻意不暴露 `--config`（避免任意路径读取），任务一律用 `config/settings.yaml`。

### 三个任务怎么点

| 卡片 | 参数控件 | 等价命令 |
|---|---|---|
| 全市场扫描 | `--limit`（留空 = 全量）、`--date`（留空 = 最近交易日） | `run_market_scan.py [--limit N] [--date YYYY-MM-DD]` |
| 每日信号 | 无 | `run_daily_signal.py` |
| 回测 | 策略下拉（留空 = 全部策略）、`--refresh` 勾选 | `run_backtest.py [--strategy X] [--refresh]` |

- `▶ 开始` 按控件里的参数起一个新任务；`⏹ 停止` 只对正在跑的那个任务可用；`↻ 重跑` 沿用上次的参数（上次的命令行会重新过一遍参数白名单，改坏了的状态文件会被拒绝）。
- 参数控件只在控制台页。既有三页顶部的精简控制条按**默认参数**运行——全市场扫描的默认就是**全量**（0.5–2 小时），要限量或指定日期请去控制台。
- 面板只接受白名单参数（日期必须是 `YYYY-MM-DD` 的真实日期、`--limit` 是 1–10000 的正整数、策略只能从注册表里选），命令一律以参数列表方式执行，不经过 shell。

### 进度怎么读

- 扫描的日志里有 `[1250/3010]` 这样的进度行 → 进度条 + "1250/3010（41%），已用 12分38秒，预计剩余 ~19分钟，信号 15 条，失败 0 只"。ETA 是**线性外推**，冷/热缓存混合时偏差不小，只当参考。
- 每日信号与回测没有可数的总量 → 不画进度条，只有转圈 + 阶段文字 + 已用时长（宁可不显示，不显示假数字）。
- **ETA 只在任务还在跑时给**。任务停掉/崩掉之后进度条留在停下的位置（那是"停在哪儿"的存档，据此判断要不要补跑），但文案换成 完成 / 失败 / 已停止，不再报剩余时间。
- 状态徽标：⚪ 空闲 / 🔵 运行中 / ✅ 成功 / ❌ 失败（带退出码）/ ⏹ 已停止。退出码 1 = 脚本自己退出（最常见的是"数据未更新到今天，17:30 后再试"），2 = 参数错，-15 = 被停止，-9 = 被强杀。
- 卡片下方是日志尾部 30 行，`完整日志` 展开是全文；日志文件留在 `output/runs/logs/<run_id>.log`，**不自动清理**（留着事后排查，`output/` 在 .gitignore 里）。
- 跑完直接在卡片里出结果：扫描 / 每日信号 → 当次 CSV 表格；回测 → **每个策略**一组指标卡。

### 停止 = 温和退出（SIGTERM）

点「停止」发的是 **SIGTERM 给整个进程组**，不是 `kill -9`：脚本有机会走完手上这一只票、让缓存原子落盘。10 秒内没退才升级到 SIGKILL。实测 `--limit 3` 的扫描收到 SIGTERM 后 0.06 秒退干净（退出码 -15，`pgrep -f run_market_scan.py` 为空），卡片转为「⏹ 已停止」，其余任务的「开始」立刻解禁。中断过的扫描重跑不会重拉已缓存的历史。

### 关掉浏览器不会停掉任务

任务是**分离进程**（自成会话与进程组），语义与 `nohup ... &` 一致：

- 关掉浏览器标签、关掉整个浏览器 → 任务继续跑；
- 连 Streamlit 服务一起 Ctrl-C 停掉 → 任务照样继续跑；
- 重开面板会从 `output/runs/<任务名>.json` 认领仍在跑的任务，进度接着显示；
- 想真的停掉它，只有点「停止」（或自己 `kill` 状态文件里的那个 pid）。

### 同时只允许一个任务

baostock 是**单会话**：两个任务并发会互踢下线，还更慢。所以只要有任务在跑，控制台三张卡片、以及其余页面控制条上的「开始」**全部禁用**，并提示是谁在跑。这条由 runner 层强制（按钮禁用只是第一道），不靠自觉。

### 命令行入口全部保留

三个脚本的参数与产物一个字没改，面板只是替你敲命令，**两种方式等价**，可以混用。已有的 `nohup ... &` / cron 用法不受影响。两点差别要知道：

- 命令行起的任务不写 `output/runs/`，面板看不到它的进度（产物照样出现在页面上）；
- 因此**它也不参与上面那条互斥**——命令行已经在跑扫描时，别再去面板点「开始」，否则两个 baostock 会话互踢。

## 5. 配置：`config/settings.yaml`

```yaml
universe: ["600519", "600036", "601318", "600900", "000333",
           "600030", "600276", "601088", "600887", "601899"]
benchmark: "000300"
backtest:
  start: "2016-01-01"
  capital: 5000000
costs:
  commission_rate: 0.00025
  commission_min: 5.0
  stamp_tax:
    - {until: "2023-08-27", rate: 0.001}
    - {from: "2023-08-28", rate: 0.0005}
  slippage: 0.001
strategies:
  ma_cross: {fast: 20, slow: 60}
  donchian: {entry_n: 20, exit_n: 10, amount_n: 20, amount_ratio: 1.5}
  tsmom: {lookback: 250}   # 时序动量（v0.4.0）：250 根 ≈ 12 个月
overlays:                  # 叠加层（v0.4.0）：对全部策略生效；整段缺失 = 全部禁用
  trend_filter: {enabled: true, n: 200}
  atr_stop: {enabled: true, n: 20, k: 3.0}
scan:
  history_days: 400        # 每票拉取历史窗口（自然日），约 270 根 K 线 > MA60 暖机两倍
  min_avg_amount: 50000000 # 20 日均成交额门槛（元）
  top_n: 20                # 终端打印条数（CSV 始终存全量）
```

| 段 | 含义与注意 |
|----|-----------|
| `universe` | 股票池的**种子**（v0.3.2 起语义如此）：新装机器的默认池子，6 位数字代码（交易所前缀由 provider 自动补）。**只放沪深主板**：引擎按 10% 涨跌停建模，创业板/科创板 20% 会算错。默认 10 只跨行业高流动性白马。**一旦 `config/universe.local.yaml` 存在，生效的是它**（面板「信号池」页写的就是那个文件，见下一节）；改这里只影响还没有本地文件的机器 |
| `benchmark` | 基准指数代码，默认沪深 300 |
| `backtest.start` | 回测与取数起点。改早了要重新联网补历史（缓存会自动回补头部缺口） |
| `backtest.capital` | 虚拟本金。每标的固定额度 = `capital / len(universe)`，**不随权益浮动**。500 万不是随便定的：茅台一手十余万，本金太小会静默买不进 |
| `costs.commission_rate` / `commission_min` | 佣金万 2.5、单笔最低 5 元，买卖双边收 |
| `costs.stamp_tax` | 仅卖出收，按**成交日**分段：2023-08-28 之前 0.1%，之后 0.05%。写成 `{until: ...}` / `{from: ...}` 的闭区间列表，日期含当日；找不到覆盖当日的区间会直接报错（不静默用旧税率） |
| `costs.slippage` | 滑点 0.1%，买入价 ×1.001、卖出价 ×0.999，顺带涵盖过户费等杂费 |
| `strategies` | 键名必须是注册表里的策略名（`ma_cross` / `donchian` / `tsmom`，见 `src/quant/strategy/__init__.py`），值是构造参数。**这一段删空或键名拼错**，每日信号与全市场扫描脚本会直接退出报错而不是天天空跑 |
| `overlays` | 叠加层（v0.4.0）：对**全部**策略生效，回测、每日信号、全市场扫描三个入口走同一条流水线（`quant/strategy/pipeline.py`，唯一出口，有源码级测试钉着不许绕开）。整段缺失 = 全部禁用（老配置照跑）；段里出现未知键会**报错拒跑**而不是静默忽略 |
| `scan` | 全市场扫描（入口 ③）参数。`min_avg_amount` 是最值得按需调的：门槛越低扫出的票越多、但流动性假设越不可信 |

策略规则：

- **ma_cross**：MA(fast) 在 MA(slow) 之上 → 目标仓位 1，否则 0（状态式，等价于上穿买/下穿卖）。
- **donchian**：收盘价 > 前 `entry_n` 日（**不含当日**）最高收盘 **且** 当日成交额 > `amount_ratio` × 前 `amount_n` 日平均成交额 → 入场；收盘价 < 前 `exit_n` 日（不含当日）最低收盘 → 出场；其余持有不变。窗口若含当日，"收盘 > N 日最高"永不成立，会得到全 0 的死信号——测试里有专门的回归用例守着。
- **tsmom**（v0.4.0）：过去 `lookback` 根（250 ≈ 12 个月）收益为正 → 持有，否则空仓。只看今天与一年前两个时点的价差，中间怎么走一概不问。三个策略里公开证据最强的一个（Moskowitz/Ooi/Pedersen 2012，跨 58 个品种上百年数据），也是参数最少的一个。

叠加层规则（**止损不是策略，是覆盖层**——它不产生入场信号，只在策略给出的仓位之上做减法）：

- **trend_filter（200 日趋势过滤，Faber 风格）**：收盘价（后复权）不在自己 `n` 日均线上方就不持有多头——既挡入场也强制出场。均线未成形的暖机期不入场。
- **atr_stop（ATR 追踪止损，海龟法则变体）**：持有期间收盘价 < 入场以来最高价 − `k`×ATR(`n`) → 次日开盘离场；离场后**保持空仓直到基础策略给出新的一次 0→1 入场**（否则次日就会回补刚止损的那只票，止损形同虚设）。`k` 默认 3 而不是海龟经典的 2：实测证明"出场太急、一次正常回调就被甩下车"正是唐奇安在基线里跑输的主因。
- **顺序定死在代码里**：先趋势过滤、后止损（先判断"这个环境能不能持有"，再管"持有之后何时认输"）。两者的真实代价见 ① 的归因表——在长牛蓝筹池上相当昂贵，开不开、参数怎么调，请拿那张表做决定，别凭直觉。

### 你的数据在哪（哪些文件不进 git，v0.3.2 新增）

仓库里有两类文件，分得很清楚：**用户数据**（你的，不受版本控制）与**项目配置**（项目的决策，受版本控制）。

| 文件 | 是什么 | 进 git 吗 |
|---|---|---|
| `journal/trades.csv` | **你的交易记录**（不可再生） | **不进**。一份完整的真实交易记录，仓库一推到任何远端就全公开了 |
| `journal/trades.csv.bak` | 上一版日志，每次写盘前自动另存（只留一层） | **不进**，同上 |
| `config/universe.local.yaml` | **你的信号池**（暴露持仓与关注标的） | **不进** |
| `config/settings.yaml` | 项目配置：成本模型、策略参数、`scan`，以及 `universe` **种子** | **进**。这些是项目决策，改动值得留痕，也有测试钉着 |

三份用户数据在 `.gitignore` 里**按文件名逐条列出**（不是忽略 `journal/` 或 `config/` 整个目录——那会把项目配置一起带走，而两个测试拿 `config/settings.yaml` 当 fixture）。有测试用 `git check-ignore` 钉住这三条规则，防止将来被误删。

**改自己的池子、记一笔账，`git status` 都不会再变脏**，这是分开放的直接好处；顺带把隐私风险也去掉了。

**没有 git 兜底了，靠什么撤销**：日志每次写盘前把上一版另存为 `journal/trades.csv.bak`（原子替换；备份失败会响亮报错，不会悄悄跳过）。改错删错就从那里取回。长期备份用「记账」页的**导出**（CSV / Excel），格式与日志文件完全相同，可以直接放回去。

**本地信号池文件坏了怎么办**：报错会指名是哪个文件，并给出两条出路——删掉它回到 `config/settings.yaml` 的默认池子，或按 `universe: ["600519", "000333"]` 的写法改好（**代码要带引号**，否则 `000333` 会被 YAML 1.1 当八进制读成 219）。**绝不会悄悄回退到种子池子**：那意味着你盯着一批标的、而三个脚本每天在跑另一批，且永远不报错。

**换新机器怎么办**：`git clone` 只给代码，**不会**带上面那三份文件。把老机器上的 `journal/trades.csv` 与 `config/universe.local.yaml` **拷**到新机器同样的相对路径下即可。不拷也能跑（日志从空表开始、池子从种子开始），但以前的记录不会自己出现——这一点得先知道，别等那时才发现。

**分层原则**：策略层只认行情 DataFrame，不知道数据从哪来；引擎只认目标仓位序列，不知道策略逻辑；UI 只做渲染，不含业务逻辑——面板要起任务，判断与解析也全在 `src/quant/runner/`（面板本身写不了单元测试，把逻辑挤出 UI 层是把缺陷挡在外面的关键手段）。

**四条绝不能改的语义**（改了回测结论全部作废，来龙去脉见设计文档 §4）：

1. **信号用后复权价 `adj_*`，撮合/涨跌停判定/成本计算用原始价**。前复权会随每次除权改写历史（引入未来信息）；而整手、最低佣金、涨跌停只有在真实价位上才有意义。
2. **T 日收盘算信号 → T+1 日开盘成交**（引擎内是 `positions.shift(1)`）。杜绝"当日收盘信号当日成交"的未来函数。
3. **每标的固定额度 = 初始本金 / N，不随权益浮动**，各标的账本互不挪用；赚到的钱留作闲置现金，不放大下一轮仓位。
4. **印花税仅卖出且按成交日分段**（2023-08-28 前 0.1%，之后 0.05%）。用现行税率回溯 2016-2023 会把那段历史的卖出成本低估一半。

引擎每日循环：应用除权因子（调持仓股数 + 把昨收折算到今日价格体系）→ 比对目标仓位生成订单 → 约束检查（停牌跳过 / 买单遇涨停顺延 / 卖单遇跌停顺延 / T+1 当日买入不可卖 / 不足一手放弃）→ 原始开盘价 ± 滑点撮合、计佣金与印花税 → 原始收盘价估值记净值（停牌标的沿用最近可得收盘价）。被挡掉的订单全部写进 `skipped.csv`。

## 7. 已知近似与局限（重要，看结果前先看这里）

**交易规则层面**

- **涨跌停判定是近似**：用「原始开盘价 ≥ 昨收 × 1.095（或 ≤ 0.905）」或「当日 high == low 的一字板」判定。真实盘口的排队、封板中途打开、部分成交都无法复现。
- **ST 期间的 5% 涨跌幅未建模**：数据层检测到 ST 只写告警，引擎仍按 10% 处理。默认股票池是非 ST 白马，影响有限；换池子时要留意。
- **只支持主板 10% 涨跌幅**，创业板/科创板 20% 的分支没写。
- **除权除息按"分红再投资"假设**：除权日持仓股数 × (今日因子/昨日因子)，现金不变。结果是**持仓股数会变成非整数**，与真实账户"现金分红入账、股数不变"有出入。
- **成交假设过于友好**：以次日开盘价 ± 0.1% 滑点**全额**成交，不考虑冲击成本、流动性不足、部分成交。
- **停牌日整行被过滤**，不进指标计算也不交易，等价于信号顺延到复牌后。

**绩效与基准层面**

- **夏普比率用 rf = 0**（简化口径）。中国无风险利率约 1.5–2%，真实夏普应比这里低一些。
- **CAGR 已改为日历年化**（首末日期跨度 ÷ 365.25，即 CAGR 的标准定义），不再按 bar 数 ÷ 252 折算——旧口径会把收益塞进更短的"年"里，系统性高估约 3.8%（相对）。夏普年化仍沿用业界惯例 √252：A 股一年实际只有约 243 个交易日，√(252/243) ≈ 1.018，夏普因此约被高估 2%。
- **沪深 300 是价格指数，不含成分股分红**，相对策略净值有每年约 2–3% 的天然劣势——**不要拿它当主要参照**。报告里的「等权买入持有」基准用后复权价（分红再投资口径），与策略同权，才是主要对照组。
- **现金不计利息**，闲置资金收益为 0，长期会低估机会成本对比。
- **胜率/盈亏比/平均持仓天数只统计已平仓交易**，回测末尾仍持仓的那一笔不计入；持仓天数是自然日不是交易日。

**样本与方法层面**

- **股票池有幸存者偏差**：这 10 只是**今天**回头挑出来的高流动性白马，2016 年时并不知道它们会走成这样。回测收益天然偏乐观，退市股、掉队股一只都没有。
- **策略参数没有调优也没做样本外检验**（无参数扫描、无前进分析）。现有 `metrics.json` 只是"这条流水线能跑出数"的证据，不是策略有效性的证据。
- **数据未与交易所对账**：baostock 是免费源，复权因子、停牌标记、成交额都按它给的用。

**全市场扫描层面（v0.1.1）**

- **逐票串行取数是 baostock 单连接的天花板**：单次全量预估 0.5–2 小时（固定开销约 2–4 分钟 + 每票约 0.5–2 秒，见入口 ③ 的实测拆解；与设计文档 §3.4 的 30–60 分钟量级预估一致，但其"已缓存的票秒过"不成立——缓存省不掉每票一次增量联网往返，实测热缓存无法加速扫描本身）。接口分层已留好快路径插槽（如 akshare 全市场快照），需要时替换"当日 bar 来源"即可，扫描逻辑不用动。
- **排序用当日成交额而非策略强度分**——简单、普适、可解释；"哪个信号更强"的策略特定排序留给 top-K 组合（v0.2）。
- **扫描发现的票没有回测背书**：回测仍只跑固定 `universe`；扫描池按"当天"的在市清单取，对当日扫描本身无幸存者偏差，但某只票扫出来 ≠ 策略在它身上历史有效。加池观察前别赋予信号超出"技术条件今天满足了"的含义。
- **不扫创业板/科创板/北交所/ST**：与引擎 ±10% 涨跌停假设保持一致（这些板 20%/5% 的分支没建模），将来做 top-K 回测可无缝衔接。

**工程层面**

- akshare 备选 provider 在设计文档里列了，**v0.1 没有实现**——baostock 挂了就得现写。
- **面板任务控制台有两个已知的互斥漏洞**（设计文档 §8.1，暂不修）：① 面板重启过、且任务日志超过 10 分钟没有新输出时，会按"PID 多半被复用"处理而放开互斥；② 起任务的互斥是"先查后起"，毫秒级同时点击（多标签页）理论上能起两个任务。单人本机使用概率极低，修法的复杂度与收益不成比例。命令行起的任务同样不参与互斥（见 §3）。
- 无实盘/模拟盘对接、无盘中与分钟级、无定时任务与推送（面板只能手动点，不含调度）。个股级的止损与趋势过滤 v0.4.0 起有了（§5 的 `overlays`），但**组合级**风控（仓位管理、波动率目标、行业敞口）仍然没有——同板块信号全买还是会把仓位押在一个 beta 上。
- **叠加层的参数（k=3、n=200 等）与三组策略参数一样，没有调优也没做样本外检验**；止损"封锁到基础信号重新 0→1"的语义对慢信号（tsmom）尤其苛刻，① 的归因表是它在这个池子上的真实账单。

## 8. 开发备忘（三个月后的自己大概率会再踩）

- **baostock 的 `rs.get_data()` 用不得**：0.9.3 版翻页分支调用了 pandas 早已删除的 `DataFrame.append`，首页满 2000 行就抛 `AttributeError`，10 年日线（约 2579 行）必然触发。`BaostockProvider` 里已经改成 `next()` / `get_row_data()` 逐行迭代，别改回去；`tests/test_baostock_integration.py` 有联网回归用例守着（`pytest -m network`）。
- **数据缓存的增量判据用的是"已请求过的起始日"**（`data/cache/<代码>.meta.json` 里的 `covered_start`），不是"缓存里最早那根 K 线的日期"——后者在 start 落在非交易日（比如默认的 2016-01-01 元旦）时恒为真，会让增量分支变成死代码、每次全量重拉。
- 增量取数会**回拉 5 天重叠**：盘中跑过一次的话，当天那根未收盘的 K 线会进缓存，靠重叠重拉 + `keep="last"` 覆盖修正。缓存疑似脏了就 `--refresh`。
- 提交前跑全量测试：`.venv/bin/python -m pytest`。做变异测试时务必加 `PYTHONDONTWRITEBYTECODE=1` 并 `-B`，且先 `rm -rf` 相关 `__pycache__`——等长度改写源码会命中陈旧 `.pyc`，结果完全不可信。
